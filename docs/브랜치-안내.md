# 어느 브랜치에서 작업해야 하는가

이 저장소에는 **서로 이어져 있지 않은 두 갈래**가 있습니다. 모르고 작업하면
헛일이 됩니다. 실제로 그런 일이 있었습니다.

## 한 줄 요약

**데스크톱 CRM을 고치려면 `codex/bring-field-platform` 에서 작업하세요.**

## 왜 헷갈리는가

| | `codex/bring-field-platform` | 기본 브랜치 |
| --- | --- | --- |
| 직원 PC로 배포 | **예** — 푸시할 때마다 자동 릴리스 | 아니오 |
| 커밋 수 | 874+ | 10 |
| desktop-crm 내용 | 그룹웨어·밸류스코프·AI 비서 포함 | 그것들이 없는 다른 계통 |

두 브랜치는 **공통 조상이 없습니다.**

```
git merge-base codex/bring-field-platform <기본 브랜치>   → 결과 없음
```

그래서 한쪽에서 만든 커밋을 다른 쪽으로 **체리픽할 수 없습니다.** 옮기려면
그 브랜치의 파일에 맞춰 다시 적용해야 합니다.

## 무엇이 어디로 나가는가

| 대상 | 소스 | 배포 방식 |
| --- | --- | --- |
| 직원 PC의 데스크톱 CRM | `codex/bring-field-platform` | 푸시 시 자동 릴리스 (`crm-release.yml`) |
| 업무흐름 빌더 (웹) | 기본 브랜치의 `index.html` | GitHub Pages |
| RTDB 접근 규칙 | `codex/bring-field-platform` | 릴리스에 포함 |
| Cloud Functions | — | **배포되지 않음** (Spark 요금제) |

## 작업 전에 확인할 것

1. 고치려는 파일이 `desktop-crm/` 아래인가? → `codex/bring-field-platform`
2. 웹 업무흐름 빌더(`index.html`)인가? → 기본 브랜치
3. 헷갈리면 이렇게 확인합니다.

```bash
# 이 파일이 배포 브랜치에도 있는가
git cat-file -e origin/codex/bring-field-platform:<파일경로> && echo 있음 || echo 없음
```

## 주의

`codex/bring-field-platform` 에 **푸시하는 순간 직원 PC로 배포가 시작됩니다.**
PR을 열어두는 것만으로는 배포되지 않으니, 검토가 필요하면 별도 브랜치에서
PR을 올리고 머지 시점을 정하세요.

자세한 배포 규칙은 `docs/crm-automatic-release.md` 를 보세요.
