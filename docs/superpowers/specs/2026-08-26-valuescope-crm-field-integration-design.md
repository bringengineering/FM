# ValueScope·CRM·현장 업무 통합 설계

상태: 대표 승인 — 추천안으로 진행

작성일: 2026-08-26

대상: `bringengineering/valuescope`, `bringengineering/FM`, BRING CRM 데스크톱 앱, BRING FIELD

## 1. 결론

ValueScope의 지도 원본과 공개 배포는 기존 `bringengineering/valuescope` 저장소에 유지하고, BRING CRM에는 `지도·밸류스코프`라는 정식 업무 메뉴로 연결한다. 공개 지도에 CRM 로그인이나 서버 권한을 넘기지 않으며, 지도에서 선택한 대상은 검증된 좁은 연결 통로를 통해 CRM 영업 대상·건물·현장 업무로 전환한다.

별도의 독립 실행 프로그램은 만들지 않는다. 기존 BRING CRM Windows 앱의 다음 버전에 지도 모듈과 현장 업무 등록을 포함해 로그인, 권한, 자동 업데이트를 하나로 유지한다.

## 2. 확인된 현재 상태

- GitHub Pages는 `bringengineering/valuescope`의 `main/docs`에서 배포되며 HTTPS가 적용돼 있다.
- `wonju.html`, `sales.html`, `valueup.html`, `system.html`은 모두 HTTP 200으로 공개된다.
- 원주 지도는 약 9.3MB의 `docs/data/wonju.js`, 영업 지도는 `docs/data/agents.js`를 읽는다.
- 영업 지도와 밸류업 입력은 브라우저 `localStorage`에만 남아 CRM 공용 서버와 동기화되지 않는다.
- 현재 FM 운영 브랜치에는 `bring-valuescope/` 또는 ValueScope HTML 사본이 없다. 따라서 “FM에 엔진·데이터가 이미 병합돼 있다”는 설명은 현재 운영 브랜치 기준으로는 사실이 아니다.
- CRM의 현장 업무 조회·작업자 전환·서버 명령 기반은 연결돼 있으나 `openCreateJob`은 의도적으로 `FIELD_CREATE_UNAVAILABLE`을 반환한다.
- 서버 도메인에는 건물 또는 영업 대상을 부모로 하는 현장 업무 생성 계약과 원자적 저장 구조가 이미 존재한다.

## 3. 검토한 방식

### A. 공개 링크만 여는 방식

구현은 가장 빠르지만 지도 선택 결과가 CRM에 남지 않고, 영업 상태와 밸류업 입력이 사용자 PC마다 달라진다. 링크 모음 이상이 아니므로 채택하지 않는다.

### B. 지도 전체를 FM으로 복사하는 방식

한 저장소에서 관리할 수 있지만 지도 원본이 두 군데가 되고, 어느 사본이 최신인지 알기 어려워진다. 지도와 CRM 배포가 불필요하게 묶이므로 채택하지 않는다.

### C. 원본 분리 + CRM 안전 연결 방식 — 채택

- 지도 원본과 공개 배포: `valuescope`
- 고객·건물·영업·업무 원장: FM의 CRM 서버
- 데스크톱 사용자 화면: BRING CRM 앱
- 연결: 허용된 ValueScope 출처와 정해진 명령만 통과하는 브리지

역할은 분리하되 사용자는 CRM 한 곳에서 업무를 마칠 수 있다.

## 4. CRM 화면 구조

CRM 왼쪽 메뉴에 `지도·밸류스코프`를 추가하고 다음 네 탭을 제공한다.

1. 원주 건물 — 건물 분포와 분석 보기
2. 영업 지도 — 중개사·영업 후보 탐색 및 CRM 등록
3. 건물 밸류업 — 수익성 입력·비교·CRM 기록
4. 사업체계 — 사업 흐름 안내

상단에는 CRM 공통 검색과 다음 행동을 유지한다.

- `CRM 영업 대상 등록`
- `기존 건물과 연결`
- `현장 업무 만들기`
- `원본 지도 새 창에서 열기`

지도 화면은 CRM 콘텐츠 영역에만 표시하며 CRM 사이드바와 상단바를 중복으로 만들지 않는다.

## 5. 데이터 연결 규칙

### 5.1 지도 대상 식별

지도 레코드에는 다음 최소 정보만 CRM으로 전달한다.

- `source`: `valuescope`
- `sourcePage`: `wonju` 또는 `sales`
- `externalId`
- 이름
- 도로명 주소
- 좌표
- 공개 데이터에서 가져온 분류·요약

전화번호, 개인 메모, 로그인 토큰은 공개 페이지와 주고받지 않는다.

### 5.2 CRM 영업 대상 생성

지도에서 등록하면 `salesProspect`를 생성하고 `sourceRef`에 ValueScope 출처와 외부 ID를 기록한다. 같은 출처·외부 ID가 있으면 새로 만들지 않고 기존 대상을 연다.

주소가 같은 CRM 건물이 있으면 연결 후보를 보여준다. 주소가 같다는 이유만으로 자동 병합하거나 기존 데이터를 덮어쓰지 않는다.

### 5.3 밸류업 기록

밸류업 계산 자체는 브라우저에서 즉시 수행하되, CRM에 저장할 때는 입력값, 계산 결과, 계산식 버전, 저장자, 저장시각, 연결 건물 또는 영업 대상 ID를 함께 기록한다. 개인 PC의 `localStorage`는 임시 초안 역할만 한다.

### 5.4 권한

- viewer: 지도와 연결된 CRM 기록 조회만 가능
- member/admin: 영업 대상 등록과 현장 업무 생성 가능
- 건물 병합·연결 해제·운영 설정 변경: admin만 가능

## 6. 보안 경계

- ValueScope 페이지에는 Firebase 인증 토큰, CRM 데이터 전체, Google Drive 권한을 전달하지 않는다.
- Electron은 `https://bringengineering.github.io/valuescope/`의 정확한 경로만 내장 화면으로 허용한다.
- 새 창, 다운로드, 다른 호스트 이동은 기본 차단하고 허용된 HTTPS 외부 링크만 운영체제 브라우저에서 연다.
- 지도에서 CRM으로 들어오는 메시지는 origin, webContents, 명령명, 정확한 필드, 문자열 길이, 좌표 범위를 검사한다.
- 지도 페이지가 연결 기능을 지원하지 않거나 버전이 맞지 않으면 읽기 전용으로 유지한다.
- 서버 저장은 기존 CRM의 인증·역할·충돌 방지·감사 로그 규칙을 사용한다.

## 7. 현장 업무 완성 범위

CRM의 `＋ 현장 업무` 버튼을 실제 등록 흐름으로 바꾼다.

입력 항목:

- 대상: CRM 건물 또는 영업 대상
- 호실: 선택 사항
- 업무 종류: 공실 촬영, 퇴실 확인, 청소 전후, 정기 시설점검, 민원 확인, 수리 전후
- 방문 예정일
- 담당자 또는 미배정
- 우선순위
- 연결된 CRM 할 일 또는 케이스: 선택 사항

저장 시 기존 `createFieldJobs` 서버 명령을 사용한다. 성공하면 현장 업무 목록을 다시 불러오고 생성된 업무를 선택한다. 중복 요청은 같은 `requestId`로 재시도해 한 번만 생성한다.

지도에서 `현장 업무 만들기`를 선택한 경우 먼저 기존 CRM 건물·영업 대상을 찾는다. 없으면 영업 대상을 생성한 후 그 ID로 현장 업무 등록 화면을 연다.

## 8. 앱 버전과 배포

- 기존 Electron 앱의 제품명, 로그인, 설치 경로, 자동 업데이트 체계를 유지한다.
- 다음 미사용 버전을 사용하고 기존 태그를 이동하거나 재사용하지 않는다.
- ValueScope 서버가 일시적으로 열리지 않아도 CRM의 다른 메뉴와 저장 기능은 정상 동작해야 한다.
- 배포 전 소스 테스트, 브리지 보안 테스트, CRM 회귀 테스트, FIELD 테스트, Windows 빌드, 실제 지도 탭 화면을 검증한다.
- 운영 브랜치 반영과 GitHub Release 공개 후 `latest.yml`, 설치 EXE, blockmap, 자동 업데이트 조회까지 확인한다.

## 9. 완료 기준

1. 네 공개 지도와 저장소 위치에 대한 조사 결과가 문서화돼 있다.
2. CRM에서 지도 네 종류를 하나의 메뉴로 볼 수 있다.
3. 지도 장애가 CRM 전체 장애로 번지지 않는다.
4. 공개 지도에 CRM 인증정보가 노출되지 않는다.
5. 지도 대상이 중복 없이 CRM 영업 대상으로 등록된다.
6. 기존 건물 연결은 후보 제안 뒤 사람이 확정한다.
7. 밸류업 기록이 개인 브라우저가 아니라 CRM 서버에 저장된다.
8. CRM에서 새 현장 업무를 등록할 수 있다.
9. 지도 대상에서 현장 업무 등록까지 다시 검색하지 않고 이어진다.
10. viewer는 쓰기 동작을 수행할 수 없다.
11. 기존 CRM 데이터와 현장 업무 조회가 회귀하지 않는다.
12. 새 Windows 앱 버전과 자동 업데이트 파일이 공개되고 실제 업데이트 조회가 성공한다.

## 10. 이번 범위에서 하지 않는 것

- ValueScope 전체 Python 분석 엔진을 FM 저장소로 복제
- 공개 지도에서 CRM 고객 전화번호나 개인 메모 표시
- 주소만으로 건물을 자동 병합
- 별도 로그인과 자동 업데이트 체계를 가진 두 번째 Windows 프로그램 제작
- 지도에서 수집한 공개 정보를 검증 없이 고객 정보로 확정
