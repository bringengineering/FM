# BRING CARE 건물관리 광고페이지 전환형 재구성 설계

## 목적

현재 디자인과 시각 언어는 유지하되, 방문자가 회사 소개보다 먼저 자신의 문제와 BRING CARE의 해결 방식을 이해하도록 정보 순서를 바꾼다. 핵심 성공 기준은 첫 화면 이후 3개 구간 안에서 `문제 → 해결 방식 → 실제 증거`가 이어지고, 페이지 중간과 하단에서 무료 관리진단으로 전환되는 것이다.

## 변경 원칙

- 기존 색상·글꼴·카드·사진 스타일은 유지한다.
- 새로운 과장 수치, 별점, 고객 후기 또는 성과를 만들지 않는다.
- 인증은 서비스 품질 보증처럼 보이지 않게 기업 운영 기반의 근거로만 사용한다.
- 실제 관리 현장 사진은 기존 공개 자산만 사용한다.
- 긴 설명을 줄이고, 문제·조치·확인 결과를 한 카드 안에서 읽게 한다.

## 최종 정보 구조

1. **핵심 약속 Hero** — `건물은 임대하고, 관리는 맡기세요.`와 월 89,000원부터, 무료 관리진단 CTA를 유지한다.
2. **계단 건물관리팀 브랜드 선언** — 기존 `bringcare-team-stair-v1.png` 단체 장면을 세로형 대형 비주얼로 배치한다. 사진 옆에는 `우리는 건물을 관리하며, 청소까지 책임지는 회사입니다.`와 `건물을 대하는 태도부터 다릅니다.`를 표시한다. 이 이미지는 실제 직원 증명으로 표현하지 않고 BRING CARE의 브랜드 캠페인 비주얼로 표기한다.
3. **소형 신뢰 띠** — 브랜드 선언 바로 아래에는 연구개발전담부서·벤처기업·창업기업 확인 명칭만 작게 노출한다. 문서 원본 카드는 이 위치에 두지 않는다.
4. **고객 문제** — 공실·시설·결과 확인에 연락처가 분산되는 문제를 먼저 보여준다.
5. **한 개의 관리창구와 서비스 메뉴** — BRING CARE를 중심으로 공실·입퇴실·청소·시설·민원·수리를 연결한다.
6. **관리 흐름** — 실제 사진을 사용해 `확인 → 조율 → 처리 → 보고`를 보여준다.
7. **실제 관리사례** — 각 카드에 `확인한 문제`, `진행한 조치`, `남긴 결과`를 구분해 표시한다. 입증되지 않은 성과 숫자는 사용하지 않는다.
8. **월간 보고 예시** — 방문 횟수·확인 범위·후속 조치·현장 사진이 어떻게 정리되는지 보여준다.
9. **중간 전환 CTA** — `우리 건물은 어떻게 관리할지 먼저 받아보세요.` 문구와 무료 관리진단 버튼을 배치한다.
10. **직접 관리 비교표** — 연락, 현장 확인, 업체 조율, 완료 확인, 기록, 월간 보고를 비교한다.
11. **서비스 범위와 가격** — 월 관리비 포함 항목과 청소·수리·자재 등 별도 항목을 명확히 구분한다.
12. **24H 입·퇴실 관리** — 퇴실 접수부터 다음 입실 준비까지의 병렬 준비 방식을 설명한다.
13. **운영 기준** — 사전 승인, 기록, 원주 직영 운영, 전문업체 협업 원칙을 비교 카드로 보여준다.
14. **상세 인증·기업 신뢰** — 공개용 인증서 3장을 펼쳐볼 수 있는 카드로 배치한다. 만료된 중소기업 확인서는 제외한다.
15. **FAQ와 최종 신청 폼** — 건물 주소와 불편 사항을 입력하는 상담 폼과 카카오톡 동선을 유지한다.

## 컴포넌트 변경

### `CertificationTrustBar`

- Hero 바로 아래의 얇은 신뢰 띠다.
- 인증 명칭 3개와 `공식 기업 인증 확인` 링크만 제공한다.
- 링크는 하단 `#company-certifications`로 이동한다.

### `BrandTeamManifesto`

- Hero 다음에 기존 계단 단체 장면을 독립된 대형 이미지로 추가한다. Hero의 현장 사진은 교체하지 않는다.
- 이미지 파일은 `/brand-campaign/bringcare-team-stair-v1.png`를 사용한다.
- 데스크톱에서는 카피와 세로형 사진을 2열로 구성하고, 모바일에서는 카피 다음에 사진이 나오도록 쌓는다. 계단 전체와 팀원이 잘리지 않도록 `object-fit: cover`와 `object-position: center`를 사용한다.
- 이미지 하단에 `BRING CARE 브랜드 캠페인 이미지`라고 작게 표기해 실제 직원 단체사진으로 오인되지 않게 한다.
- 카피는 `우리는 건물을 관리하며, 청소까지 책임지는 회사입니다.`와 `건물을 대하는 태도부터 다릅니다.`로 고정한다.

### `RealCaseEvidence`

- 기존 실제 관리사례 데이터를 확장해 문제·조치·결과를 표시한다.
- 결과는 `현장 사진 기록`, `후속 확인 항목 정리`처럼 실제로 증명 가능한 표현만 쓴다.

### `MidConversionCta`

- 실제 관리사례와 월간 보고 다음에 배치한다.
- 기존 `QuickEstimateTrigger`를 사용해 동일한 신청 모달을 연다.
- 전화번호 버튼을 보조 행동으로 유지한다.

### 기존 시각 모듈

- `ServiceVisualMenu`, `ManagementCycle`, `ManagementComparison`, `ManagementScopeTable`, `OperatingStandardComparison`, `CertificationStrip`은 재사용한다.
- 하나의 긴 `bc-visual-hub`에 몰아두지 않고 관련 설명 구간 사이에 분산한다.

## 반응형·접근성

- 모바일에서는 신뢰 띠를 세로 3행으로 바꾸고, 비교표는 기존 카드형 변환을 유지한다.
- 사례 카드의 문제·조치·결과 레이블은 텍스트로 제공한다.
- 중간 CTA는 키보드로 작동하는 기존 버튼 컴포넌트를 사용한다.
- 가로 스크롤이 생기지 않아야 한다.

## 테스트 기준

- Hero 다음에는 `BrandTeamManifesto`가 먼저 나오고, 그 다음이 `CertificationTrustBar`여야 한다.
- 계단 단체 장면은 기존 Hero 현장 사진을 교체하지 않고 추가되어야 한다.
- 계단 단체 장면에는 브랜드 캠페인 이미지라는 표기가 있어야 한다.
- 상세 인증 카드는 실제 사례·가격·운영 기준 뒤에 있어야 한다.
- 관리사례마다 문제·조치·결과 레이블이 보여야 한다.
- 중간 무료 관리진단 CTA가 존재하고 기존 신청 경험을 연다.
- 인증 카드 3개만 노출되고 만료된 2026년 중소기업 확인서는 보이지 않아야 한다.
- `4.9점`, `최우수`, `100% 보상` 같은 검증되지 않은 문구가 없어야 한다.
- 랜딩 전체 테스트, 프로덕션 빌드와 라이브 DOM 검수를 통과해야 한다.
