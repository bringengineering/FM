# BRING 무료 웹 TV 키오스크 설계

## 목표

회사 TV에 업무지시, 프로젝트, 성과, 이슈, 공지와 시간표를 순환 표시한다. TV 컴퓨터는 Windows Edge 전체화면으로 회사 웹 TV 주소를 자동 실행하고, CRM에서 게시한 내용은 별도 설치 파일이나 프로그램 업데이트 없이 다음 조회 주기에 반영한다.

이 전환은 Windows EXE 코드서명과 TV 전용 유료 인증서를 요구하지 않는다. 기존 회사 Cloudflare Worker와 TV 전용 저장소를 재사용하며, 현재 사용량이 Cloudflare 무료 한도 안에 있는 동안 추가 서비스 비용은 없다.

## 확정한 방향

### 채택: Cloudflare Worker 동일 출처 웹 TV

- `bring-crm-ai-gateway.bringengineering1008.workers.dev`에 TV 전용 웹 화면을 제공한다.
- TV는 직원 Firebase 로그인 정보를 보관하지 않는다.
- 최초 실행 때 일회용 승인 코드를 표시하고 CRM 관리자가 기기명을 확인한 뒤 승인한다.
- 승인 후 Worker가 `HttpOnly`, `Secure`, `SameSite=Strict` 기기 쿠키를 발급한다.
- 브라우저 JavaScript, 주소, `localStorage`, `sessionStorage`, 로그에는 원시 기기 인증값을 남기지 않는다.
- 관리자가 기기를 해제하면 다음 요청부터 표시가 중단된다.
- 게시된 화면 자료는 짧은 주기로 다시 읽고 자동 반영한다. 웹 파일 자체는 서버 배포 즉시 갱신되므로 TV 프로그램 업데이트가 없다.

### 제외: 서명 없는 Electron 운영 배포

기존 Electron TV 코드는 향후 유료 코드서명 도입 가능성을 위해 보존하지만 운영 기본 경로로 사용하지 않는다. 무서명 EXE, 자체서명 인증서, CRM 업데이트 채널과 TV 채널 혼용은 허용하지 않는다.

## 사용자 흐름

### TV 최초 연결

1. Windows TV 컴퓨터가 Edge 키오스크 모드로 웹 TV 주소를 연다.
2. 서버에 승인된 기기 쿠키가 없으면 화면에 8자리 승인 코드와 연결 상태만 표시한다.
3. 관리자는 CRM의 회사 운영보드에서 승인 코드와 TV 이름을 입력한다.
4. TV가 승인 결과를 확인하면 서버가 브라우저 전용 기기 쿠키를 설정한다.
5. TV는 게시된 운영보드를 불러와 전체화면 순환을 시작한다.

### 일상 운영

1. CRM 관리자가 공개 가능한 수치·공지·일정을 검토한다.
2. `TV에 게시`를 실행하면 기존 낙관적 버전 검사를 거쳐 새 스냅샷을 저장한다.
3. TV는 15초 이내의 다음 조회에서 새 버전을 받고 현재 장면을 안전하게 교체한다.
4. 네트워크가 끊기면 마지막으로 검증된 공개 스냅샷만 표시하고 연결 끊김을 작게 알린다.
5. 연결이 복구되면 최신 버전으로 자동 전환한다.

### 기기 해제

관리자가 CRM에서 기기를 해제하면 서버 저장소의 권한이 즉시 무효화된다. TV 쿠키가 남아 있어도 새 데이터와 기존 서버 자료를 받을 수 없으며 다시 연결하려면 새 승인 코드가 필요하다.

## 화면 구성

기존 BRING FM의 흰색 카드, 파란 강조색, 짙은 글자, 넉넉한 여백을 그대로 사용한다. TV 해상도별로 정보량만 조정하고 별도 브랜드 스타일을 만들지 않는다.

순환 화면은 기존 다섯 장면을 유지한다.

1. 회사 현황: 진행 중 업무, 완료, 지연, 전체 진행률
2. 팀 성과: 담당자별 목표·실적·증빙·미보고
3. 업무지시: 오늘·이번 주 업무, 기한, 담당자, 상태
4. 이슈·공지: 긴급 이슈, 결정 필요, 회사 공지
5. 일정: CRM 내부 일정과 현장 방문·회의·마감

개인 전화번호, 상세 주소, 고객 상담 원문, 출입정보, 비밀번호, 인증정보는 TV 스냅샷에 포함하지 않는다.

## 구성요소와 책임

### Worker 웹 TV 셸

- TV HTML·CSS·JavaScript를 같은 회사 Worker 도메인에서 제공한다.
- 보안 헤더와 콘텐츠 보안 정책을 고정한다.
- 승인 코드 발급, 브라우저 승인 완료, 게시 자료 조회를 분리된 경로로 제공한다.
- 기존 Electron의 Authorization 헤더 경로는 호환을 위해 유지하되 웹 쿠키와 혼용하지 않는다.

### 브라우저 기기 세션

- 원시 기기 토큰은 Worker가 암호학적으로 안전하게 생성하고 해시만 서버 저장소에 보관한다.
- 브라우저에는 서버가 읽는 보호 쿠키만 남긴다.
- 쿠키에는 짧고 임의적인 기기 세션 값만 저장하며 직원 신원이나 고객정보를 넣지 않는다.
- 승인 대기 토큰은 메모리에만 두고 새로고침 시 새 코드를 발급해도 안전하게 처리한다.

### 웹 TV 렌더러

- 기존 `wallboard-publication-schema`와 `company-wallboard` 장면 규칙을 재사용한다.
- DOM 문자열은 안전하게 이스케이프하고 임의 HTML을 렌더링하지 않는다.
- 720p와 1080p에서 잘림 없이 보이고, 브라우저 확대율 100%를 기준으로 한다.
- 웹 기기는 앱 버전이나 원격 설치 상태 대신 `웹 자동반영` 상태를 보고한다.

### CRM 관리자 화면

- 웹 TV 기기에는 EXE 버전 예약·취소 버튼을 표시하지 않는다.
- 기기 유형, 마지막 접속, 연결 상태, 게시 버전, 해제 버튼을 보여 준다.
- 기존 Electron 기기가 남아 있으면 기존 버전과 업데이트 상태를 그대로 표시한다.

### Windows 자동 실행

- 저장소에 관리자 권한 없이 실행 가능한 설치 스크립트를 제공한다.
- 스크립트는 현재 Windows 사용자의 시작프로그램에 Edge 키오스크 바로가기를 만든다.
- URL은 회사 Worker의 고정 `/tv` 주소만 허용한다.
- 제거 스크립트는 해당 바로가기만 삭제하고 브라우저 데이터나 다른 파일은 지우지 않는다.

## 보안 경계

- 웹 TV는 회사 CRM 관리자 권한을 갖지 않는다.
- 승인·게시·기기 해제는 Firebase에서 확인된 관리자만 가능하다.
- TV 표시 조회는 해당 기기 세션만 허용한다.
- 쿠키 인증 요청에는 CORS를 허용하지 않고 상태 변경 경로는 동일 출처만 받는다.
- API 응답은 `Cache-Control: no-store`, HTML 정적 셸은 짧은 캐시와 새 배포 재검증을 사용한다.
- CSP는 자체 스크립트·스타일만 허용하고 외부 프레임과 임의 연결을 차단한다.
- 로그에는 승인 코드, 쿠키, 원시 기기 토큰, 고객정보를 기록하지 않는다.
- 기존 AI, Telegram, 카카오, CRM 데이터 경로와 Worker 저장소는 변경하지 않는다.

## 실패 처리

- 연결 전: 승인 코드와 재시도 상태만 표시한다.
- 서버 장애: 마지막 검증 스냅샷을 유지하고 과장된 성공 상태를 만들지 않는다.
- 잘못된 응답: 기존 장면을 유지하고 새 응답을 폐기한다.
- 기기 해제: 즉시 연결 화면으로 돌아가며 로컬 공개 스냅샷을 삭제한다.
- 브라우저 저장소 손상: 공개 스냅샷만 초기화하고 새 승인을 요구한다.
- Edge 미설치 또는 경로 변경: 자동 실행 설치가 명확한 오류를 내고 시작프로그램을 반쯤 만들지 않는다.

## 데이터와 호환성

- Worker의 기존 Durable Object 기기 목록과 게시 스냅샷을 그대로 사용한다.
- 기기에 `clientType: "web" | "electron"`을 추가한다. 값이 없는 기존 기기는 `electron`으로 읽는다.
- 웹 기기는 `clientVersion`과 `targetVersion`을 요구하지 않는다.
- 기존 Electron 기기 토큰·업데이트 기록을 삭제하거나 변환하지 않는다.
- CRM 원본 데이터와 TV 공개 스냅샷은 계속 분리한다.

## 검증 기준

자동검증:

- 웹 TV 정적 파일은 직원 인증 코드와 비밀 값을 포함하지 않는다.
- 브라우저 승인 완료 응답은 원시 기기 토큰을 JSON으로 반환하지 않는다.
- 쿠키는 `HttpOnly`, `Secure`, `SameSite=Strict`, 제한된 경로를 사용한다.
- 미승인·해제 기기는 표시 API를 읽지 못한다.
- 웹 기기에는 EXE 업데이트 명령이 만들어지지 않는다.
- 기존 Electron 승인·표시·업데이트 테스트는 그대로 통과한다.
- Worker 전체 테스트, CRM 전체 테스트와 배포 검사가 통과한다.

실기기 검증:

- Windows 재부팅 후 Edge가 TV 주소를 전체화면으로 자동 실행한다.
- CRM 승인 뒤 15초 안에 운영보드가 표시된다.
- 다섯 장면이 정해진 간격으로 순환한다.
- CRM 재게시 뒤 TV가 자동 반영한다.
- 네트워크 단절·복구와 기기 해제가 예상대로 동작한다.
- 1280×720과 1920×1080에서 글자·카드가 잘리지 않는다.

## 배포 순서

1. 테스트 우선으로 웹 세션·웹 렌더러·CRM 기기 유형을 구현한다.
2. 로컬 Worker와 CRM 전체 테스트를 통과시킨다.
3. GitHub 검토 요청을 만들고 운영 브랜치에 병합한다.
4. 회사 Cloudflare Worker만 배포한다. Firebase Functions와 Hosting은 배포하지 않는다.
5. 공개 `/tv` 화면과 익명·해제 요청 차단을 탐침한다.
6. TV Windows 컴퓨터에서 자동 실행 스크립트를 한 번 실행한다.
7. CRM에서 기기를 승인하고 실기기 검수표를 완료한다.

## 완료 조건

TV 컴퓨터를 켰을 때 별도 로그인이나 프로그램 업데이트 없이 BRING 운영보드가 전체화면으로 열리고, CRM에서 게시한 검토 완료 자료가 자동 반영되며, 관리자 기기 해제가 즉시 적용되면 완료다.
