# BRING CRM 내부 FIELD 통합 및 자동 로그인 설계

## 목표

BRING CRM에 로그인한 내부 직원이 왼쪽 `BRING FIELD` 메뉴를 누르면 외부 브라우저나 별도 로그인 화면 없이 CRM 프로그램 오른쪽 업무 영역에서 현장 플랫폼을 사용한다.

기존 CRM 메뉴, 데이터, Firebase 프로젝트와 단독 FIELD 웹앱의 보안은 유지한다. 이번 변경은 CRM과 FIELD를 하나의 프로그램 경험으로 연결하는 작업이며, 기존 CRM 데이터를 이전하거나 두 Firebase 프로젝트를 합치지 않는다.

## 사용자 경험

1. 직원은 기존 방식으로 BRING CRM에 로그인한다.
2. 왼쪽 메뉴에서 `BRING FIELD`를 누른다.
3. CRM의 왼쪽 메뉴와 상단 영역은 유지되고, 오른쪽 업무 영역에 FIELD가 열린다.
4. 화면에는 `CRM 계정 연결 중` 상태가 잠시 표시되고 자동으로 FIELD 홈으로 이동한다.
5. 지도, 건물 등록, 촬영, 업로드 현황, 광고 묶음을 같은 프로그램 안에서 사용한다.
6. 다른 CRM 메뉴를 누르면 기존 CRM 화면으로 즉시 돌아간다.
7. CRM에서 로그아웃하면 내장 FIELD 세션도 종료되고 화면과 임시 연결 정보가 제거된다.

FIELD 단독 주소 `https://bring-fm.web.app/field`로 접속하는 경우에는 기존 Google 로그인과 내부 직원 확인을 그대로 적용한다.

## 채택 방식

두 Firebase 프로젝트 사이에 장기 토큰을 공유하지 않고 60초 동안 한 번만 사용할 수 있는 불투명 연결코드를 사용한다.

- CRM 인증 프로젝트: `bring-fm-hj`
- FIELD 인증 프로젝트: `bring-fm`
- CRM 비밀번호, Google OAuth 토큰, Firebase ID 토큰은 렌더러나 URL로 전달하지 않는다.
- URL에는 무작위 1회용 코드만 잠시 포함한다.
- 코드는 서버에서 한 번 사용되는 즉시 폐기하고 브라우저 주소에서도 제거한다.

Firebase 프로젝트 통합은 기존 권한과 데이터에 영향을 줄 위험이 커서 이번 범위에서 제외한다. 장기 인증 토큰을 Electron 화면에 직접 주입하는 방식도 노출 위험 때문에 사용하지 않는다.

## 구성요소

### 1. CRM Electron 셸

- `BRING FIELD` 클릭을 외부 브라우저 실행이 아닌 전용 IPC 명령으로 처리한다.
- Electron `WebContentsView`를 CRM 오른쪽 콘텐츠 영역에 배치한다.
- 내장 화면은 `https://bring-fm.web.app`만 로드할 수 있다.
- 새 창, 임의 도메인 이동, 파일 다운로드, Node 통합을 차단한다.
- 창 크기가 바뀌면 FIELD 영역도 함께 조절한다.
- 다른 CRM 메뉴를 선택하면 FIELD 뷰를 숨기고 기존 CRM 화면을 복원한다.

### 2. CRM 인증 연결 요청

- Electron 메인 프로세스만 CRM의 최신 Firebase ID 토큰을 읽을 수 있다.
- 메인 프로세스가 FIELD 서버의 연결코드 발급 엔드포인트를 호출한다.
- 렌더러에는 CRM 토큰이나 FIELD 커스텀 토큰을 노출하지 않는다.
- 연결코드 발급 실패 시 기존 CRM 화면 안에 재시도 가능한 오류를 표시한다.

### 3. FIELD 연결코드 서버

두 단계로 동작한다.

1. `createDesktopFieldHandoff`
   - `bring-fm-hj` 발급 ID 토큰의 서명, 발급자, 대상 프로젝트, 만료, 이메일 확인 여부를 검증한다.
   - 이메일을 FIELD 내부 직원 허용목록과 대조하고 FIELD 역할을 결정한다.
   - 256비트 무작위 코드를 생성하고 원문이 아닌 SHA-256 해시만 저장한다.
   - 만료시간 60초, 미사용 상태, 요청 사용자와 감사정보를 기록한다.

2. `exchangeDesktopFieldHandoff`
   - 코드 해시를 찾아 만료 및 미사용 여부를 확인한다.
   - 단일 트랜잭션으로 사용 완료 처리해 재사용 경쟁을 차단한다.
   - `bring-fm`용 Firebase 커스텀 토큰을 반환한다.
   - 성공과 거절 결과를 비밀값 없이 감사 로그에 남긴다.

만료·사용 완료 레코드는 정기 정리 작업으로 삭제한다. 코드 발급과 교환에는 IP/사용자 단위 속도 제한을 적용한다.

### 4. FIELD 웹앱 인증 진입점

- `desktop_handoff`가 있으면 Google 로그인보다 먼저 교환을 시도한다.
- 교환된 커스텀 토큰으로 `signInWithCustomToken`을 수행한다.
- 성공 즉시 `history.replaceState`로 연결코드를 주소에서 제거한다.
- 기존 FIELD 세션 검증과 역할 확인을 다시 거친 뒤 업무 화면을 표시한다.
- 데스크톱 연결 흐름에서 실패하면 Google 로그인 팝업을 자동으로 열지 않고 `CRM으로 돌아가기`와 `다시 연결`을 표시한다.
- 연결코드가 없는 일반 웹 접속은 현재 `AuthGate` 동작을 그대로 유지한다.

## 화면 상태

내장 FIELD 영역은 다음 네 상태만 갖는다.

- `닫힘`: 기존 CRM 화면 표시
- `연결 중`: CRM 계정 확인 및 1회용 코드 교환
- `사용 가능`: FIELD 전체 기능 표시
- `연결 실패`: 원인을 일반화한 안내와 재시도 버튼 표시

연결 중에는 중복 클릭을 막고, 실패해도 기존 CRM 데이터 화면과 로그인 세션에는 영향을 주지 않는다.

## 로그아웃과 세션 수명

- CRM 로그아웃 시 FIELD 뷰에 로그아웃 명령을 보내고 저장된 FIELD 인증을 제거한 뒤 뷰를 폐기한다.
- CRM 사용자 계정이 바뀌면 기존 FIELD 뷰를 재사용하지 않고 새로 만든다.
- FIELD 토큰 갱신은 Firebase SDK가 담당한다.
- 프로그램 재실행 후에는 유지된 CRM 로그인이 유효할 때 새 1회용 코드를 발급해 FIELD를 다시 연결한다.
- FIELD 내 별도 로그아웃 버튼은 CRM 내장 모드에서 숨긴다. 계정 종료는 CRM 로그아웃 한 곳에서만 수행한다.

## Drive 동작

FIELD의 사진·영상은 기존 Firebase Storage 및 서버 Drive 동기화 흐름을 그대로 사용한다. 내장 모드가 Drive OAuth 토큰을 클라이언트로 전달하지 않는다. 서버에 설정된 회사 Drive 연결 상태가 유효하면 별도 Drive 로그인 화면 없이 업로드와 자동 폴더 생성이 계속 동작한다.

Drive 설정이 끊긴 경우 FIELD에는 `회사 Drive 연결 점검 필요` 상태만 표시하고, 일반 직원에게 OAuth 재로그인을 요구하지 않는다. 관리자 복구 절차는 기존 서버 운영 경로를 사용한다.

## 보안 경계

- CRM 인증 토큰은 Electron 메인 프로세스 밖으로 내보내지 않는다.
- 1회용 코드 원문은 서버 데이터베이스에 저장하지 않는다.
- 코드 TTL은 60초이고 정확히 한 번만 사용할 수 있다.
- FIELD 허용목록에 없는 CRM 계정은 연결을 거절한다.
- 내장 WebContentsView는 Node API, preload 임의 호출, 팝업, 외부 탐색을 허용하지 않는다.
- FIELD 원격 콘텐츠가 CRM IPC에 접근할 수 없도록 별도 세션 파티션과 권한 정책을 사용한다.
- 로그에는 ID 토큰, 커스텀 토큰, 연결코드, OAuth 토큰을 기록하지 않는다.

## 오류 처리

- CRM 세션 만료: CRM 재로그인 안내 후 FIELD 연결 중단
- 허용되지 않은 직원: 내부 직원 등록 안내
- 연결코드 만료·재사용: 새 코드 자동 재발급을 한 번 시도하고 실패 시 수동 재시도 제공
- 네트워크 단절: 기존 CRM 화면은 유지하고 FIELD 영역에 연결 재시도 제공
- FIELD 서버 오류: 비밀정보가 없는 추적 ID만 표시
- Drive 설정 오류: 업로드를 로컬 대기열에 유지하고 관리자 점검 상태 표시

## 테스트 기준

### 자동 테스트

- CRM 메뉴가 외부 브라우저를 호출하지 않고 내장 FIELD IPC를 사용한다.
- 허용되지 않은 URL 탐색과 팝업이 차단된다.
- CRM 토큰이 렌더러 응답, URL, 로그에 포함되지 않는다.
- 연결코드는 60초 후 만료되고 한 번만 교환된다.
- 동일 코드 동시 교환에서는 하나만 성공한다.
- 다른 Firebase 프로젝트·미확인 이메일·비허용 직원 토큰은 거절된다.
- 내장 연결 성공 시 FIELD가 자동 로그인되고 URL에서 코드가 제거된다.
- 단독 웹 접속은 기존 Google 로그인 흐름을 유지한다.
- CRM 로그아웃과 사용자 변경 시 FIELD 세션 및 뷰가 폐기된다.
- 기존 CRM 테스트와 FIELD 전체 회귀 테스트가 통과한다.

### 실제 검증

- 설치본에서 `건물 관리` 아래 `BRING FIELD`가 보인다.
- 버튼 클릭 후 Chrome이 열리지 않는다.
- CRM 프로그램 안에서 지도·촬영·사진첩 추가·업로드 현황·광고 묶음이 동작한다.
- `bringengineering1008@gmail.com` CRM 세션으로 FIELD 로그인 화면 없이 진입한다.
- CRM의 다른 메뉴 전환과 로그아웃이 정상 동작한다.
- 휴대전화 단독 FIELD 접속은 기존 보안 로그인을 유지한다.

## 배포 순서

1. FIELD 서버에 연결코드 발급·교환과 보안 규칙을 배포한다.
2. FIELD 웹앱에 데스크톱 연결 진입점을 배포한다.
3. 실제 배포 주소에서 코드 교환과 기존 단독 로그인을 검증한다.
4. CRM 데스크톱 내장 뷰를 포함한 다음 버전을 배포한다.
5. 기존 설치본 자동 업데이트 후 실제 CRM 프로그램에서 최종 검증한다.

서버 기능을 먼저 배포해 구버전 CRM에는 영향이 없도록 하고, 문제가 발생하면 CRM 새 버전만 되돌릴 수 있게 한다.

## 완료 조건

- CRM 최초 로그인 이후 FIELD에서 추가 로그인 요구가 없다.
- FIELD가 외부 사이트 창이 아닌 CRM 내부 업무 영역에서 실행된다.
- 기존 CRM 데이터와 기능, 단독 FIELD 웹 보안이 유지된다.
- 사진·영상 업로드와 Drive 자동 폴더·광고 묶음이 내장 화면에서도 동일하게 동작한다.
- 자동 테스트, 설치본 테스트, 실제 배포 환경 검증이 모두 통과한다.
