# BRING CARE CRM 마케팅 관제 1차 설계

## 1. 목적과 범위

기존 BRING CRM 안에 `운영`과 `마케팅` 두 업무 공간을 만들고, 광고비부터 계약·이익까지 한 프로그램에서 추적한다. 별도 앱이나 별도 로그인은 만들지 않는다.

1차 범위는 다음과 같다.

- 로그인 후 운영·마케팅 공간 선택
- 마케팅 전체 현황
- 채널별 성과
- CRM 고객 전환 퍼널과 유입 정보
- 광고 데이터 수동 입력
- 공통 필터와 핵심 지표 계산
- 미응답·재연락·데이터 누락 알림
- 주간 마케팅 보고서
- 기존 인증·권한·감사기록을 이용한 보호

CSV 업로드, 외부 광고 API, 자동 예산 변경, 문자·이메일 자동 발송, LTV 분석은 후속 버전으로 남긴다.

## 2. 절대 보존 조건

- 기존 고객·건물·상담·영업·계약·작업·입금 데이터와 17단계 업무 흐름을 삭제하거나 의미 변경하지 않는다.
- 현진님을 포함한 팀원의 최신 운영 변경을 덮어쓰지 않는다.
- 기존 레코드에 새 필드가 없어도 모든 기존 화면이 정상적으로 열린다.
- 마케팅 저장 실패가 CRM의 기존 저장을 막지 않는다.
- 운영 데이터나 실제 고객정보를 개발 테스트 데이터로 사용하지 않는다.
- Firebase 설정 블록과 기존 로그인 흐름을 교체하지 않는다.

## 3. 사용자 경험과 정보 구조

### 3.1 업무 공간 입구

로그인 성공 후 첫 진입에는 두 개의 큰 폴더 카드를 표시한다.

- `운영`: 현재 CRM 전체 기능
- `마케팅`: 새 마케팅 관제 기능

한 번 선택한 공간은 기기 로컬 환경설정에 마지막 공간으로 기억한다. 이후에는 기억한 공간으로 바로 들어가되, 좌측 상단 또는 상단 바의 공간 전환 버튼으로 언제든 `운영 ↔ 마케팅`을 전환할 수 있다. URL, 로그인 세션, 자동 업데이트 방식은 하나로 유지한다.

### 3.2 운영 공간

현재 좌측 메뉴와 동작을 그대로 보존한다. 새 공간 구조를 도입하기 위해 기존 메뉴명을 바꾸거나 순서를 재편하지 않는다.

### 3.3 마케팅 공간 메뉴

1. 전체 현황
2. 채널별 성과
3. 고객 전환
4. 광고 데이터 입력
5. 알림
6. 주간보고

모바일에서는 핵심 지표, 전환 퍼널, 오늘 알림, 주간보고를 먼저 보여주고 넓은 표는 카드 또는 가로 스크롤로 제공한다.

## 4. 시스템 구성과 책임 분리

마케팅 기능은 기존 거대 렌더러에 계산 로직을 직접 섞지 않고 다음 경계로 분리한다.

- `marketing-core`: 정규화, 필터, 기간 비교, 퍼널, KPI, 채널 평가, 알림 계산
- `marketing-store`: 마케팅 레코드의 읽기·쓰기·버전 충돌·감사기록 계약
- `marketing-ui`: 업무 공간 입구, 대시보드, 표, 입력 폼, 보고서 렌더링
- 기존 CRM 연결 어댑터: 고객·케이스·영업·계약·작업 데이터를 읽기 전용 분석 스냅샷으로 변환

UI는 계산 결과를 표시하고 사용자 입력을 수집한다. 지표 계산과 중복 판정은 순수 함수에서 수행한다. Firebase 쓰기는 기존 메인 프로세스의 검증된 IPC 및 서버 저장 경로를 거친다.

## 5. 데이터 모델

### 5.1 기존 고객·케이스 확장

기존 엔터티에는 선택적 `marketing` 객체만 추가한다.

```text
marketing
- firstSource
- lastSource
- subChannel
- campaignId
- campaignName
- keyword
- contentId
- contentTitle
- inquiryMethod
- validLead
- invalidReason
- firstTouchAt
- inquiryAt
- attributionNote
```

기존 영업·계약 데이터에 이미 존재하는 담당자, 다음 연락일, 견적금액, 계약금액, 예상원가, 입금액, 실패 사유를 우선 재사용한다. 같은 의미의 필드를 중복 생성하지 않는다. 연결 기준은 안정적인 고객 또는 케이스 ID이며 이름·전화번호만으로 자동 연결하지 않는다.

### 5.2 별도 마케팅 경로

```text
marketing/
  daily/{recordId}
  alerts/{alertId}
  settings/{settingId}
  audits/{auditId}
```

일별 광고 레코드는 다음 필드를 가진다.

```text
id, date, channel, accountName, campaignId, campaignName,
adGroup, keyword, contentId, contentTitle, service, region,
spend, impressions, clicks, phoneClicks, chatClicks,
directionsClicks, saves, platformLeads, note,
sourceType, enteredBy, enteredAt, updatedBy, updatedAt,
version, archivedAt
```

`sourceType`은 1차에서 `manual`과 `crm`만 허용한다. 삭제는 `archivedAt`을 설정하는 보관 처리이며, 금액 변경은 수정 전후 값과 작업자를 감사기록에 남긴다.

### 5.3 중복 판정

수동 저장 전에 `날짜 + 채널 + 캠페인 + 키워드 또는 콘텐츠`를 정규화한 키로 기존 활성 레코드를 검사한다. 일치하면 자동 저장하지 않고 기존 데이터 비교, 덮어쓰기, 취소 중 사용자가 선택하게 한다. 덮어쓰기도 버전 기반 조건부 저장을 사용한다.

## 6. 공통 필터와 기간

전체 마케팅 화면은 하나의 필터 상태를 공유한다.

- 기간: 오늘, 어제, 최근 7일, 이번 주, 지난주, 이번 달, 지난달, 직접 설정
- 채널
- 서비스
- 지역
- 담당자
- 고객 유형
- 캠페인
- 키워드
- 신규·기존 고객
- 데이터 상태

날짜 경계는 한국시간으로 계산한다. 비교 기간은 현재 선택 기간과 길이가 같은 직전 기간이다. 필터 변경 시 KPI, 퍼널, 표, 알림, 보고서 미리보기를 같은 스냅샷에서 다시 계산한다.

## 7. 지표와 귀속 규칙

확정 계산식은 다음과 같다.

- CTR = 클릭 ÷ 노출 × 100
- CPC = 광고비 ÷ 클릭
- 문의 CVR = 실제 문의 ÷ 클릭 × 100
- 유효 문의율 = 유효 문의 ÷ 실제 문의 × 100
- CPL = 광고비 ÷ 유효 문의
- 견적 전환율 = 견적 ÷ 유효 문의 × 100
- 계약 전환율 = 계약 ÷ 견적 × 100
- CPA = 광고비 ÷ 신규 계약
- AOV = 계약금액 ÷ 계약 수
- ROAS = 광고 유입 계약금액 ÷ 광고비 × 100
- 예상 마케팅 이익 = 계약금액 - 예상 작업원가 - 광고비
- 마케팅 ROI = 예상 마케팅 이익 ÷ 광고비 × 100

분모가 0이면 `0`으로 오인시키지 않고 `-`를 표시한다. 취소·무효 계약은 계약 수와 계약금액에서 제외한다. 계약금액과 실제 입금액은 분리한다. 금액은 원 단위 정수, 날짜는 한국시간을 기준으로 한다. 세금 기준은 기존 CRM 금액 필드의 의미를 그대로 따르며 마케팅 모듈에서 임의 변환하지 않는다.

기본 성과 귀속은 `최초 유입`이며 `최종 유입`은 보조 비교로 제공한다. 값이 없으면 추측하지 않고 `확인 필요`로 집계한다.

## 8. 화면별 기능

### 8.1 전체 현황

총마케팅비, 노출, 클릭, 실제 문의, 유효 문의, 견적, 계약, 계약금액, 예상이익, 실제 입금액과 직전 기간 대비 증감을 표시한다. CTR, CPC, 문의 CVR, CPL, 견적·계약 전환율, CPA, ROAS, ROI, 평균 계약금액을 제공한다.

퍼널은 `노출 → 클릭 → 실제 문의 → 유효 문의 → 상담 → 견적 → 계약 → 결제` 순서이며 단계별 건수, 전환율, 이탈 수, 비교 기간 변화를 표시한다.

### 8.2 채널별 성과

채널별 비용, 노출, 클릭, 유효 문의, 견적, 계약, 매출, 이익, CPL, CPA, ROAS를 비교한다. 규칙 기반으로 `확대 검토`, `유지`, `개선 필요`, `중단 검토`, `데이터 부족`과 근거를 표시하지만 광고 계정이나 예산은 자동 변경하지 않는다.

### 8.3 고객 전환

기존 17단계를 분석용으로만 `신규 문의, 유효 문의, 상담, 견적, 계약, 작업, 결제, 사후관리`에 매핑한다. 원래 단계 값과 전환 규칙은 바꾸지 않는다. 고객 상세에서 최초·최종 유입, 캠페인, 키워드, 문의 방식, 유효 여부, 마케팅 메모와 실패 사유를 편집한다.

### 8.4 광고 데이터 입력

수기 입력, 이전 레코드 복사, 수정, 보관을 제공한다. 필수값·음수·비정상 날짜를 저장 전에 차단하고 중복 가능성을 확인한다. 마지막 업데이트 시각과 입력자를 표시한다.

### 8.5 알림

읽기 시점에 규칙 엔진이 다음 항목을 계산한다.

- 신규 문의 30분 이상 미응답
- 담당자 또는 다음 연락일 누락
- 오늘 또는 기한 초과 재연락
- 견적 후 24시간 무응답
- 광고비가 있으나 유효 문의 없음
- 72시간 이상 업데이트되지 않은 채널
- 계약금액·예상원가·입금·유입 경로 누락

알림은 근거 레코드로 이동할 수 있어야 하며 임의로 고객에게 메시지를 발송하지 않는다.

### 8.6 주간보고

선택 기간의 확정 계산 스냅샷으로 총광고비, 문의, 유효 문의, 견적, 계약, 계약금액, 예상이익, 채널별 성과, 좋은 채널·키워드, 비용만 발생한 항목, 실패 사유, 다음 주 검토 사항을 생성한다. 화면 보기, 복사, 인쇄와 운영체제의 PDF 저장을 지원한다. 보고서 숫자는 UI의 KPI와 동일한 계산 결과를 재사용한다.

## 9. 권한과 개인정보

최신 CRM의 회사 이메일 로그인과 서버 권한 확인을 재사용한다. 별도 공용 비밀번호나 두 번째 사용자 목록을 만들지 않는다.

- 관리자: 운영·마케팅 전체 조회·수정, 목표·사용자·설정, 보관·복원, 내보내기
- 마케팅 담당: 광고 입력·수정, 채널 분석, 보고서, 제한된 고객정보
- 영업 담당: 고객 유입·상담·견적·계약 결과, 광고비 수정 불가
- 조회 전용: 집계 조회, 개인정보 마스킹, 수정 불가

대표와 현진님은 현재 요구에 따라 관리자 권한으로 운영할 수 있게 하되, 권한은 이름 하드코딩이 아니라 기존 서버 역할 설정으로 부여한다. 우중님은 기본적으로 마케팅 담당 역할을 사용하며 관리자가 변경할 수 있다.

`cases`와 `marketing` 쓰기 권한은 Database Rules에서 분리한다. 비로그인 사용자는 둘 다 읽을 수 없다. CSV 내보내기는 1차 UI에 노출하지 않으며 향후 추가 시 관리자 전용으로 한다.

## 10. 오류·동시수정·데이터 품질

- 서버 저장 성공 전에는 저장 완료로 표시하지 않는다.
- 마케팅 저장 실패는 원래 CRM 레코드를 롤백하거나 차단하지 않는다.
- 레코드별 버전과 조건부 저장으로 동시수정 충돌을 감지하고 새 서버 값을 보여준다.
- 데이터가 없으면 오류 대신 `데이터 없음`과 마지막 확인 상태를 표시한다.
- 유입 경로와 키워드는 비어 있을 수 있으며 이를 임의 추정하지 않는다.
- 유효 문의를 무효로 바꾸면 사유를 필수로 받되 레코드를 삭제하지 않는다.
- 계산에서 제외된 레코드 수와 이유를 확인할 수 있게 한다.

## 11. 테스트 전략

운영 Firebase 고객 데이터는 사용하지 않는다. 순수 계산 테스트, 가짜 저장소, 로컬 Rules 에뮬레이터, UI 계약 테스트로 검증한다.

- 기간·한국시간·직전 기간 경계
- 모든 계산식과 0분모 처리
- 취소 계약 제외, 계약금액·입금액 분리
- 최초·최종 유입 귀속
- 신규 케이스 한 번만 집계
- 17단계의 분석 단계 매핑
- 필터 조합과 채널 비교
- 중복 경고와 버전 충돌
- 역할별 조회·쓰기·마스킹
- 기존 고객의 새 필드 누락 호환성
- 기존 CRM 전체 회귀 테스트
- 모바일 핵심 화면 계약

## 12. 배포 방식

최신 `codex/bring-field-platform`에서 분리한 작업 브랜치에 구현한다. 운영 브랜치가 움직이면 변경을 먼저 통합하고 fast-forward 가능한 경우에만 반영한다. 기존 태그는 이동하거나 재사용하지 않고 다음 미사용 CRM 버전을 예약한다.

Windows EXE, blockmap, latest.yml을 공개한 뒤 설치된 이전 버전의 자동 업데이트 인식까지 확인한다. Firebase Functions와 Hosting은 배포하지 않는다. 데이터 경로에 필요한 Database Rules만 에뮬레이터 검증 후 배포한다.

## 13. 완료 기준

1. 로그인 후 운영·마케팅 두 공간을 선택하고 전환할 수 있다.
2. 기존 운영 메뉴와 17단계 흐름이 동일하게 작동한다.
3. 고객에게 최초·최종 유입과 캠페인·키워드를 기록할 수 있다.
