# BRING CRM AI 상담 등록·계약 준비 도우미 설계

## 목표

BRING CRM 고객 관리에서 녹음 파일 또는 대화문을 받아 고객·상담·후속 업무 정보를 자동 정리하고, 직원이 확인한 뒤 서버에 한 번에 저장한다. 상담이 계약 단계로 진행되면 Google Drive의 회사 계약 자료를 기준으로 계약 유형별 준비 서류와 누락 항목을 안내한다.

두 기능은 같은 고객 흐름에서 연결되지만 독립 모듈로 구현한다.

- `AI 상담 등록`: 대화를 CRM 데이터 초안으로 변환한다.
- `계약 준비 도우미`: 승인된 회사 기준을 계약 체크리스트로 변환하고 진행 상황을 관리한다.

AI는 직원 확인 없이 고객 정보, 계약 기준 또는 외부 메시지를 자동 확정하지 않는다.

## 1. AI 상담 등록

### 진입점

고객 관리와 상담 기록 화면에 `AI 상담 등록` 버튼을 둔다. 모바일과 데스크톱에서 동일하게 사용할 수 있어야 한다.

### 입력

- MP3, M4A, WAV 녹음 파일
- 붙여넣은 대화문
- 기존 고객 선택 또는 신규 고객 후보 생성

지원 한도와 허용 확장자는 화면에 표시한다. 업로드한 원본 녹음은 전사 처리 후 기본적으로 장기 보관하지 않는다.

### AI 추출 항목

- 고객명, 연락처, 고객 유형
- 관련 건물명과 주소
- 현재 요청사항
- 상담 내용과 결과
- 다음 행동과 다음 연락 예정일
- 개인 메모·고객 특징
- 예상 계약금액
- 작업 종류와 우선순위
- 계약 가능성 및 추천 계약 유형

AI가 확인하지 못한 값은 비워 두고 추측값을 사실처럼 저장하지 않는다. 추정 항목에는 `확인 필요` 표시를 붙인다.

### 확인 및 저장

AI 처리 결과를 항목별 편집 화면으로 보여준다. 직원은 각 항목을 수정하거나 저장 대상에서 제외할 수 있다.

확정 시 다음 순서로 서버 저장을 실행한다.

1. 기존 고객을 연결하거나 신규 고객을 생성한다.
2. 고객 요청사항과 개인 메모를 반영한다.
3. 상담 기록을 생성한다.
4. 필요한 후속 할 일을 생성한다.
5. 직원이 승인한 경우에만 건물 정보를 연결 또는 생성한다.

부분 저장으로 데이터가 어긋나지 않도록 하나의 저장 작업으로 처리한다. 서버가 저장 성공을 확인하지 못하면 성공으로 표시하지 않고, 입력과 AI 결과를 로컬 임시 초안으로 보존하여 재시도할 수 있게 한다.

## 2. 계약 준비 도우미

### 기준 자료

Google Drive의 건물운영 관리 체계에 있는 계약·운영 자료를 기준으로 한다. 초기 대상에는 다음 문서 계열을 포함한다.

- 건물관리·임대차 위탁계약서
- 공용부 청소 위탁계약서
- 협력업체 용역계약서
- 중개보조 업무위탁계약서
- 근로계약서
- 개인정보·보안 서약서
- 협력업체 자격·보험 확인서
- 계약책임·지연배상 기준서
- 신분증 사본 목적 외 사용금지 확인서
- 증거보전·기록관리 매뉴얼

동일한 이름의 문서가 여러 폴더에 있을 수 있으므로 파일명만으로 최신 기준을 고르지 않는다. 관리자가 승인한 파일 ID를 기준 문서로 등록하고, 그 파일의 수정 시각과 버전을 추적한다.

### 동기화 정책

- 회사 중계 서버가 하루 한 번 승인된 Drive 파일의 변경 여부를 확인한다.
- CRM 실행 시 마지막 확인 시각과 변경 감지 상태를 읽는다.
- 변경된 문서는 곧바로 운영 기준에 반영하지 않는다.
- 관리자는 기존 기준과 새 문서에서 추출한 체크리스트 차이를 검토해 승인 또는 보류한다.
- 승인된 버전만 전체 직원의 계약 준비 안내에 사용한다.
- 관리자는 필요할 때 `지금 확인`으로 즉시 변경 검사를 실행할 수 있다.

Drive 접근 권한과 인증 정보는 데스크톱 앱이나 GitHub에 넣지 않고 회사 중계 서버에서 관리한다.

### 계약 준비 안내

고객 또는 계약 화면에서 계약 유형을 자동 추천하되 직원이 변경할 수 있다. 선택한 유형에 따라 다음 정보를 제공한다.

- 사용할 계약서와 기준 문서
- 고객·건물주에게 요청할 서류
- 회사가 준비할 서류
- 협력업체에게 요청할 자격·보험 자료
- 계약 전 확인사항
- 서명·날인·교부 확인
- 담당자와 준비 기한
- 준비 완료, 미완료, 해당 없음 상태
- 누락 항목과 다음 행동

각 체크 항목에는 해당 기준 문서, 승인된 기준 버전, 근거 문구 위치를 연결한다. 법률적 판단이 필요한 내용은 `회사 운영 참고용이며 최종 확인 필요`로 표시한다.

### 상담 흐름과의 연결

AI 상담 등록 결과에서 계약 가능성이 확인되면 다음을 제안한다.

1. 추천 계약 유형을 표시한다.
2. `계약 준비 시작` 버튼을 제공한다.
3. 승인된 기준으로 체크리스트를 생성한다.
4. 누락 서류를 CRM 할 일로 추가할 수 있게 한다.
5. 계약 상태와 입금·작업 일정 화면에 연결한다.

AI의 추천은 초안이며 계약 생성과 체크리스트 확정은 직원이 승인한다.

## 3. 구성 요소

### 데스크톱 CRM

- 녹음·대화문 입력 모달
- 전사 및 분석 진행 상태
- AI 결과 검토·편집 화면
- 고객·상담·할 일 통합 저장
- 계약 준비 체크리스트 화면
- 기준 문서 변경 알림과 관리자 승인 화면

### 회사 중계 서버

- 사용자 인증과 권한 확인
- 녹음 파일 전사 요청
- 구조화 AI 요청
- 일일 Drive 변경 감지
- 기준 문서 내용 추출과 버전 저장
- 체크리스트 차이 생성
- API 키와 Google 인증 정보 보호

### 데이터

- AI 상담 임시 초안과 처리 상태
- 전사 결과 및 추출 필드
- 직원의 최종 승인 기록
- 승인된 계약 기준 문서 ID와 버전
- 계약 유형별 체크리스트 템플릿
- 고객별 계약 준비 상태
- 변경 승인 이력과 담당자

원본 녹음은 처리 완료 후 삭제하는 것을 기본값으로 한다. 전사문은 직원이 CRM 상담 기록으로 저장하기로 승인한 범위만 보관한다.

## 4. 권한

- 일반 직원: 녹음 전사, AI 상담 정리, 결과 수정·확정, 승인된 계약 체크리스트 사용
- 관리자: 기준 Drive 파일 등록, 즉시 변경 확인, 변경 비교, 새 기준 승인·보류
- 시스템 관리자: 중계 서버 인증과 외부 서비스 키 관리

계약 기준 변경과 고객 데이터 저장은 감사 이력에 사용자, 시각, 대상, 결과를 남긴다.

## 5. 오류 처리

- 음성 인식 실패: 원본 입력을 유지하고 재시도 또는 대화문 직접 입력 제공
- AI 구조화 실패: 전사문을 유지하고 재분석 제공
- 고객 중복 가능성: 자동 생성하지 않고 기존 고객 후보를 표시
- 서버 저장 실패: 저장 성공으로 표시하지 않고 초안 보존
- Drive 접근 실패: 기존 승인 버전을 계속 사용하고 관리자에게 동기화 오류 표시
- 문서 중복·이동: 승인된 파일 ID를 우선하며 새 후보는 관리자 검토 대상으로 분리
- 문서 변경 감지: 기존 운영 기준을 유지한 채 차이만 표시

## 6. 검증 기준

- 녹음 파일과 대화문 모두 동일한 검토 화면으로 변환된다.
- 신규 고객과 기존 고객 연결을 직원이 구분해서 확정할 수 있다.
- 고객, 상담, 할 일 저장이 서버 확인을 받은 경우에만 완료로 표시된다.
- AI가 개인 메모와 공식 상담 내용을 별도 필드로 유지한다.
- 승인되지 않은 Drive 변경은 직원 체크리스트에 반영되지 않는다.
- 승인된 기준 문서의 파일 ID, 버전, 수정일을 추적할 수 있다.
- 계약 유형별 누락 서류와 다음 행동이 고객 화면에서 확인된다.
- 일반 직원은 계약 기준을 변경할 수 없다.
- 원본 녹음 삭제 정책과 개인정보 안내가 화면에 표시된다.
- 기존 CRM 고객·상담·계약·작업 기능과 기존 데이터가 유지된다.

## 7. 개발 순서

두 모듈은 다음 순서로 나누어 배포한다.

1. 대화문 기반 AI 상담 등록과 서버 저장 검증
2. 녹음 업로드·전사 추가
3. 승인된 Drive 기준 문서 등록과 변경 감지
4. 계약 체크리스트 생성·고객 화면 연결
5. Drive 변경 비교·관리자 승인 자동화

각 단계는 독립적으로 테스트하고 운영 브랜치에 반영한다. 기존 CRM과 현진님이 추가한 기능을 덮어쓰지 않고 최신 운영 브랜치를 기준으로 작업한다.
