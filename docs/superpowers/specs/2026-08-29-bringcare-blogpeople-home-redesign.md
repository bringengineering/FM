# 브링케어 블로그피플 100개 분석 기반 홈·콘텐츠 시스템 개편 설계

작성일: 2026-08-29  
대상: 네이버 블로그 `bringcare`  
참고 표본: 네이버 블로그팀 공식블로그 `blogpeople` 공개 글 100개

## 1. 목적

브링케어 블로그의 첫 화면을 최신 글 하나가 크게 노출되는 구조에서, 방문자가 회사·서비스·현장 증거·건물주 정보를 한눈에 찾는 프롤로그형 홈으로 바꾼다. 동시에 `blogpeople`의 공개 글 100개에서 확인한 반복 가능한 편집 원리를 브링케어 매뉴얼, 게시물 템플릿과 검증 기준에 반영한다.

참고 블로그의 문구·색상·이미지를 복제하지 않는다. 정보 계층, 반복 시리즈, 제목 약속, 카드형 탐색 구조만 브링케어의 사실과 브랜드 자산에 맞게 재설계한다.

## 2. 표본과 확인 범위

- 표본 수: 고유 게시물 100개
- 표본 기간: 2025년 2월~2026년 8월 공개 글
- 수집 항목: 제목, 게시일, 댓글 표시값, 시리즈 접두어, 숫자·시기 표현, 질문·행동 표현, 이모지, 카테고리 계열
- 별도 확인: 공식블로그 프롤로그의 배경, 중앙 콘텐츠 보드, 메뉴, 대표 글, 최신 글, 프로필 배치
- 제한: 댓글 수는 콘텐츠 품질의 단독 지표가 아니며 이벤트 보상과 공식 채널 규모의 영향을 받는다. 브링케어에 댓글 수치를 목표로 이식하지 않는다.

| 항목 | 확인 수 | 적용 해석 |
|---|---:|---|
| 대괄호 시리즈 접두어 | 35 | 반복 콘텐츠에만 고정 시리즈명을 사용한다. |
| 이모지 포함 | 36 | 제목당 0~1개를 원칙으로 하고 기능이 있을 때만 쓴다. |
| 질문형 제목 | 7 | 모든 글을 질문형으로 만들지 않는다. 반전·추측이 핵심일 때만 사용한다. |
| 느낌표 포함 | 83 | 공식블로그의 행사 문법이므로 브링케어는 그대로 모방하지 않는다. |
| 숫자 포함 | 66 | 날짜·횟수·단계처럼 검증된 숫자만 사용한다. |

| 행동형 표현 포함 | 60 | 독자가 무엇을 확인하고 얻는지 제목에서 분명히 한다. |

대표 반복 계열은 `이달의 블로그` 37개, `블로그 있어요` 13개, 이벤트·챌린지 23개, 기능·업데이트 안내 13개, 네이버 메이트 6개였다. 반응이 큰 글은 새 시리즈의 시작, 다음 주인공 추측, 참여 방식이 명확한 이벤트처럼 독자의 역할이 분명했다.

브링케어에는 이를 다음처럼 번역한다.

- `현장 BEFORE → 확인 → 완료`: 증거 시리즈
- `건물주 3분 가이드`: 검색·검토 시리즈
- `퇴실 14일 전`: 입퇴실 준비 시리즈
- `이번 달 관리 기록`: 신뢰·운영 시리즈

## 4. 선택한 접근법

### 채택: 네이버 기본 기능 안에서 구현하는 브랜드 프롤로그형 홈

네이버가 제공하는 스킨·프롤로그·메뉴·대표글 기능을 사용한다. 외부 웹페이지처럼 보이게 억지로 꾸미지 않고 모바일과 PC에서 깨지지 않는 기본 구조를 우선한다.

다른 접근법은 채택하지 않는다.

- 최신 글 중심 블로그 유지: 구현은 쉽지만 회사와 서비스 탐색 문제가 남는다.
- 참고 블로그 외형 복제: 유사성은 높지만 브링케어 정체성이 약하고 저작권·유지보수 위험이 있다.

## 5. 첫 화면 정보 구조

### 브랜드 배경

- 색상: 네이비, 브링 블루, 화이트
- 문구: `건물의 일을, 한 곳에서 끝냅니다`
- 보조 문구: `원주 원룸·다가구의 입퇴실 준비, 현장 확인, 청소, 업체 조율과 결과 보고`
- 검정·초록의 네이버 공식블로그 디자인은 사용하지 않는다.

### 상단 메뉴

1. 브링케어 안내
2. 입퇴실 24H
3. 현장 기록
4. 건물주 가이드

### 중앙 콘텐츠 보드

- 대표 공지 1: 브링케어는 어떤 회사인가
- 대표 공지 2: 퇴실 14일 전부터 준비하는 24H 패키지
- 대표 공지 3: 서비스 범위와 가격
- 최근 현장 기록 3개
- 건물주 가이드 2개

### 프로필 영역

- 이름: BRING Care
- 설명: `직접 방문이 어려운 건물주를 대신해 확인하고, 분류하고, 연결하고, 결과를 보고합니다.`
- 행동: 카카오채널 상담 하나
- 전화번호·SNS·URL을 여러 줄로 반복하지 않는다.

## 6. 제목 시스템

### 공통 규칙

- 한 제목은 `대상 또는 시점 + 문제 + 얻는 답`을 담는다.
- 시리즈 접두어는 실제 연재에만 사용한다.
- 숫자는 본문 근거와 일치할 때만 쓴다.
- 한 제목에 이모지는 최대 1개이며 장식용으로 사용하지 않는다.
- 느낌표를 기본 종결부호로 쓰지 않는다.
- 지역명은 검색 의도가 지역 서비스일 때만 넣는다.

### 유형별 공식

- 검색정보: `[지역/상황] + 문제, + 먼저 확인할 기준`
- 현장사례: `[현장 BEFORE] + 보이는 문제 + 확인한 원인/다음 조치`
- 건물주고민: `[건물주 3분 가이드] + 결정 상황 + 판단 기준`
- 입퇴실: `[퇴실 14일 전] + 준비 항목 + 지연을 줄이는 순서`
- 회사공지: `[브링케어 안내] + 서비스 이름 + 포함/제외 범위`

## 7. 본문 템플릿

1. 첫 화면 약속: 대표 이미지와 제목이 같은 질문을 약속한다.
2. 구체적 장면: 독자가 실제로 겪는 한 장면을 3~5문장으로 보여준다.
3. 핵심 판단: 인용구 한 개로 통념을 바로잡는다.
4. 확인 기준: 스스로 볼 수 있는 항목을 순서대로 설명한다.
5. 증거: 실제 현장 사진 또는 공식 자료를 관련 문단 바로 뒤에 둔다.
6. 역할 구분: 브링케어 직접 역할, 외부 전문업체 작업, 건물주 결정을 분리한다.
7. 다음 행동: 글의 역할에 맞는 CTA 하나만 둔다.

본문은 제목을 제외하고 가운데 정렬한다. 의미 묶음 사이 빈 문단을 두고, 실제 네이버 인용구·구분선 컴포넌트를 사용한다. 모든 글에 같은 회사소개를 복사하지 않는다.

## 8. 이미지 시스템

- 대표 이미지: 상황과 핵심 문구가 모바일에서 즉시 보이는 한 장
- 실제 현장 사진: 2~3장 묶음 또는 비교 콜라주로 배치
- 정보 이미지: 전체 폭 대형 PPT를 연속 삽입하지 않고 관련 설명 가까이에 작은 카드로 배치
- 캡션: 사진에서 확인되는 사실만 한 문장으로 기록
- 현장사례: AI 이미지 금지
- 일반 정보·회사소개: 실사진 확보 실패 기록이 있을 때만 설명용 AI 이미지 허용
- 외부 업체 사진을 브링케어 작업 실적으로 표현하지 않는다.

## 9. 매뉴얼·템플릿 변경 범위

- `writing-bringcare-naver-blog` 콘텐츠 시스템에 시리즈·제목·프롤로그 규칙 추가
- 게시물 템플릿을 역할별 다섯 유형으로 분리
- 검증기에 다음 경고 추가:
  - 근거 없는 제목 숫자
  - 시리즈 접두어와 카테고리 불일치
  - 같은 회사소개 반복
  - CTA 두 개 이상
  - 현장사례 AI 이미지
  - 대형 정보 이미지 연속 배치
  - 첫 5문장에 독자 장면·문제·약속 부재
- 마스터 매뉴얼에 100개 분석 결과, 제목 공식, 홈 구조와 QA 체크리스트 반영

## 10. 네이버 적용 순서

1. 현재 로그인 계정이 `dpvld858`인지 확인한다.
2. 현재 스킨·레이아웃·프롤로그 설정을 기록한다.
3. 네이비·블루·화이트 스킨과 브랜드 헤더를 적용한다.
4. 프롤로그를 첫 화면으로 지정한다.
5. 메뉴 네 개와 대표 콘텐츠를 연결한다.
6. PC 공개 화면을 검수한다.
7. 모바일 공개 화면에서 제목·카드·메뉴·대표글 이동을 검수한다.
8. 문제가 있으면 즉시 저장을 중단하고 기존 설정으로 되돌릴 수 있는 재개 지점을 기록한다.

## 11. 검수 기준

- 첫 화면 10초 안에 회사, 대상 고객, 핵심 서비스 세 가지를 이해할 수 있다.
- 대표 공지 세 개가 실제 클릭된다.
- 메뉴 네 개가 올바른 카테고리로 이동한다.
- 최신 글 하나가 전체 화면을 독점하지 않는다.
- 모바일에서 가로 스크롤, 잘린 문구, 지나치게 큰 제목이 없다.
- 브링케어 색상과 실제 사진이 사용된다.
- 참고 블로그의 로고·문구·이미지·색상을 복제하지 않는다.
