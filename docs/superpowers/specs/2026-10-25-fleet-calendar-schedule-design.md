# 차량 일정표 중심 예약 UX 설계

## 목표

공용차 예약의 시작점을 별도 신청 폼이 아니라 월간 일정표로 바꾼다. 직원은 차량이 비어 있는 날짜와 기존 예약 상태를 먼저 확인하고, 날짜를 선택한 뒤 같은 화면에서 예약을 신청한다. 관리자는 같은 일정표에서 승인 대기 건을 확인하고 승인 또는 반려한다.

## 선택한 접근

### 월간 달력 + 선택 날짜 상세 패널

- 홈의 `예약 신청` 메뉴를 `차량 일정표`로 교체한다.
- 일정표 화면 상단에는 이전 달, 오늘, 다음 달 이동 기능을 둔다.
- 각 날짜 칸에는 예약 개수와 상태 점을 표시한다.
- 날짜를 누르면 하단 상세 패널에 그날의 예약 목록과 `이 날짜에 예약하기` 버튼이 열린다.
- 예약 폼은 상세 패널 안에서 단계적으로 펼쳐지며 선택 날짜가 자동 입력된다.
- PC에서는 달력과 상세 패널을 나란히, 휴대폰에서는 달력 아래에 상세 패널을 배치한다.

단순 주간 목록은 한 달의 주말과 빈 날짜를 찾기 어렵고, 달력과 별도 신청 페이지를 유지하는 방식은 사용 흐름이 다시 분리되므로 채택하지 않는다.

## 일정 표시 규칙

- 승인 완료: 네이비 바탕과 `승인` 문자 표시
- 승인 대기: 주황색 점과 `대기` 문자 표시
- 반려: 기본 달력에서는 숨기고 본인 예약 상세에서만 표시
- 내 예약: 상태와 함께 `내 일정` 배지를 표시
- 오늘: 테두리와 `오늘` 표시
- 선택 날짜: 라임색 강조
- 예약이 없는 날짜: `예약 가능`으로 안내

색상만으로 상태를 전달하지 않고 문자와 배지를 함께 사용한다.

## 예약 신청 흐름

1. 직원이 날짜를 선택한다.
2. 선택 날짜의 예약 목록과 사용 가능한 상태를 확인한다.
3. `이 날짜에 예약하기`를 누른다.
4. 시작·종료 시각, 예약 사유, 목적, 목적지를 입력한다.
5. 시작과 종료는 선택 날짜 안에서 자동 생성한다. 자정을 넘기는 예약은 종료 날짜를 별도로 선택할 수 있게 한다.
6. 기존 승인 또는 대기 예약과 시간이 겹치면 저장 전에 즉시 오류를 표시한다.
7. 저장 후 달력에 `대기` 일정이 바로 나타나고 선택 날짜 상세가 유지된다.

주말은 `주말·야간`, 평일은 사용자가 장거리 또는 외부 반출을 선택한다. 기존 데이터 구조와 승인 정책은 유지한다.

## 관리자 흐름

- 관리자 화면에도 동일한 일정표 요약을 제공한다.
- 승인 대기 일정을 누르면 신청자, 목적지, 목적, 시간대를 확인할 수 있다.
- 승인 시 다른 승인 예약과 충돌하면 막는다.
- 승인 또는 반려 후 일정표 상태가 실시간으로 갱신된다.

## 화면 구조와 시각 디자인

- 전체 배경은 옅은 회청색, 주요 표면은 흰색, 브랜드 네이비와 라임을 강조색으로 사용한다.
- 상단에는 월 제목과 이동 버튼을 한 줄로 배치한다.
- 요일 헤더는 고정된 7열 그리드로 구성한다.
- 날짜 셀은 최소 48px 터치 영역을 보장하고, 모바일에서도 가로 스크롤 없이 보이게 한다.
- 예약 상세는 둥근 카드와 명확한 시간축으로 구성한다.
- 폼 필드는 항상 보이는 레이블과 필드 가까이의 오류 메시지를 제공한다.
- 전환 애니메이션은 150~220ms 범위로 제한하고 `prefers-reduced-motion`을 존중한다.

## 컴포넌트 경계

- `FleetCalendar`: 월 이동, 날짜 그리드, 선택 상태
- `FleetDayPanel`: 선택 날짜의 일정 목록과 예약 시작 버튼
- `FleetReservationForm`: 선택 날짜를 받은 예약 입력 폼
- `fleet-calendar.ts`: 월 그리드 생성, 한국 시간 날짜 키, 날짜별 예약 그룹화
- 기존 저장소 함수와 Firebase 예약 데이터 구조는 재사용한다.

달력 계산은 순수 함수로 분리해 시간대와 월 경계 테스트가 가능하게 한다.

## 오류 및 경계 상황

- 종료가 시작보다 빠르거나 같은 경우 저장하지 않는다.
- 과거 시간 예약은 저장하지 않는다.
- 월요일 시작 달력에서 앞뒤 달 날짜도 흐리게 표시하고 선택 가능하게 한다.
- 실시간 데이터가 늦게 도착해도 선택 날짜는 유지한다.
- 중복 예약은 클라이언트 사전 검사와 기존 승인 시 검사 모두 유지한다.
- 저장 실패 시 입력값과 선택 날짜를 보존한다.

## 검증

- 월 시작 요일, 윤년, 앞뒤 달 날짜를 포함한 달력 순수 함수 테스트
- 날짜 선택 시 해당 날짜가 예약 폼 기본값으로 전달되는 UI 테스트
- 상태별 배지, 내 일정 표시, 중복 시간 차단 테스트
- 375px 휴대폰과 넓은 데스크톱 레이아웃 확인
- 키보드 탐색, 포커스 표시, 44px 이상 터치 영역 확인
- 전체 차량 앱 테스트, TypeScript 검사, ESLint, 정적 빌드, Firebase 규칙 회귀 테스트
