# 팀원 본인 업무지시 추가 설계

## 목표

일반 팀원 계정이 CRM에서 자신이 수행할 업무를 직접 정식 업무지시로 등록하게 한다. 등록된 업무는 기존 업무지시 데이터에 저장되어 대시보드·프로젝트 로드맵·운영보드의 같은 집계 흐름을 사용한다.

## 역할과 권한

- 관리자: 지금처럼 팀원에게 업무를 배정하고 업무지시를 만들거나 수정할 수 있다.
- 팀원(member): 새 업무만 만들 수 있고 담당자는 로그인한 본인으로 고정한다. 다른 사람 지정, 기존 업무의 지시 내용 수정, 업무 삭제, 완료 검수는 할 수 없다.
- 팀원은 자기 업무의 진행·결과 제출을 기존 흐름대로 한다. 완료 상태는 관리자 검수로 결정한다.
- 조회 전용(viewer)과 마케팅 전용 계정은 업무를 추가할 수 없다.

## 등록 흐름

1. 업무지시 화면에서 member에게 `내 업무 추가` 버튼을 표시한다.
2. 기존 입력 양식을 재사용한다. 제목, 프로젝트, 이유, 할 일, 완료 기준, 마감일, 예상 시간, 산출물 종류·이름·수량의 기존 검증을 적용한다. 프로젝트 연결은 선택 사항으로 하되, 선택한 프로젝트는 현재 목록에 있는 항목만 허용한다.
3. UI의 담당자는 본인으로 표시하고 바꿀 수 없게 한다. 저장 계층도 로그인 UID를 기준으로 담당자를 검증하고, `createdBy`, `updatedBy`, 생성 시각은 로그인 세션으로 채운다.
4. 새 업무는 `assigned`, 진행률 0으로 생성한다. 기존 업무 수정 경로는 관리자 전용으로 그대로 둔다.
5. 저장 후 기존 업무 조회·실시간 동기화·대시보드/TV 연동이 갱신되어야 한다.

## 보안과 검증

- Electron renderer의 버튼 표시만으로 권한을 보장하지 않는다. `RemoteClient.saveWorkOrder`에서 member의 생성만 허용하고 담당자가 세션 UID와 다르거나 기존 ID가 있으면 저장 전에 거절한다.
- Realtime Database 규칙은 member가 새 레코드를 만들 때 `assigneeUid === auth.uid`, `status === assigned`, `progress === 0`, 작성자 메타데이터와 기존 필수 필드를 만족하는지 서버에서 확인한다.
- member의 기존 업무 수정은 계속 `updateWorkOrderProgress` 경로만 사용한다. 지시 필드 잠금과 관리자 완료 검수를 변경하지 않는다.
- 규칙 테스트와 RemoteClient 동작 테스트로 member 본인 생성 허용, 타인 배정·기존 업무 수정·viewer 생성 거부, 관리자 기존 동작 유지를 확인한다.

## 화면과 피드백

- 관리자에는 기존 `새 지시`와 프로젝트 관리 동작이 그대로 보인다.
- member에게는 본인 업무를 등록하는 버튼과 담당자 고정 안내를 보여 준다.
- 서버 저장 거절이나 권한 변경이 발생하면 기존 오류·토스트 흐름을 사용하며, 실패한 업무를 저장된 것처럼 목록에 추가하지 않는다.

## 범위 밖

- 팀원이 다른 팀원에게 업무를 배정하는 기능
- 관리자 승인 대기함 또는 별도 업무 제안함
- 업무지시의 관리자 검수 정책·상태 체계 변경
- 사용자별 임의 필드·새 업무 스키마
