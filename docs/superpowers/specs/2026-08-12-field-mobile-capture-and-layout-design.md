# BRING FIELD 모바일 촬영·레이아웃 개선 설계

## 목표

현장 직원이 같은 촬영 구역에 사진을 계속 추가하고 휴대전화 사진첩에서도 여러 장을 선택할 수 있게 한다. 상단, 건물주 전달사항, 단계 이동 영역은 화면을 과도하게 가리지 않도록 일반 문서 흐름으로 바꾸며 제공된 Bring Care 로고를 적용한다.

## 촬영 흐름

- 사진 구역마다 `카메라로 촬영`과 `사진첩에서 추가`를 분리한다.
- 카메라는 후면 카메라를 여는 기존 `capture="environment"` 입력을 유지한다.
- 사진첩 입력은 `accept="image/*"`, `multiple`이며 `capture` 속성을 두지 않는다.
- 선택된 사진은 선택 순서대로 각각 고유 mediaId를 발급받아 기존 구역 자료 뒤에 누적 저장한다.
- 영상 구역도 `영상 촬영`과 `사진첩에서 영상 추가`를 제공하되 메타데이터 검사 흐름은 기존 로직을 유지한다.
- 교체 버튼은 기존 자료 한 건을 바꾸는 동작으로 유지하고 추가 버튼과 혼동되지 않게 한다.

## 모바일 레이아웃

- 상단 계정·Drive·로그아웃 바는 sticky를 제거해 페이지와 함께 위로 스크롤된다.
- 건물주 전달사항도 sticky를 제거해 작성 위치에 머문다.
- 단계 이동 영역은 fixed를 제거하고 카드 아래 일반 흐름에 둔다.
- 모바일 하단 주 메뉴는 접근성을 위해 유지하되 높이를 줄이고 버튼 터치 영역은 최소 44px로 유지한다.
- 불필요해진 큰 하단 여백과 scroll padding을 줄인다.

## 브랜딩과 배포

- 제공된 Bring Care 로고 이미지를 흰 여백 없이 잘라 정적 자산으로 저장한다.
- 사이드바와 모바일 상단에 같은 로고를 비율 왜곡 없이 표시한다.
- 기존 Firebase RTDB와 인증·Drive 저장 구조는 변경하지 않는다.
- 테스트와 모바일 빌드 후 기존 Firebase 프로젝트 `bring-fm` Hosting에 배포한다.

## 검증

- 사진첩 입력에 `multiple`이 있고 `capture`가 없는지 검사한다.
- 다중 사진 선택 시 모든 파일이 누적 enqueue되는지 검사한다.
- CSS에 요청 대상 sticky/fixed 규칙이 남지 않는지 검사한다.
- 로고 접근성 이름과 정적 자산 존재 여부를 검사한다.
- 현장앱 전체 테스트, 타입 검사, 빌드, 배포 후 운영 URL 응답을 확인한다.
