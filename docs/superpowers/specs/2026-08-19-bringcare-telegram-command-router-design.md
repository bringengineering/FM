# 브링케어 텔레그램 규칙형 업무 리모컨 설계

## 목적

OpenAI API나 별도 유료 AI 서비스를 사용하지 않고, 대표자가 텔레그램 개인 채팅에서 자연스러운 한국어 문장으로 브링케어 네이버 블로그 업무를 조회·요청·승인할 수 있게 한다.

기존 `승인`·`취소` 발행 흐름은 유지한다. 이번 기능은 그 위에 조회, 수정 요청, 도움말을 추가하는 확장이다.

## 범위

지원 업무는 브링케어 네이버 블로그에 한정한다.

- 현재 글 상태 조회
- 승인 대기 글 조회
- 최근 발행 글과 URL 조회
- 다음 콘텐츠 준비 예정 시각 조회
- 오늘 성과 조회
- 최근 오류와 필요한 조치 조회
- 제목 수정 요청 기록
- 본문 수정 요청 기록
- 발행 승인
- 취소 또는 보류
- 도움말과 인사

새로운 글의 자유로운 기획·작성, 긴 대화 추론, 일반 상식 질의응답은 이 리모컨의 책임이 아니다. 그런 작업은 기존 Codex 자동화가 담당한다.

## 권장 구조

### 1. 메시지 수집기

기존 Telegram Bot API `getUpdates` 흐름을 재사용한다. 등록된 대표자 개인 `chat_id`에서 온 새 텍스트만 처리하고, 마지막 처리 `update_id`를 저장해 같은 메시지를 두 번 실행하지 않는다.

### 2. 규칙형 명령 라우터

문장을 공백·문장부호·존댓말 차이를 정규화한 뒤, 명확한 규칙으로 하나의 의도에만 분류한다.

의도 우선순위는 다음과 같다.

1. 승인·취소처럼 상태를 바꾸는 명령
2. 제목·본문 수정 요청
3. 상태·성과·오류·링크 조회
4. 인사·도움말
5. 알 수 없음

한 문장이 두 개 이상의 변경 업무와 동시에 일치하면 실행하지 않고 한 번에 한 요청만 보내도록 안내한다.

### 3. 조회 서비스

조회 명령은 기존 원장을 읽어 즉시 텔레그램으로 답한다.

- 현재 글 상태·승인 대기: 발행 승인 상태 파일과 backlog
- 최근 발행 링크: performance ledger 또는 발행 완료 원장
- 다음 제작 시각: 자동화 원장의 마지막 준비 시각과 3시간 주기
- 오늘 성과: 확인 가능한 실제 값만 표시하고 미확인 값은 `NA`
- 오류 상태: `blog/automation/alerts.md`의 최신 미해결 항목

파일이 없거나 값이 없으면 0으로 추정하지 않고 “아직 확인된 기록이 없습니다”라고 답한다.

### 4. 수정 요청 저장소

`제목을 …로 바꿔줘`, `본문에서 …를 수정해줘` 같은 요청은 즉시 공개 글을 바꾸지 않는다. 구조화된 요청 원장에 다음 항목을 저장한다.

- 요청 ID
- Telegram update ID
- 요청 시각
- 대상 post_id
- 요청 종류: `title` 또는 `body`
- 사용자가 보낸 수정 내용
- 상태: `requested`, `applied`, `cancelled`

대상 글이 하나로 특정되지 않으면 현재 승인 대기 글을 대상으로 한다. 승인 대기 글도 없으면 저장하지 않고 대상을 알려 달라고 응답한다.

### 5. 승인과 실행

조회는 승인 없이 즉시 수행한다. 외부 상태를 바꾸는 동작은 두 단계로 처리한다.

1. `올려줘`, `발행해`, `진행해`를 받으면 대상·제목·동작을 요약하고 10분짜리 승인 대기를 만든다.
2. 같은 대표자 채팅에서 정확한 `승인`을 받으면 기존 발행 자동화가 선점 후 검증하고 실행한다.

`취소`, `보류`는 현재 승인 대기를 취소한다. 만료되었거나 승인 대상이 없으면 아무 작업도 실행하지 않는다.

공개 글 수정도 같은 원칙을 적용한다. 수정 요청 저장 후 적용 내용을 보여 주고 별도의 `승인`이 있어야 공개 상태를 바꿀 수 있다.

### 6. 응답 형식

응답은 짧고 행동 중심으로 고정한다.

- 상태: 제목, 현재 단계, 다음 행동
- 링크: 최신 순으로 제목과 공개 URL
- 오류: 원인, 사용자가 할 일, 재개 지점
- 알 수 없음: “이 문장은 아직 지원하지 않습니다”와 사용 가능한 예시 4~6개

토큰, 비밀번호, 쿠키, 환경변수 값은 응답·로그·수정 요청 원장에 넣지 않는다.

## 대표 표현 매핑

| 의도 | 예시 |
|---|---|
| 현재 상태 | `어디까지 됐어?`, `지금 글 상태 알려줘`, `작성 중인 글 있어?` |
| 승인 대기 | `승인 기다리는 글 보여줘`, `올릴 글 뭐야?` |
| 최근 발행 | `최근에 뭐 올렸어?`, `블로그 링크 줘`, `마지막 글 보여줘` |
| 다음 시각 | `다음 글 몇 시야?`, `언제 또 만들어?` |
| 오늘 성과 | `오늘 성과 알려줘`, `오늘 조회수 어때?` |
| 오류 | `뭐가 문제야?`, `오류 상태 알려줘`, `막힌 거 있어?` |
| 제목 수정 | `제목을 가을철 원룸 관리로 바꿔줘` |
| 본문 수정 | `본문에서 회사 소개를 더 짧게 수정해줘` |
| 발행 준비 | `올려줘`, `발행해`, `진행해` |
| 최종 승인 | `승인` |
| 취소 | `취소`, `보류` |
| 도움말 | `안녕`, `뭐 할 수 있어?`, `도움말` |

## 오류·안전 처리

- 허용되지 않은 chat ID: 응답하지 않고 기록만 남긴다.
- 중복 update ID: 무시한다.
- 모호한 변경 요청: 실행하지 않고 한 가지 요청으로 다시 보내도록 안내한다.
- 대상 글 없음: 요청을 저장하거나 승인하지 않는다.
- 승인 만료: 실행하지 않고 새 승인 요청을 요구한다.
- 원장 파싱 실패: 원본을 덮어쓰지 않고 오류 알림을 보낸다.
- Telegram 네트워크 오류: 다음 폴링에서 재시도하되 이미 처리한 명령은 중복 실행하지 않는다.
- 네이버 로그인·CAPTCHA·편집기 변경: 기존 차단 규칙을 그대로 적용한다.

## 실행 방식

대화를 방해하는 Codex 1분 heartbeat는 사용하지 않는다. 무료 리모컨 감시는 Windows에서 실행되는 경량 폴러가 담당하고, Codex의 블로그 콘텐츠 자동화는 3시간 주기를 유지한다.

폴러가 조회·수정 요청 기록·승인 상태 변경을 처리한다. 실제 원고 생성과 네이버 브라우저 발행은 기존 Codex 자동화가 담당한다. 따라서 PC가 켜져 있고 폴러가 실행 중이어야 텔레그램 명령이 즉시 반영된다.

## 테스트 기준

- 대표 표현과 변형을 의도별로 정확히 분류한다.
- `승인`과 일반 문장 속 “승인”을 구분한다.
- 두 변경 의도가 섞인 문장은 실행하지 않는다.
- 허용 chat ID 외 메시지를 무시한다.
- update ID를 재처리하지 않는다.
- 조회 데이터가 없을 때 값을 만들지 않는다.
- 수정 요청은 공개 글을 즉시 바꾸지 않고 원장에만 저장한다.
- 10분을 넘긴 승인은 실행되지 않는다.
- 응답과 로그에 토큰 등 민감정보가 포함되지 않는다.
- 기존 Telegram 승인 테스트와 블로그 발행 흐름이 모두 통과한다.

## 완료 조건

대표자가 텔레그램에서 지원 문장을 보내면 1분 이내에 비용 없는 규칙형 응답을 받고, 조회·수정 요청·발행 승인·취소가 중복 없이 처리된다. 지원하지 않는 문장은 추측 실행되지 않으며 도움말로 안내된다. Codex 대화는 1분마다 깨지지 않는다.
