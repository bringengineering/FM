# BRING CRM 운영 분석 내부 통합 설계

## 목표

별도 창으로 구현된 운영 인텔리전스를 BRING CRM의 정식 내부 업무 페이지로 전환한다. 사용자는 고객·건물·작업관리와 같은 왼쪽 메뉴에서 `운영 분석`을 선택하고, CRM 중앙 본문에서 운영 기록을 조회·등록·수정하며 병목과 개선 후보를 함께 관리한다.

## 채택 방식

기존 CRM의 `data-view` 탐색·렌더링 체계에 `operationsIntelligence` 화면을 추가한다. 별도 BrowserWindow를 CRM 본문에 억지로 삽입하는 iframe 방식은 사용하지 않는다. 기존 분석 코어와 Firebase 저장 경로는 재사용하되, 화면 렌더링과 이벤트 처리는 CRM 내부 모듈로 연결한다.

이 방식은 로그인·권한·검색·알림·화면 전환을 기존 CRM과 일관되게 유지하며, 별도 창에서 생기는 이중 화면과 사용 흐름 단절을 없앤다.

## 화면 구조

- 왼쪽 메뉴의 `작업관리` 바로 아래에 `운영 분석`을 배치한다.
- 메뉴는 일반 `data-view="operationsIntelligence"` 항목으로 동작하며 `별도 창` 표시는 제거한다.
- 중앙 본문 상단에는 `운영 분석` 제목, 분석 기간, `운영 등록` 버튼을 둔다.
- 내부 탭은 `운영 현황`, `병목 분석`, `개선 후보` 세 가지를 유지한다.
- CRM의 공통 사이드바, 상단 검색, 로그인 사용자 표시, 업데이트 UI는 그대로 유지한다.
- 화면을 떠났다가 돌아와도 선택한 분석 기간과 내부 탭을 현재 실행 세션 동안 유지한다.

## 데이터와 저장

- 저장 위치는 기존 `crmCompany/operationsIntelligence/operations`를 그대로 사용한다.
- 고객·건물·사용자 목록은 현재 CRM에 로드된 데이터를 읽기 전용 참조로 사용한다.
- 운영 기록의 생성·수정은 기존 메인 프로세스 검증과 낙관적 동시성 제어를 거친다.
- 기존 고객, 건물, 작업관리, 상담, 계약 데이터는 운영 기록 저장으로 변경하지 않는다.
- viewer는 분석 조회만 가능하고 member/admin은 운영 기록을 등록·수정할 수 있다.

## 코드 경계

- `operations-intelligence-core.js`는 정규화와 지표·병목·후보 계산을 계속 담당한다.
- 새 내부 UI 모듈은 CRM 상태를 받아 HTML을 만들고, 폼 입력을 저장 요청 형태로 변환한다.
- `app.js`는 화면 선택, 데이터 로딩, 이벤트 연결만 담당하며 분석 계산을 중복 구현하지 않는다.
- 기존 별도 창 파일은 새 내부 화면이 검증된 후 런타임 진입점에서 제거한다. 분석 코어와 스타일 중 재사용 가능한 부분은 유지한다.

## 오류 처리

- 최초 조회 중에는 로딩 상태를 표시한다.
- 서버 조회 실패 시 기존 CRM 전체 화면을 막지 않고 운영 분석 본문에 재시도 안내를 표시한다.
- 저장 실패나 버전 충돌 시 로컬 목록을 성공한 것처럼 갱신하지 않고 오류 내용을 표시한다.
- 데이터가 없을 때, 표본이 부족할 때, 권한이 없어 수정할 수 없을 때를 각각 구분해 안내한다.

## 테스트 기준

- 왼쪽 메뉴에서 `운영 분석`을 선택하면 별도 창 호출 없이 CRM 본문이 바뀐다.
- `작업관리` 다음에 `운영 분석` 메뉴가 표시된다.
- 세 내부 탭과 기간 필터가 같은 CRM 화면 안에서 동작한다.
- member/admin은 등록·수정할 수 있고 viewer에게는 수정 버튼이 노출되지 않는다.
- 저장 후 다시 조회했을 때 서버 기록이 유지된다.
- 버전 충돌과 서버 오류 시 성공 표시나 낙관적 로컬 변경이 발생하지 않는다.
- 기존 고객·건물·작업관리·상담·계약 테스트와 저장 결과가 동일하다.
- 별도 운영 인텔리전스 BrowserWindow가 더 이상 사용자 동선에서 열리지 않는다.

## 범위 제외

- 운영 기록과 기존 작업관리의 자동 병합 또는 양방향 동기화
- AI 원인 진단이나 자동 업무 배정
- 첨부파일 원본 업로드
- 운영 브랜치 병합 및 실사용자 자동 업데이트 배포
