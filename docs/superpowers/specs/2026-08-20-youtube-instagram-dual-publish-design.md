# YouTube·Instagram 동시 게시 설계

## 목적

텔레그램에서 승인된 완성 영상을 YouTube Shorts와 Instagram Reels에 한 번의 명령으로 공개한다. 한 플랫폼의 실패가 다른 플랫폼의 성공을 되돌리지 않으며, 실패한 플랫폼만 안전하게 재시도한다.

## 검토한 접근법

1. 브라우저 자동화만 사용: 초기 구현은 빠르지만 UI 변경, 로그인 만료, 팝업에 취약하다.
2. Meta·YouTube 공식 API만 사용: 안정적이지만 기존 텔레그램 승인 흐름과 별도 운영 화면이 생긴다.
3. 기존 Marketing OS를 지휘 계층으로 두고 공식 API 업로더를 분리: 승인·기록·재시도는 공통으로 관리하면서 플랫폼별 오류를 격리할 수 있다.

3번을 채택한다.

## 사용자 흐름

1. 영상 제작과 QC가 완료되면 텔레그램에 미리보기와 게시 선택지를 보낸다.
2. 기본 선택은 `YouTube + Instagram 동시 공개`다.
3. 사용자는 필요할 때 `YouTube만`, `Instagram만`, `보류`를 선택할 수 있다.
4. 승인 후 각 플랫폼 업로더가 독립 실행된다.
5. 성공한 플랫폼의 게시물 ID와 URL을 즉시 저장한다.
6. 일부 실패 시 성공 결과는 유지하고 실패 플랫폼만 재시도 대기열에 넣는다.

## 구성요소

### 공통 게시 요청

- 영상 절대 경로
- 공통 제목과 설명 원문
- 플랫폼별 제목·본문·해시태그
- 공개 승인 시각과 승인자
- 파일 SHA-256 지문
- 멱등성 키

### Instagram 업로더

- Windows 사용자 환경변수에서 `META_PAGE_ACCESS_TOKEN`, `META_PAGE_ID`, `INSTAGRAM_BUSINESS_ACCOUNT_ID`를 읽는다.
- Graph API의 미디어 컨테이너 생성, 처리 상태 확인, 게시 단계를 분리한다.
- 토큰이나 비밀값은 로그·예외·텔레그램 메시지에 출력하지 않는다.
- 같은 멱등성 키로 이미 게시된 영상은 다시 공개하지 않는다.

### YouTube 업로더

- 기존 `automation/youtube_uploader.py`를 유지한다.
- 공통 게시 요청과 결과 형식에 맞추는 얇은 어댑터만 둔다.

### 게시 오케스트레이터

- 두 업로더를 독립 실행한다.
- 상태는 `pending`, `publishing`, `published`, `failed_retryable`, `failed_terminal`로 기록한다.
- 플랫폼별 게시물 ID, URL, 시도 횟수, 마지막 오류를 분리 저장한다.
- 네트워크·처리 지연은 지수 백오프로 재시도하고 인증·파일 규격 오류는 즉시 중단한다.

## 게시 전 품질 게이트

- 파일 존재와 SHA-256 일치
- 세로형 9:16 권장 규격
- 플랫폼 허용 길이와 파일 크기
- 음량·무음 구간 검사 결과 통과
- 자막 안전영역과 잘림 검사 결과 통과
- 플랫폼별 문구 길이와 금지 표현 검사
- 공개 승인 기록 존재

QC 실패 시 어느 플랫폼에도 공개하지 않는다.

## Instagram 미디어 전달

Instagram Graph API는 공개 HTTPS 영상 URL을 요구하므로 업로드 시점에만 접근 가능한 임시 미디어 URL을 사용한다. URL은 추측하기 어려운 일회성 경로로 만들고, 게시 완료 또는 만료 후 비활성화한다. 장기 공개 저장소 URL은 사용하지 않는다.

## 실패와 복구

- 컨테이너 처리 중: 제한 시간까지 폴링한다.
- 일시적 Meta 오류·429·5xx: 백오프 후 Instagram만 재시도한다.
- 토큰 만료·권한 부족: 자동 게시를 멈추고 텔레그램에 재인증 요청을 보낸다.
- 중복 실행: 저장된 멱등성 키와 플랫폼 게시물 ID를 확인해 건너뛴다.
- YouTube 성공·Instagram 실패: YouTube는 그대로 두고 Instagram만 재개한다.

## 테스트

- 환경변수 누락 시 비밀값 없는 명확한 오류
- QC 미통과 시 API 호출 차단
- 승인 없는 공개 차단
- 컨테이너 생성→상태 확인→게시의 정상 경로
- 처리 지연과 재시도 가능 오류
- 인증 오류의 즉시 중단
- 부분 성공 후 실패 플랫폼만 재시도
- 동일 멱등성 키의 중복 게시 방지
- 토큰이 로그에 포함되지 않는지 검사

실제 공개 테스트는 별도 사용자 승인 후 한 편으로 수행한다.

## 완료 기준

- 텔레그램 한 번의 승인으로 두 플랫폼 게시가 시작된다.
- 두 플랫폼 결과가 독립 저장된다.
- 부분 실패가 기존 성공 게시물을 훼손하지 않는다.
- 실패 지점부터 재개할 수 있다.
- 토큰과 비밀값이 저장소·로그·메시지에 노출되지 않는다.
- Instagram 비공개 읽기 검증과 공개 전 dry-run 검증이 통과한다.
