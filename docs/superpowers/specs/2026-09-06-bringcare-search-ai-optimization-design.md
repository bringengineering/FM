# BRING CARE 검색·AI 노출 개선안

## 결론

현재 최우선 문제는 세 서비스 페이지가 모두 공개 주소에서 `404`를 반환한다는 점이다. 검색엔진 최적화 파일도 공개되어 있지 않다. 따라서 콘텐츠를 늘리기 전에 기존 랜딩페이지를 선별 복구하고, 검색엔진이 읽을 수 있는 기본 구조를 만든 뒤 네이버 등록과 재측정을 진행한다.

점수는 절대적인 검색 순위가 아니라 2026-09-06 현재의 **기술 준비 상태**를 나타낸다. 실제 검색 노출과 AI 인용 성과는 배포 후 색인·검색 데이터를 통해 별도로 검증한다.

## 현재 진단

| 영역 | 현재 상태 | 판정 | 근거 |
|---|---|---:|---|
| SEO | 서비스 페이지 접근 불가 | 0/100, 차단 | `/building-care`, `/stair-cleaning`, `/move-in-cleaning`이 실제 공개 주소에서 404 |
| AEO | 답변형 콘텐츠를 검색봇이 읽을 수 없음 | 0/100, 차단 | FAQ 구조화 데이터와 공개 페이지가 없음 |
| GEO | AI 검색이 인용할 공개 원문이 없음 | 0/100, 차단 | 서비스 범위·가격·지역·근거가 소스에는 있으나 공개 URL이 404 |
| LLMO | 브랜드·서비스 엔터티 설명 미공개 | 0/100, 차단 | `llms.txt`가 404이고 회사·서비스 관계를 설명하는 기계 판독 문서가 없음 |
| NEO | 네이버가 수집할 정상 URL과 사이트맵이 없음 | 0/100, 차단 | `robots.txt`, `sitemap.xml`이 모두 404 |

### 복구 후 활용 가능한 기존 자산

- 서비스별 제목, 설명, canonical 메타데이터가 소스에 존재한다.
- 건물관리, 계단·공용부 청소, 입주·이사청소의 범위·가격·프로세스·상담 CTA가 이미 작성돼 있다.
- 실제 현장 사진, 관리기록, 기업 인증과 수상 이력, 이지부동산중개법인 협력 내용이 신뢰 근거로 준비돼 있다.
- 세 서비스 간 내부 연결 카드가 있어 토픽 구조를 만들 수 있다.

## 적용 방향

### 1. 긴급 복구

- 현재 작업 브랜치 전체를 배포하지 않는다.
- 정상 빌드된 세 서비스 디렉터리와 그 의존 자산만 운영 배포 기준과 대조한다.
- `/building-care`, `/stair-cleaning`, `/move-in-cleaning`에서 HTTP 200, 제목, 본문, 상담 버튼을 확인한다.
- 다른 운영 페이지와 기존 함수·CRM·광고 설정은 변경하지 않는다.

### 2. SEO·NEO 기반

- `robots.txt`: 공개 서비스는 허용하고 CRM·현장 내부 경로는 색인에서 제외한다.
- `sitemap.xml`: canonical 서비스 URL과 변경일만 포함한다.
- 각 페이지의 title·description·canonical·Open Graph 이미지를 서비스별로 맞춘다.
- 네이버 서치어드바이저에서 소유 확인 후 사이트맵과 주요 URL 수집을 요청한다.

### 3. AEO·GEO·LLMO 기반

- 각 서비스에 실제 고객 질문 중심 FAQ를 추가한다. 가격·방문 주기·작업 범위·지역·추가비용 조건을 명확히 쓴다.
- `LocalBusiness`, `Service`, `FAQPage`, `BreadcrumbList`, `Organization` JSON-LD를 사실 범위 안에서 제공한다.
- 회사명, 브랜드명, 제공 지역, 세 서비스의 관계를 일관되게 표기한다.
- `llms.txt`에는 대표 URL과 검증 가능한 서비스 요약만 기록한다. 수상·인증을 서비스 성능 보증처럼 과장하지 않는다.

### 4. 콘텐츠 구조

- 중심 페이지: 건물관리·입퇴실 통합관리.
- 서비스 페이지: 계단·공용부 정기청소, 입주·이사청소.
- 후속 설명 콘텐츠: 원주 원룸 공실 관리, 입퇴실 체크리스트, 공용부 청소 범위, 입주청소 가격 결정 요인.
- 모든 설명 콘텐츠는 관련 서비스 페이지와 상담 화면으로 연결한다.

## 배포 순서

1. 현재 Firebase Hosting 배포 내역과 운영 브랜치의 차이를 확인한다.
2. 세 페이지 복구 테스트를 먼저 만든다.
3. robots·sitemap·JSON-LD·FAQ·llms 테스트를 추가한다.
4. 최소 변경분을 구현하고 로컬 빌드 및 링크 검사를 수행한다.
5. Hosting만 배포하고 세 서비스와 검색 파일의 응답을 재확인한다.
6. 네이버 서치어드바이저 등록 상태를 확인한다. 계정 작업 전 현재 로그인 계정을 확인한다.
7. 2주 뒤 색인 수, 노출, 클릭, 검색어와 AI 인용 여부를 같은 기준으로 재측정한다.

## 검증 기준

- 세 서비스 URL과 `robots.txt`, `sitemap.xml`, `llms.txt`가 HTTP 200을 반환한다.
- 페이지마다 고유 title·description·canonical·대표 이미지가 있다.
- 구조화 데이터가 실제 화면 문구와 모순되지 않는다.
- 사이트맵에 내부 CRM·현장 경로가 포함되지 않는다.
- 네이버 광고의 UTM·예산·입찰가와 CRM 수집 함수는 이번 작업으로 바뀌지 않는다.
- 2주 후 점수는 느낌이 아니라 Search Advisor와 광고·CRM의 실제 수치로 다시 계산한다.

## 제외 범위

- 자동 광고비 또는 입찰가 변경
- 검색 반영이나 AI 인용을 보장하는 표현
