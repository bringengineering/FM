# 작업 완료-운영 분석 자동 연동 설계

## 목표

작업관리에서 작업을 `완료`로 변경하면 운영 분석 기록을 자동으로 한 건 생성해 중복 입력과 분석 누락을 줄인다. 작업 완료 처리는 운영 분석 저장 장애와 분리해 현장 업무 기록이 유실되지 않게 한다.

## 범위

- 단건 작업인 `serviceRecords`를 운영 분석의 `operations`와 연결한다.
- 최초 완료 시 운영 분석 기록을 자동 생성한다.
- 완료된 작업의 기본 정보가 바뀌면 연결된 운영 기록의 시스템 관리 필드만 동기화한다.
- 운영 분석에서 사용자가 입력한 판단·측정 필드는 자동 동기화가 덮어쓰지 않는다.
- 정기 계약인 `serviceContracts` 자체는 분석 기록으로 만들지 않는다. 계약에서 발생한 실제 작업 기록이 완료될 때만 생성한다.

## 선택한 접근

### 완료 시 자동 생성 + 연결 키 기반 동기화

각 운영 기록에 원본 작업 ID를 나타내는 `sourceWorkRecordId`를 저장한다. 같은 원본 ID를 가진 운영 기록은 하나만 허용한다. 작업 저장 로직은 상태가 완료인지 확인한 뒤 기존 연결 기록을 조회하여 없으면 생성하고, 있으면 시스템 관리 필드만 갱신한다.

수동 생성은 누락 가능성이 크고, 작업 객체를 분석 화면에서 직접 사용하는 방식은 두 기능의 데이터 수명과 권한을 과도하게 결합하므로 채택하지 않는다.

## 데이터 매핑

| 작업관리 원본 | 운영 분석 대상 | 처리 |
|---|---|---|
| `id` | `sourceWorkRecordId` | 중복 방지용 고유 연결 키 |
| `title` | `title` | 자동 생성·동기화 |
| `buildingId` | `buildingId` | 자동 생성·동기화 |
| `serviceType` | `category`, `subcategory` | 기존 분류표에 따라 변환 |
| `summary` | `description`, `outcome` | 빈 값은 빈 문자열로 정규화 |
| `completedAt` | `completedAt` | ISO 형식으로 저장 |
| `owner` | `assigneeId` | 자동 생성·동기화 |
| `vendorName` | `sourceVendorName` | 원본 업체명을 별도 필드로 보존 |
| `amount` | `sourceAmount` | 원본 작업 금액을 숫자로 보존 |

다음 필드는 운영 분석 사용자가 직접 보완하며 자동 동기화가 변경하지 않는다: `directMinutes`, `interventionTypes`, `siteVisit`, `remoteResolved`, `exceptionOccurred`, `exceptionNote`, `firstTimeRight`, `revisitRequired`, `reworkRequired`, `repeatability`, `managerIntervened`, `managerMinutes` 및 각종 변경 횟수.

## 처리 흐름

1. 사용자가 작업관리에서 작업을 저장한다.
2. 기존 작업 저장을 먼저 완료한다.
3. 저장 결과의 상태가 `completed`이면 `sourceWorkRecordId`로 운영 기록을 조회한다.
4. 연결 기록이 없으면 완료 상태의 운영 기록을 생성한다.
5. 연결 기록이 있으면 시스템 관리 필드만 병합한다.
6. 연동 성공 여부를 작업관리 화면에 표시한다.

완료 이후 작업 상태가 다른 값으로 되돌아가더라도 운영 분석 기록은 자동 삭제하지 않는다. 이력 보존을 우선하며, 필요하면 운영 분석 화면에서 별도로 상태를 관리한다.

## 오류 처리와 재시도

- 운영 분석 연동 실패가 작업 저장을 롤백하지 않는다.
- 실패한 작업에는 `운영 분석 연동 필요` 상태를 표시한다.
- 사용자는 작업 상세 화면에서 `연동 재시도`를 실행할 수 있다.
- 재시도도 동일한 `sourceWorkRecordId`를 사용하므로 반복 실행해도 중복 기록이 생기지 않는다.
- 동시 저장은 기존 운영 분석의 ETag 및 버전 검증 방식을 유지한다. 충돌 시 최신 데이터를 다시 읽어 시스템 관리 필드만 재병합한다.

## 화면 변경

- 완료된 작업 카드 또는 상세 화면에 연동 상태를 `연동 완료`, `연동 필요`로 표시한다.
- `연동 필요`일 때만 재시도 버튼을 노출한다.
- 운영 분석 기록 상세에는 `작업관리에서 생성됨`과 원본 작업 제목을 표시해 출처를 확인할 수 있게 한다.
- 새로운 독립 메뉴나 별도 창은 만들지 않는다.

## 권한과 저장 경계

- 기존 작업 저장 권한과 운영 분석 쓰기 권한을 모두 가진 사용자만 자동 연동 저장을 수행한다.
- 운영 분석이 읽기 전용인 사용자는 작업을 완료할 수 있더라도 분석 연동 실패 상태를 확인할 수 있다.
- 저장은 기존 Electron preload/main의 허용된 IPC와 Firebase 경로를 사용한다. 렌더러에서 임의 경로를 직접 쓰지 않는다.

## 테스트

- 미완료 작업 저장은 운영 기록을 생성하지 않는다.
- 최초 완료는 연결 키가 포함된 운영 기록 한 건을 생성한다.
- 같은 작업을 다시 저장하거나 재시도해도 중복 생성되지 않는다.
- 작업 기본 정보 수정은 시스템 관리 필드만 갱신한다.
- 사용자가 보완한 분석 필드는 동기화 후에도 유지된다.
- 연동 실패 시 작업 완료는 유지되고 재시도 상태가 표시된다.
- 재시도 성공 시 상태가 `연동 완료`로 바뀐다.
- 읽기 전용 사용자의 권한 경계를 유지한다.
- 기존 작업관리·운영 분석·Firebase 규칙 테스트가 모두 통과한다.

## 제외 범위

- 정기 계약만으로 운영 분석 기록을 미리 생성하는 기능
- 과거 완료 작업 전체의 일괄 소급 변환
- 비용·수익 회계 기능의 재설계
- AI 기반 자동 평가 또는 개선안 자동 실행
- 운영 분석 기록의 자동 삭제

## 완료 기준

완료 작업 한 건이 운영 분석 기록 한 건과 안정적으로 연결되고, 반복 저장·재시도·동시 수정에도 중복이나 사용자 입력 손실이 없으며, 장애 시 작업 완료 기록이 보존되면 완료로 판단한다.
