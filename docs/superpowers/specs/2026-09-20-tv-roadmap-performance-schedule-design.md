# BRING TV 로드맵·성과·시간표 통합 설계

## 1. 목표

BRING CRM의 기존 프로젝트 로드맵과 내부 일정 데이터를 회사 TV 운영보드에 안전하게 투영한다. TV에서는 담당자별 프로젝트 기간과 진행률, 회사 전체 진행률, 위험 프로젝트, 다음 마감, 오늘·이번 주 일정을 큰 글자와 단순한 시각 구조로 자동 순환한다.

이 기능은 CRM의 원본 데이터를 별도로 복제하거나 수정하지 않는다. TV는 조회 전용 게시 자료만 표시하며, 고객 연락처·주소·메모·출입정보 등 개인정보는 보내지 않는다.

Google 캘린더는 연결하지 않는다. 일정의 단일 기준은 CRM의 `serviceRecords`와 업무지시 데이터다.

## 2. 확정 화면 구성

TV는 아래 장면을 설정된 시간에 따라 자동 순환한다. 기존 이전·다음 버튼과 자동 순환, 15초 데이터 확인, 웹 앱 자동 업데이트 방식은 유지한다.

1. **프로젝트 로드맵**
   - 세로축: 담당자
   - 가로축: 현재 주를 중심으로 한 8주
   - 막대 위치·길이: 프로젝트 또는 연결 업무의 시작일~종료일
   - 막대 내부 채움: CRM에 입력된 진행률 0~100%
   - 막대 문구: 프로젝트명과 정확한 진행률
   - 색상: 정상은 파랑, 기한 위험은 주황, 완료는 초록
   - 담당자가 많으면 3명씩 자동 페이지 전환
2. **프로젝트별 진행률 순위**
   - 활성 프로젝트를 진행률 높은 순으로 표시
   - 프로젝트명, 진행률, 담당자, 남은 업무 수를 표시
3. **주간 완료 실적**
   - 최근 5주간 검수 완료 처리된 업무 건수를 막대그래프로 표시
   - 사실로 확인할 수 없는 과거 진행률은 역산하지 않는다.
4. **프로젝트 건강도**
   - 정상, 확인 필요, 기한 위험, 완료 프로젝트 수를 구분
5. **이번 주 핵심 결과물**
   - 마감이 가까운 업무 최대 6건을 D-day 순으로 표시
6. **오늘 시간표**
   - 시간, 일정명, 담당자, 상태를 표시
7. **이번 주 일정**
   - 월~일 기준으로 일정 수와 핵심 일정 최대 8건을 표시
8. **회사 공지**
   - 기존 공지 장면을 유지

## 3. 로드맵 우측 성과 패널

로드맵 장면의 오른쪽 22~25%를 성과 요약에 사용한다.

- **전체 프로젝트 진행률**: 활성 프로젝트의 표시 진행률 단순 평균. 소수점 없이 반올림한다.
- **프로젝트 상태**: 정상·확인 필요·기한 위험·완료 개수.
- **다가오는 마감**: 가장 가까운 미완료 업무 3건의 D-day, 업무명, 프로젝트명, 담당자.
- **자료 기준 시각**: 마지막 게시 성공 시각과 게시 버전.

프로젝트에 연결된 업무가 있으면 CRM 로드맵과 동일하게 연결 업무들의 입력 진행률 평균을 사용한다. 연결 업무가 하나도 없으면 프로젝트 자체의 수동 진행률을 사용한다. 진행률을 완료 건수로 추정하지 않는다.

## 4. 프로젝트 상태 판정

- **완료**: 프로젝트 상태가 완료이거나 연결 업무가 모두 `done`.
- **기한 위험**: 미완료 업무 중 마감일이 지났거나 프로젝트 종료일이 지났음.
- **확인 필요**: 7일 이내 마감 업무가 있거나 날짜가 없는 미완료 업무가 있음.
- **정상**: 위 조건에 해당하지 않는 활성 프로젝트.

색상만으로 상태를 전달하지 않는다. 색상과 함께 `정상`, `확인`, `위험`, `완료` 문구를 표시한다.

## 5. 시간표 표시 범위

CRM의 `serviceRecords` 중 취소되지 않은 일정만 사용한다.

- 오늘 시간표: `scheduledDate`가 오늘인 일정
- 이번 주 일정: 이번 주 월요일부터 일요일까지의 일정
- 표시 필드: `scheduledDate`, `startTime`, `endTime`, `title`, `owner`, `status`
- 제외 필드: 고객명, 전화번호, 건물 주소, 작업 메모, 금액, 업체명, 증빙 URL
- 시간이 없는 일정은 `시간 미정`으로 마지막에 배치
- 일정이 없으면 빈 화면이 아니라 `오늘 등록된 일정이 없습니다` 또는 `이번 주 등록된 일정이 없습니다`를 표시

## 6. 데이터 구조

기존 공개 게시물 모델에 다음 조회 전용 투영을 추가한다.

```text
model
├─ counts / total / overdue / unknown / people
├─ roadmap
│  ├─ range: from, to, weeks, todayOffset
│  ├─ lanes[]: assigneeName, progress, projectCount
│  └─ assignments[]: projectName, startDate, endDate,
│                    left, width, progress, health, owner
├─ portfolio
│  ├─ overallProgress
│  ├─ healthCounts
│  ├─ projects[]
│  ├─ weeklyDone[]
│  └─ milestones[]
└─ schedule
   ├─ today[]
   └─ week[]
```

게시 스키마는 허용된 키만 통과시키며 문자열 길이, 날짜, 시간, 개수, 진행률 범위를 검증한다. TV 웹 앱도 같은 구조를 다시 검증한 뒤 렌더링한다.

## 7. 데이터 흐름

1. 로그인된 관리자 CRM이 서버에서 업무지시, 프로젝트, CRM 내부 일정을 읽는다.
2. `company-wallboard` 투영기가 TV에 필요한 안전한 필드만 계산한다.
3. 게시 스키마가 구조와 값 범위를 검증한다.
4. 기존 관리자 게시기가 1분마다 최신 게시 자료를 Worker에 저장한다.
5. TV는 15초마다 게시 자료를 확인하고 새 버전이면 현재 장면을 유지한 채 내용을 갱신한다.
6. 앱 코드 버전이 바뀌면 기존 무접촉 업데이트 방식으로 TV 페이지가 자동 재시작된다.

CRM 서버 조회가 실패하면 마지막으로 검증된 게시 자료를 계속 표시하고 상단에 `연결 확인 중 · 최근 자료 유지`를 표시한다. 잘못된 새 자료로 기존 화면을 덮지 않는다.

## 8. 디자인 원칙

- CRM과 동일한 토스형 토큰을 사용한다: `#F2F4F6` 배경, 흰 카드, `#3182F6` 주색, `#191F28` 본문, `#E5E8EB` 테두리.
- 장식용 그라데이션은 제거하고 평면 카드와 얕은 그림자를 사용한다.
- 1920×1080 TV에서 3m 거리 기준으로 프로젝트명과 퍼센트를 읽을 수 있어야 한다.
- 현재 주와 오늘 선을 분명히 표시한다.
- 화면 전환은 30초 기본값이며 기존 편성 설정에서 10~120초로 변경할 수 있다.
- `prefers-reduced-motion`에서는 전환 애니메이션을 제거한다.

## 9. 편성 설정

기존 5개 장면 제한을 확장한다. 새 기본 순서는 다음과 같다.

1. 프로젝트 로드맵 — 40초
2. 프로젝트별 진행률 — 25초
3. 주간 완료 실적 — 20초
4. 프로젝트 건강도 — 20초
5. 이번 주 핵심 결과물 — 25초
6. 오늘 시간표 — 30초
7. 이번 주 일정 — 30초
8. 사람별 업무 — 25초
9. 확인할 이슈 — 20초
10. 회사 공지 — 30초

관리자는 CRM 회사 운영보드에서 장면 사용 여부, 순서, 노출 시간을 기존 방식으로 변경한다.

## 10. 오류·빈 상태

- 프로젝트가 없으면 `등록된 프로젝트가 없습니다`를 표시한다.
- 날짜 없는 프로젝트는 로드맵에서 숨기지 않고 `날짜 미정` 영역에 표시한다.
- 진행률이 없으면 0%로 표시하되 `미입력` 문구를 함께 보여 입력값과 실제 0%를 구분한다.
- 프로젝트가 화면 폭보다 길면 보이는 기간까지만 잘라 표시하고 양 끝에 계속됨 표시를 둔다.
- 담당자·프로젝트가 많으면 글자를 줄이지 않고 페이지를 나눈다.
- 한 장면의 렌더링 실패가 다른 장면의 자동 순환을 중단하지 않도록 장면별 오류 경계를 둔다.

## 11. 검증 기준

- 원본 프로젝트 화면과 TV의 프로젝트명·기간·진행률이 일치한다.
- 전체 진행률 계산이 활성 프로젝트 진행률 평균과 일치한다.
- 기한 위험·확인 필요 판정이 날짜 경계에서 정확하다.
- 오늘/이번 주 일정이 날짜·시간 순으로 표시된다.
- 취소 일정과 비공개 필드가 게시 자료에 포함되지 않는다.
- 0건, 1건, 3명 초과, 8주 범위 밖, 날짜 미정 데이터를 모두 안전하게 표시한다.
- 게시 스키마와 TV 클라이언트가 변조·과다 데이터·알 수 없는 장면 키를 거부한다.
- 1920×1080과 1366×768에서 잘림·가로 스크롤·글자 겹침이 없다.
- 기존 페어링, 자동 순환, 15초 데이터 갱신, 60초 앱 버전 확인 기능이 회귀하지 않는다.

## 12. 완료 기준

CRM에서 프로젝트 진행률이나 내부 일정을 변경한 뒤 운영보드 게시가 성공하면 TV가 별도 조작 없이 새 자료를 반영한다. TV의 로드맵에서 담당자·프로젝트·기간·진행률을 확인할 수 있고, 자동 순환을 통해 프로젝트 순위·주간 완료·건강도·마감·오늘 및 이번 주 시간표를 모두 볼 수 있으면 완료다.
