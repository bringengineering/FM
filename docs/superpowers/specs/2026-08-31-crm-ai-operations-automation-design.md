# BRING CRM AI 영업·건물관리·경영분석 자동화 설계

## 1. 목적

기존 BRING CRM 안에서 다음 세 업무를 하나의 공통 AI 체계로 지원한다.

1. 영업 자동화: 고객별 우선순위, 재연락 시점, 후속 문자 초안
2. 건물관리 자동화: 민원 분류, 업체 요청문, 작업지시서, 완료보고서
3. 경영·수익 분석: 작업별 손익과 월간 정량·정성 보고

AI가 숫자나 사실을 임의로 만들지 않도록 CRM의 확정 데이터를 계산의 원천으로 사용한다. 외부 발송 문구와 금액 보고서는 반드시 사용자가 검토한 뒤 사용한다.

## 2. 설계 원칙

- 새 프로그램을 만들지 않고 기존 CRM 메뉴와 데이터 구조에 포함한다.
- 현진님을 포함한 팀원이 이미 입력한 고객, 건물, 상담, 영업, 작업, 계약 데이터는 마이그레이션하거나 덮어쓰지 않는다.
- 우선순위·재연락 추천·민원 분류·손익 계산은 가능한 범위에서 규칙 기반으로 먼저 산출한다.
- Groq AI는 설명, 요약, 문서 초안처럼 언어 생성이 필요한 부분만 담당한다.
- AI 결과는 `제안`과 `확정 데이터`를 구분한다. 사용자가 실행한 자동정리 동작에서만 확정 필드에 반영한다.
- 문자와 업체 요청은 CRM 밖으로 자동 전송하지 않는다.
- 개인 메모, 비밀번호, 인증 토큰, 불필요한 연락처는 AI 요청에서 제외한다.
- 기존 Cloudflare Worker 중계 구조를 확장하며 EXE나 GitHub에 Groq API 키를 넣지 않는다.

## 3. 공통 구조

### 3.1 역할 분담

- CRM 계산 엔진: 점수, 기한, 매출, 원가, 이익, 이익률을 확정적으로 계산한다.
- Cloudflare AI 중계 서버: 허용된 작업과 필드만 Groq에 전달하고 결과 형식을 검증한다.
- CRM 화면: 원본 근거와 AI 제안을 함께 표시하고 사용자가 적용·복사·수정하도록 한다.
- 기존 저장 계층: 적용된 변경을 현재의 서버 저장 및 감사 로그 방식으로 기록한다.

### 3.2 AI 제안 공통 형식

모든 구조화된 제안은 다음 정보를 가진다.

- `requestId`: 요청 추적 ID
- `task`: AI 작업 종류
- `entityType`, `entityId`: 대상 고객·건물·작업·보고서
- `generatedAt`, `expiresAt`: 생성·만료 시각
- `sourceRevision`: 생성 당시 원본 데이터 버전
- `proposedPatch`: 적용 가능한 구조화 필드
- `explanation`: 추천 이유
- `confidence`: 높음·보통·낮음
- `warnings`: 누락 데이터나 검토 필요 사항

적용 시 `sourceRevision`이 현재 데이터와 다르면 오래된 제안을 거부하고 다시 생성하도록 안내한다. 적용 결과는 담당자, 시각, 변경 전후 값, AI 요청 ID와 함께 감사 로그에 남긴다.

## 4. 영업 자동화

### 4.1 영업 집중 점수

고객 및 영업 대상마다 0~100점의 점수를 계산한다. 기본 가중치는 다음과 같다.

- 단계 점수 최대 25점: 실제 문의·협의·견적 단계일수록 높음
- 후속조치 기한 최대 25점: 오늘 예정 15점, 기한 초과 25점
- 최근 반응 최대 20점: 회신·통화·방문 등 유효 반응
- 공실·구체 요청 최대 15점: 공실 또는 해결할 문제가 명시됨
- 예상 금액 최대 10점: 확정 금액이 있는 경우 구간별 반영
- 장기 미접촉 보정 최대 5점: 재접촉이 필요한 휴면 고객

점수 구간은 `긴급 80~100`, `높음 55~79`, `보통 30~54`, `육성 0~29`로 고정한다. 입력값이 없는 항목은 0점으로 처리하고 AI가 임의로 보충하지 않는다.

### 4.2 자동정리 동작

영업 관리 화면에 `AI 영업 집중 목록`과 `오늘 영업 자동정리`를 추가한다. 사용자가 자동정리를 실행하면:

1. 규칙 엔진이 점수와 추천 재연락일을 계산한다.
2. AI가 근거 설명과 후속 문자 초안을 만든다.
3. 점수, 우선순위, 다음 행동, 재연락일은 변경 미리보기 후 일괄 적용한다.
4. 문자 초안은 복사·수정만 가능하며 자동 발송하지 않는다.

추천 재연락 간격은 긴급 1일, 높음 3일, 보통 7일, 육성 14일을 기본으로 하되 이미 더 빠른 확정 일정이 있으면 유지한다.

### 4.3 화면 출력

- 고객명·건물명
- 집중 점수와 등급
- 추천 근거 2~3개
- 다음 행동과 추천일
- 후속 문자 초안 생성 버튼
- 적용, 제외, 다시 계산

## 5. 건물관리 자동화

### 5.1 민원 분류

민원은 `누수·수도`, `전기`, `난방·냉방`, `청소`, `폐기물`, `예초·외부`, `시설파손`, `임대차`, `기타`로 분류한다. 긴급도는 `즉시`, `오늘`, `3일 이내`, `일반`으로 분류한다.

화재·가스·감전·침수·출입 불가처럼 안전 관련 표현은 규칙 엔진이 우선 경고하고 AI 판단과 무관하게 `즉시 확인`을 표시한다. 이는 긴급기관 신고를 대신하지 않는다.

### 5.2 생성 문서

기존 작업관리 또는 고객·건물 상세에서 다음 문서를 생성한다.

- 업체 요청문: 위치, 증상, 방문 희망일, 확인 항목
- 작업지시서: 작업 범위, 준비물, 사진·확인 기준, 담당자
- 완료보고서: 수행 내용, 전후 상태, 비용, 미완료·후속조치

연락처와 상세주소는 화면에서 사용자가 확인할 수 있지만 AI에는 문서 생성에 꼭 필요한 최소 정보만 전달한다. 개인 메모는 항상 제외한다.

### 5.3 저장과 전달

분류와 문서 초안은 원본 작업 옆에 표시한다. 사용자가 적용하면 기존 작업 기록에 구조화 필드를 저장하고 감사 로그를 남긴다. 업체 요청문은 복사만 제공하며 카카오톡·문자·이메일로 자동 전송하지 않는다.

## 6. 경영·수익 분석

### 6.1 확정 계산

기존 계약·단건 작업 데이터에서 다음 값을 월별로 계산한다.

- 완료 작업 수
- 매출: 수금 예정 또는 수금 완료 금액을 상태별로 분리
- 원가: 업체 지급 예정 또는 지급 완료 금액을 상태별로 분리
- 매출총이익: 매출 - 원가
- 이익률: 매출이 0보다 클 때 매출총이익 / 매출 × 100
- 미수금과 미지급금
- 작업 유형별 매출·이익
- 담당자별 작업·영업 실적
- 영업 연락 수, 유효 반응 수, 계약 전환 수와 전환율

AI는 이 숫자를 계산하거나 수정하지 않는다. CRM 계산 엔진이 만든 읽기 전용 지표 묶음만 전달받는다.

### 6.2 월간 보고서

Operations Intelligence 화면에 `AI 월간 경영보고`를 추가한다. 보고서는 다음 순서로 생성한다.

1. 핵심 수치 요약
2. 전월 대비 변화
3. 수익성이 높은·낮은 작업 유형
4. 미수·미지급 및 일정 위험
5. 영업 활동과 전환 현황
6. 다음 달 실행 제안 3개

모든 정성 문장은 사용한 지표명과 값을 근거로 표시한다. 비교할 전월 데이터가 없으면 비교 불가라고 명시하며 추정하지 않는다. 보고서는 화면 확인 후 복사 또는 내보내기만 가능하고 자동 외부 공유하지 않는다.

## 7. 권한·보안·개인정보

- 로그인된 허용 사용자만 AI 중계 서버를 호출할 수 있다.
- 관리자와 편집 권한 사용자는 제안을 생성·적용할 수 있다.
- 읽기 전용 사용자는 결과 조회만 가능하고 CRM 데이터를 변경할 수 없다.
- Worker는 작업 종류, 입력 크기, 호출 횟수, 허용 이메일을 검증한다.
- API 키는 Cloudflare Secret으로만 저장한다.
- 개인 메모, 인증 정보, 원문 전체 덤프는 AI 요청에서 제외한다.
- 오류 로그에는 고객 원문 대신 요청 ID, 작업 종류, 오류 코드만 남긴다.
- AI 호출 실패 시 CRM 저장과 기존 업무 기능은 계속 동작한다.

## 8. 기존 데이터와 충돌 방지

- 기존 필드는 삭제·이름 변경하지 않고 선택 필드를 추가한다.
- 기존 고객·건물·상담·작업·계약 레코드는 일괄 변환하지 않는다.
- 자동정리는 사용자가 명시적으로 누른 대상에만 실행한다.
- 적용 전 변경 미리보기와 적용 대상 건수를 표시한다.
- 서버 저장 실패 시 로컬 성공으로 표시하지 않고 기존 오류 처리와 재시도 흐름을 사용한다.
- 최신 운영 브랜치 변경을 먼저 가져오고 fast-forward 가능한 상태에서만 배포한다.

## 9. 구현 단계

1. 공통 제안 계약, 규칙 계산 엔진, 권한·감사 로그 기반
2. 영업 집중 점수, 재연락 추천, 문자 초안
3. 민원 분류, 업체 요청문, 작업지시서, 완료보고서
4. 월간 손익 집계, 경영보고, 통합 대시보드 카드
5. 전체 회귀 테스트, Worker 배포, EXE 릴리스, 자동 업데이트 검증

각 단계는 기존 화면과 저장 기능의 회귀 테스트를 통과한 뒤 다음 단계로 진행한다.

## 10. 테스트와 검증

- 점수 경계값과 누락 데이터 단위 테스트
- 재연락일 계산과 기존 빠른 일정 보존 테스트
- 매출·원가·이익·이익률·미수·미지급 계산 테스트
- 개인 메모와 불필요한 개인정보가 AI 요청에 포함되지 않는 테스트
- 읽기 전용 사용자의 적용 차단 테스트
- 원본 변경 후 오래된 AI 제안 적용 차단 테스트
- Worker 허용 작업, 인증, 마스킹, 호출 제한 테스트
- 화면별 생성·수정·적용·취소·오류 복구 통합 테스트
- Node 22 환경 전체 테스트와 데스크톱 빌드
- 저장소 및 산출물의 비밀정보 검사
- 인증된 실제 AI 요청 probe와 자동 업데이트 probe

## 11. 배포 원칙

- Cloudflare Worker의 작업 목록과 검증 스키마를 먼저 배포한다.
- Firebase Functions와 Hosting은 사용하거나 배포하지 않는다.
- 데이터 규칙 변경이 필요한 경우에만 Rules를 배포한다.
- 운영 브랜치에는 force push 없이 fast-forward로 반영한다.
- 기존 태그를 이동하거나 재사용하지 않고 다음 미사용 버전을 발행한다.
- EXE, blockmap, latest.yml 공개와 실제 자동 업데이트 확인까지 완료해야 릴리스를 종료한다.

## 12. 완료 기준

- 영업 화면에서 우선순위·재연락일·후속 문자 초안을 한 흐름으로 만들 수 있다.
- 건물 또는 작업 화면에서 민원을 분류하고 업체 요청문·작업지시서·완료보고서를 만들 수 있다.
- Operations Intelligence에서 작업별 손익과 월간 정량·정성 보고를 생성할 수 있다.
- AI가 생성한 외부 문구와 보고서는 사용자 확인 없이는 전송·공유되지 않는다.
- 개인 메모가 AI로 전송되지 않는다.
- 기존 데이터와 현진님 변경사항을 보존하고 전체 테스트가 통과한다.
- 새 버전 설치 파일과 자동 업데이트 채널이 실제로 동작한다.
