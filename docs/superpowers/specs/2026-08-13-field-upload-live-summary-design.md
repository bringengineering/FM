# BRING FIELD 실시간 업로드 현황 설계

## 목표

휴대전화에서 촬영하거나 사진첩에서 추가한 모든 사진·영상의 업로드 상태를 앱 어디서나 실시간으로 확인한다. 별도 서버 비용은 추가하지 않고, 현재 사용 중인 IndexedDB 촬영 대기열을 기준으로 집계한다.

## 집계 기준

- `오늘`: Asia/Seoul 날짜를 기준으로 오늘 촬영한 전체 파일 수
- `업로드 중`: 날짜와 관계없이 `queued`, `uploading`, `objectStored`, `finalizing` 상태인 파일 수
- `완료`: 오늘 촬영했고 Drive 저장까지 완료된 파일 수
- `실패`: 날짜와 관계없이 `failed` 상태인 파일 수
- 전체 진행률: 오늘 촬영한 파일의 `uploadProgress` 평균. 오늘 파일이 없으면 0%로 표시한다.

사진과 영상은 동일하게 파일 1개로 계산한다. 완료 파일도 휴대전화의 로컬 촬영 기록에 남아 있는 동안 집계한다.

## 화면 구성

상단 상태 영역은 기존 높이를 늘리지 않고 `오늘 N · 업로드 중 N · 완료 N · 실패 N`을 한 줄로 표시한다. 실패가 있으면 경고 색상을 사용한다.

촬영 화면 상단에는 동일한 네 개의 숫자와 전체 진행 막대, 백분율을 표시한다. 개별 파일의 기존 진행률과 상태 표시는 그대로 유지한다.

## 데이터 흐름

`OfflineQueuePort.list(uid)`로 현재 휴대전화의 전체 촬영 기록을 읽고 순수 집계 함수가 요약값을 계산한다. 앱이 열려 있는 동안 1초 간격으로 갱신하며, 화면 포커스·온라인 복귀·Drive 연결 직후에는 즉시 다시 집계한다.

조회 실패 시 마지막으로 성공한 숫자를 유지하고 `현황 확인 지연`을 표시한다. 업로드 자체는 중단하지 않는다. 로그아웃하거나 사용자가 바뀌면 이전 사용자의 숫자는 즉시 초기화한다.

## 구성요소

- `upload-summary.ts`: 날짜 판정과 상태 집계를 담당하는 순수 함수
- `FieldWorkspace`: 대기열을 주기적으로 읽고 최신 요약 상태를 보유
- `AppShell`: 전체 앱 상단의 간결한 현황 표시
- `CaptureWorkspace`: 상세 숫자와 전체 진행 막대 표시

## 테스트

- 서울 날짜 경계에서 오늘 완료 건만 집계
- 이전 날짜의 대기·실패 건은 계속 집계
- 상태별 숫자와 진행률 계산
- 사용자 변경 시 초기화
- 1초 갱신, 포커스 및 온라인 복귀 시 즉시 갱신
- 상단 및 촬영 화면 접근성 문구와 모바일 레이아웃

## 범위 밖

관리자 전체 팀원의 업로드 현황을 서버에서 통합 조회하는 기능과 과거 통계 대시보드는 이번 범위에 포함하지 않는다.
