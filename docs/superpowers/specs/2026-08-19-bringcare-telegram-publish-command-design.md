# 브링케어 텔레그램 `발행` 승인 명령 설계

## 목표

네이버 블로그 글이 발행 직전까지 준비되면 사용자가 ChatGPT 대화를 다시 열지 않고, 등록된 텔레그램 봇 대화창에 `발행`이라고 보내 해당 글의 발행을 승인할 수 있게 한다.

텔레그램 메시지는 발행 승인을 기록한다. 실제 네이버 공개 발행은 다음 3시간 Codex 자동화 회차가 승인 기록을 확인한 뒤 기존 검증·브라우저 발행 절차로 수행한다. 텔레그램 메시지가 Codex 작업을 즉시 깨우거나 네이버를 직접 조작한다고 표현하지 않는다.

## 현재 글 적용 범위

- 최초 적용 글 ID: `20260819-cheoseo-house-check`
- 제목: `처서 매직 기다렸는데, 집 안은 아직 여름인 이유`
- 현재 상태: 네이버 편집기 입력과 발행 설정을 마치고 최종 공개 발행 전 대기
- 승인 유효시간: 준비 완료 알림 생성 시점부터 24시간

## 사용자 경험

1. 자동화가 검증을 통과한 글을 네이버 편집기에서 발행 직전까지 준비한다.
2. 텔레그램 봇이 제목·유형·카테고리와 함께 다음 안내를 보낸다.
   - `이 글을 발행하려면 이 채팅에 발행이라고 보내주세요.`
   - `취소하려면 취소라고 보내주세요.`
3. 사용자는 텔레그램에 `발행` 또는 `취소`라고 보낸다.
4. 다음 자동화 회차가 텔레그램 업데이트를 동기화한다.
5. `발행`이면 해당 글을 최우선으로 발행하고, 성공 시 제목과 공개 URL을 텔레그램으로 보낸다.
6. `취소`이면 대기 글을 취소 상태로 바꾸고 새 글을 발행하지 않는다.

## 핵심 제약

- 동시에 승인 대기 상태는 정확히 한 글만 허용한다.
- `발행`은 가장 최근의 유효한 단일 대기 글에만 적용한다.
- 대기 글이 없거나 둘 이상이면 승인하지 않고 설명 메시지를 보낸다.
- 설정된 개인 `chat_id`에서 온 일반 텍스트 메시지만 명령으로 인정한다.
- 봇·채널·그룹·다른 사용자 메시지는 무시한다.
- 명령은 앞뒤 공백을 제거한 뒤 정확히 `발행` 또는 `취소`일 때만 인정한다.
- 승인 요청은 24시간 후 만료된다. 만료된 글은 자동 발행하지 않는다.
- 동일 Telegram `update_id`와 동일 글의 승인 명령은 한 번만 처리한다.
- 봇 토큰과 채팅 ID는 공개 로그·승인 원장·오류 메시지에 기록하지 않는다.

## 구성요소

### 1. 대기 글 원장

`automation/bringcare_telegram/publish-approval-state.json`에 다음 정보를 원자적으로 저장한다.

- `post_id`
- `title`
- `post_type`
- `category`
- `requested_at`
- `expires_at`
- `status`: `pending | approved | cancelled | expired | published | blocked`
- `approved_at`
- `telegram_update_id`
- `published_url`

임시 파일에 쓴 뒤 교체하여 중간 종료 시 JSON 손상을 막는다. 손상된 원장은 `.corrupt`로 이동하고 안전하게 중단한다.

### 2. 텔레그램 준비 완료 알림

기존 URL 버튼을 제거한다. `ready` 명령은 알림을 보낸 뒤 동일 글을 `pending`으로 기록한다. 기존 유효한 `pending` 글이 있으면 새 대기 글로 덮어쓰지 않고 실패한다.

### 3. 텔레그램 명령 동기화

새 CLI 명령 `sync-approval`이 Telegram Bot API `getUpdates`를 호출한다.

- 마지막 처리 `update_id + 1`을 offset으로 사용한다.
- 허용된 개인 채팅의 텍스트만 검사한다.
- `발행`이면 유효한 `pending`을 `approved`로 변경한다.
- `취소`이면 `cancelled`로 변경한다.
- 처리 결과는 `sendMessage`로 짧게 회신한다.
- 승인된 제목을 회신하여 사용자가 어느 글을 승인했는지 확인할 수 있게 한다.

### 4. 자동화 승인 게이트

매 자동화 회차 시작 시 새 주제를 조사하기 전에 다음 순서로 실행한다.

1. `sync-approval`
2. `approval-status --post-id <ID>`
3. 승인된 대기 글이 있으면 새 글 작성을 건너뛰고 그 글을 복구한다.
4. 기존 브리프·원고·이미지·편집 화면을 다시 검증한다.
5. 검증과 로그인 상태가 정상일 때만 네이버에 발행한다.
6. 발행 성공 후 `published` 알림과 함께 원장을 `published`로 바꾼다.

`pending`, `cancelled`, `expired`는 발행 허가가 아니다.

## 실패 처리

- Telegram 인증 실패: 승인 상태를 바꾸지 않고 기존 오류 코드로 종료한다.
- 일시적 네트워크 실패: 상태를 보존하고 다음 회차에 재시도한다.
- 대기 글 없음: `승인 대기 중인 글이 없습니다.`라고 회신한다.
- 승인 만료: `승인 요청이 만료되었습니다.`라고 회신하고 발행하지 않는다.
- 로그인 만료·CAPTCHA·편집기 변경: 승인 상태는 `blocked`로 보존하고 기존 차단 알림을 보낸다.
- 공개 검수 실패: URL을 성공으로 기록하지 않고 재개 지점을 보존한다.

## 검증 기준

- 등록된 채팅에서 `발행`을 보내면 한 건의 `pending`만 `approved`가 된다.
- 다른 채팅, 그룹, 봇, 유사 문구는 승인으로 처리되지 않는다.
- 같은 업데이트를 재수신해도 중복 처리되지 않는다.
- 24시간이 지난 요청은 발행되지 않는다.
- 승인 전에는 네이버 최종 발행 버튼을 누르지 않는다.
- 승인된 글이 있으면 새 주제보다 우선 처리한다.
- 성공 URL이 확인된 뒤에만 `published`가 된다.
- 토큰·채팅 ID·민감한 원문은 로그와 테스트 결과에 노출되지 않는다.

## 범위 밖

- 텔레그램 메시지로 Codex 작업을 즉시 깨우는 기능
- 텔레그램 봇이 네이버 편집기를 직접 조작하는 기능
- 동시에 여러 글을 번호로 선택하는 승인 기능
- 그룹 채팅 승인
- 네이버 로그인·CAPTCHA 자동 우회
