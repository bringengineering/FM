# BRING CARE 랜딩페이지 공통 간편 견적창 설계

## 목표

사용자가 페이지 맨 아래의 상세 견적 폼까지 내려가지 않아도 현재 보고 있는 위치에서 바로 상담을 신청할 수 있게 한다.

다음 네 랜딩페이지에 동일한 전환 구조를 적용한다.

- `/turnover-care` — 24H 입·퇴실 관리
- `/stair-cleaning` — 계단·공용부 청소
- `/building-care` — 건물관리
- `/move-in-cleaning` — 입주·이사청소

기존 상세 견적 폼, Firebase CRM 저장 경로, 접수 완료 화면, 전화·카카오톡 상담, 서비스별 SEO 메타데이터는 유지한다.

## 선택한 방식

공용 간편 견적창과 항상 접근 가능한 견적 버튼을 결합한다.

- 데스크톱: 화면 중앙 모달
- 모바일: 화면 아래에서 올라오는 바텀시트
- 기존 페이지 하단: 상세 견적 폼 유지
- JavaScript가 동작하지 않거나 견적창을 열 수 없는 경우: 기존 `#quick-estimate` 상세 폼으로 이동

페이지 중간마다 폼을 반복하거나 연락처 입력창 자체를 고정하는 방식은 사용하지 않는다. 반복 폼은 페이지를 더 길게 만들고, 고정 입력창은 광고성 인상을 키우며 모바일 가시 영역을 과도하게 차지하기 때문이다.

## 견적 진입 동선

각 페이지에서 기존 견적 CTA를 공용 간편 견적창의 실행 버튼으로 바꾼다.

- 상단 내비게이션의 `간편 견적` 또는 `30초 견적`
- 히어로의 `30초 간편 견적`, `퇴실 일정 상담하기` 등 견적 목적 CTA
- 모바일 하단 고정 견적 버튼
- 데스크톱에서 스크롤 중에도 접근할 수 있는 우측 하단 `30초 견적` 플로팅 버튼

전화 및 카카오톡 버튼은 현재 동작을 유지하며 견적창 실행 버튼으로 바꾸지 않는다.

모든 견적 실행 요소는 링크 폴백 `href="#quick-estimate"`를 유지한다. JavaScript가 활성화된 경우에만 기본 이동을 막고 간편 견적창을 연다.

## 간편 견적창 입력 항목

전환 장벽을 낮추기 위해 필수 입력은 세 가지로 제한한다.

1. 연락처
2. 필요한 상담 내용
3. 개인정보 수집·연락 동의

연락처는 `010-1234-5678` 형식으로 입력하며, 숫자를 입력하면 가능한 범위에서 하이픈을 자동으로 보정한다.

상담 내용의 예시는 서비스별로 바꾼다.

- 24H 입·퇴실 관리: 퇴실 예정일, 호실 위치, 필요한 준비
- 계단·공용부 청소: 건물 위치, 층수, 희망 청소 주기
- 건물관리: 건물 위치, 세대수, 현재 가장 불편한 문제
- 입주·이사청소: 청소 희망일, 공간 유형, 평형 또는 방 개수

이름, 정확한 주소, 건물 정보와 고객 유형은 간편 견적창에서 요구하지 않는다. 상담 연결 후 보완한다. 상세 정보를 바로 남기려는 사용자는 기존 하단 상세 견적 폼을 이용할 수 있다.

## CRM 저장 데이터

간편 견적창도 기존 `submitMarketingLead`를 사용해 다음 경로로 저장한다.

`crmCompany/marketingLeadInbox/{requestId}`

저장 필드는 기존 `MarketingLeadInput` 형식을 그대로 유지한다.

- `phone`: 사용자가 입력한 연락처
- `needs`: 사용자가 입력한 상담 내용
- `consent`: `true`
- `service`: 현재 랜딩페이지의 서비스명
- `sourcePath`: 현재 랜딩페이지 경로
- `utmSource`, `utmCampaign`, `utmTerm`: 현재 URL에서 자동 수집
- `name`: 빈 문자열
- `location`: 빈 문자열
- `buildingInfo`: 빈 문자열
- `customerType`: 서비스별 기본값
  - `turnover-care`, `stair-cleaning`, `building-care`: `building_owner`
  - `move-in-cleaning`: `individual`

기존 CRM 데이터 구조나 보안 규칙은 변경하지 않는다.

## 제출 결과와 오류 처리

### 성공

CRM 저장이 성공하면 기존 접수 완료 경로로 이동한다.

`/consult/complete?receipt={receiptId}`

중복 제출을 막기 위해 전송 중에는 제출 버튼을 비활성화하고 `전송 중...`으로 표시한다.

### 실패

견적창 안에서 오류 메시지를 표시하고 다음 대체 동선을 제공한다.

- `010-6566-3603` 전화 상담
- 작성한 신청 내용 복사
- 다시 제출

오류가 발생해도 입력 내용은 유지한다.

## 컴포넌트 구조

### `QuickEstimateProvider`

페이지 전체의 견적창 열림 상태와 실행 버튼의 원래 포커스를 관리하는 클라이언트 컴포넌트다. `LandingPage` 안에서 한 번만 렌더링한다.

입력:

- `service`
- `sourcePath`
- `defaultCustomerType`
- `needsPlaceholder`

역할:

- 견적창 열기·닫기
- 본문 스크롤 잠금
- 닫은 뒤 실행 버튼으로 포커스 복귀
- ESC 및 배경 클릭 처리
- 간편 견적 폼 렌더링

### `QuickEstimateTrigger`

공용 실행 요소다. 기본적으로 `href="#quick-estimate"`인 링크로 렌더링하고, Provider가 활성화된 경우 간편 견적창을 연다.

기존 클래스명과 시각 디자인을 전달받아 각 페이지의 현재 버튼 스타일을 유지한다.

### `CompactEstimateForm`

연락처, 상담 내용, 동의만 받는 전용 폼이다. CRM 제출, UTM 수집, 전송 상태, 오류 대체 동선을 담당한다.

기존 `QuickEstimateForm`은 수정 범위를 최소화해 페이지 하단 상세 견적용으로 유지한다. CRM 입력 조립과 오류 메시지 복사처럼 두 폼이 공유하는 로직만 작은 유틸리티로 분리한다.

### 플로팅 CTA

Provider가 페이지마다 하나만 렌더링한다.

- 데스크톱: 우측 하단의 작은 `30초 견적` 버튼
- 모바일: 기존 전체 폭 하단 고정 CTA

동일 화면에 데스크톱 플로팅 CTA와 모바일 고정 CTA가 동시에 보이지 않도록 CSS 미디어쿼리로 분리한다.

## 접근성

- 견적창은 접근 가능한 이름이 있는 `dialog`로 제공한다.
- 열릴 때 첫 번째 연락처 입력으로 포커스를 이동한다.
- ESC와 닫기 버튼으로 닫을 수 있다.
- 닫으면 견적창을 연 버튼으로 포커스가 돌아간다.
- 배경 콘텐츠는 대화상자가 열린 동안 키보드 탐색 대상에서 제외한다.
- 오류와 제출 상태는 `aria-live`로 알린다.
- 모바일 키보드가 열려도 제출 버튼과 동의 문구에 접근할 수 있도록 견적창 내부만 스크롤 가능하게 한다.
- `prefers-reduced-motion` 환경에서는 바텀시트 이동 애니메이션을 제거한다.

## 반응형 디자인

### 데스크톱

- 너비 최대 520px
- 중앙 정렬
- 흰색 배경, 24px 안팎 여백
- 20~24px 모서리
- 연락처 한 줄 입력, 상담 내용 4줄
- 우측 상단 닫기 버튼
- 배경은 반투명 네이비 오버레이

### 모바일

- 화면 하단에 붙는 바텀시트
- 좌우 14px 또는 전체 폭 안쪽 여백
- 위쪽 모서리 24px
- 최대 높이 `calc(100dvh - 24px)`
- 내부 세로 스크롤
- 제출 버튼은 바텀시트 안에서 전체 폭

기존 BRING CARE 블루, 네이비, Pretendard 체계를 사용하고 별도의 새로운 시각 언어를 추가하지 않는다.

## 계측과 유입 정보

별도 분석 도구나 새 데이터베이스 필드는 추가하지 않는다. 현재 CRM 데이터만으로 다음을 구분한다.

- 서비스명
- 유입 페이지
- 네이버 광고의 `utm_source`, `utm_campaign`, `utm_term`

간편 견적과 상세 견적의 성과를 구분할 필요가 생기면 후속 작업에서 `formVariant` 필드를 추가한다. 이번 범위에서는 CRM 스키마를 변경하지 않는다.

## 테스트 기준

### 컴포넌트 테스트

- 네 페이지의 모든 견적 CTA가 간편 견적창을 연다.
- 기본 링크 폴백은 `#quick-estimate`다.
- 서비스별 이름, 경로, 고객 유형과 상담 예시가 정확하다.
- 연락처, 상담 내용과 동의가 없으면 제출되지 않는다.
- 전화번호 형식이 잘못되면 CRM을 호출하지 않는다.
- 전송 중 중복 제출이 차단된다.
- 성공 시 접수 완료 경로로 이동한다.
- 실패 시 입력 유지, 전화, 복사와 재시도가 제공된다.
- ESC·닫기·배경 클릭·포커스 복귀가 동작한다.

### 회귀 테스트

- 기존 상세 `QuickEstimateForm`의 CRM 저장 테스트가 계속 통과한다.
- 가격, 부가세, 전화, 카카오톡, 현장기록, FAQ와 SEO가 유지된다.
- 페이지마다 `#quick-estimate` ID는 하나만 존재한다.
- 다른 세 랜딩페이지의 고유 히어로와 콘텐츠가 바뀌지 않는다.

### 공개 화면 검수

- 데스크톱, 768px 태블릿, 390px 모바일에서 견적창의 잘림과 가로 넘침이 없다.
- 모바일 키보드 환경에서도 상담 내용과 제출 버튼까지 스크롤할 수 있다.
- 네 페이지에서 견적창을 열고 닫되 실제 CRM 제출은 자동 검수에서 수행하지 않는다.
- 공개 HTML과 Firebase Hosting 결과물에 네 경로의 견적 실행 요소가 포함된다.

## 배포 범위

- `company-site` 소스와 테스트
- `company-site/firebase-public/**` 정적 결과물
- Firebase Hosting `bring-fm`만 배포

Database, Storage, Functions, CRM 보안 규칙은 변경하거나 배포하지 않는다.

## 제외 범위

- 가격 정책 변경
- 랜딩페이지 본문 재디자인
- CRM 데이터 구조 변경
- 카카오톡 자동 메시지 발송
- 실제 상담 전화·문자 자동 발송
- 네이버 광고 설정 변경
- 실제 고객 정보로 자동 제출 테스트
