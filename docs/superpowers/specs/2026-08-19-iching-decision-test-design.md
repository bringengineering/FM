# 《하지 말라고 했습니다》 테스트 버전 설계

## 목적

사용자가 고민과 두 선택지를 입력하고 동전을 여섯 번 던진 뒤, 주역의 괘를 자기성찰형 의사결정 메시지로 읽는 모바일 웹 체험을 만든다. 미래 예측이나 정답 제공이 아니라, 결과를 읽으며 사용자가 자신의 선호와 회피를 알아차리게 하는 것이 핵심 가치다.

## 테스트 가설

1. 역설적인 첫 문구가 사용자의 호기심을 유발한다.
2. 직접 동전을 여섯 번 던지는 과정이 결과에 대한 몰입을 높인다.
3. 모호한 길흉보다 현재 장애물, 두 선택지의 위험, 현실 질문을 제공할 때 결과를 저장하거나 공유하고 싶어진다.

## 범위

### 포함

- 모바일 우선 단일 페이지 웹앱
- 고민 한 문장과 선택지 A/B 입력
- 동전 3개를 여섯 번 던지는 인터랙션
- 6·7·8·9 값에 따른 음양효와 변효 계산
- 상괘·하괘를 이용한 64괘 판정
- 본괘, 변효, 변괘 표시
- 64괘별 자체 작성 핵심 메시지 데이터
- 입력한 고민과 선택지를 반영한 규칙 기반 상세 결과
- 결과 복사 및 처음부터 다시 하기
- 오락·자기성찰 목적 안내

### 제외

- 결제, 회원가입, 이메일 발송
- 외부 AI API
- PDF 생성
- 관리자 화면과 사용자 데이터 저장
- 의료·법률·투자 판단
- 384효 전체의 전문 해설

## 사용자 흐름

1. 첫 화면에서 “이런 거 믿지 마세요”라는 역설적 소개를 읽는다.
2. 현재 고민과 선택지 A/B를 입력한다.
3. 버튼을 눌러 동전 세 개를 여섯 차례 던진다.
4. 매 회 생성된 효가 아래에서 위로 쌓이는 모습을 본다.
5. 본괘와 변괘, 핵심 해석을 확인한다.
6. 현재 장애물, A/B 선택의 위험, 피할 행동, 현실 확인 질문을 읽는다.
7. 결과를 복사하거나 다시 시작한다.

## 해석 원칙

- 괘는 전통적인 3동전 방식으로 계산한다.
- AI가 미래를 안다고 주장하지 않는다.
- 결과는 “반드시”, “확실히” 같은 단정 대신 관점과 질문을 제시한다.
- 모든 해석은 실제 입력한 고민과 선택지를 문장에 포함한다.
- 결과 마지막에는 “이 괘를 보지 않았다면 어느 쪽을 선택했을까?”라는 자기점검 질문을 둔다.
- 위험 분야가 감지되면 전문가와 현실 정보를 우선하라는 경고를 표시한다.

## 화면 구성

### 시작

- 제목: 하지 말라고 했습니다
- 소개: 주역이 미래를 맞힌다는 보장은 없지만, 결과를 읽는 자신의 반응은 관찰할 수 있다는 설명
- 고민, 선택지 A, 선택지 B 입력란

### 동전 던지기

- 현재 횟수와 진행률
- 앞면·뒷면이 보이는 동전 3개
- 누적된 6개 효
- 중간에 입력값을 변경하지 못하도록 고정

### 결과

- 괘 이름과 번호
- 본괘·변괘 도식
- 한 문장 핵심
- 지금 막힌 이유
- A의 위험과 B의 위험
- 지금 할 행동과 피할 행동
- 현실 확인 질문
- 면책 안내, 결과 복사, 다시 하기

## 기술 구조

- 별도 폴더의 정적 HTML, CSS, JavaScript로 구성한다.
- 빌드 과정 없이 파일을 열거나 간단한 로컬 서버로 실행한다.
- 계산 로직, 괘 데이터, 화면 로직을 분리해 검증 가능하게 한다.
- 브라우저 저장소와 서버로 입력 내용을 보내지 않는다.

## 검증 기준

- 여섯 번의 동전 결과가 올바른 효 값으로 변환된다.
- 8개 기본괘 조합이 64괘 번호와 이름으로 정확히 매핑된다.
- 변효가 있을 때 해당 효가 반전된 변괘가 표시된다.
- 빈 입력, 동일한 A/B 선택지, 위험 분야 입력을 안전하게 처리한다.
- 모바일 화면에서 입력부터 결과까지 끊김 없이 완료된다.
- 결과 복사와 초기화가 동작한다.

## 향후 확장 조건

테스트 사용자가 결과를 끝까지 읽고 저장·공유 의사를 보일 때만 결제와 AI 맞춤 해석을 추가한다. 그 전에는 전문 해설 데이터나 384효 전체 구축에 투자하지 않는다.
