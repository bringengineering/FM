# 3D 설비지도 A안: 밝은 건축 모형

사용자가 밝은 건축 모형 A안을 선택했다. 이 문서는 적용 범위와 검증 기준을 정한다. 운영 배포와 디자인 변경은 분리한다.

## 목표

기존 CRM 안의 지도에서 건물은 차분하게, 설비와 선택 상태는 명확하게 보이도록 한다. 브라우저 비교 시안은 가상 건물을 그린 개념도이며 실제 형상이나 구현 결과를 보장하는 실측 도면이 아니다.

## 시각 변경

- 층판: 차가운 파란색 반투명 재질을 밝은 아이보리 계열로 바꾸고 층 가장자리 대비를 유지한다.
- 외벽: 현재 외벽 투명 토글을 유지한다. 투명 상태는 옅은 청회색 윤곽과 낮은 불투명도로 설비를 가리지 않는다.
- 배경: 밝은 회청색, 강한 검은 격자는 옅은 기준선으로 완화한다.
- 조명: 부드러운 환경광과 방향광으로 형태를 구분한다. 바닥 그림자는 장식용이며 실제 일조·음영 분석이 아니다. 무거운 후처리 효과는 추가하지 않는다.
- 설비: 기존 데이터 영역별 색상 의미와 종류별 형상을 유지한다. 선택 설비를 흰색으로 바꾸지 않고 기존 색상에 파란 선택 링·밝은 라벨로 구분한다.
- 연결: 추정 경로의 점선과 현장 확인 경로의 실선 의미를 유지한다. 선택 설비에 직접 연결된 경로만 대비를 높이고 나머지도 식별 가능하게 둔다.
- 라벨/도구: 밝은 카드와 짙은 글자, 명확한 포커스 표시. 좁은 화면의 버튼과 경고가 잘리지 않게 한다.

## 변경 경계

native/viewer.mjs 및 필요한 시각 보조 모듈, native/theme.css에 한정한다. 원본 upstream 모듈·라이선스는 보존한다. 고객·건물 ID·좌표·층수·배관 경유점·검증 수준·사진·점검 이력·IPC·DB Rules·저장 정책은 변경하지 않는다. 미확인 창문, 조경, 호실, 설비를 장식 목적으로 생성하지 않는다.

## 동작·오류 처리

회전·확대·층 선택·분리·레이어·선택·평면 편집은 기존과 동일하게 작동한다. 화면 표시만 바꿔서는 서버 저장이 발생하지 않는다. WebGL 실패 시 목록·상세 대체 화면과 기존 오류 처리를 유지한다. 추가한 재질·텍스처·도형은 재렌더/화면 종료 시 정리한다.

## 검증

색상·선택·경로 스타일 결정을 테스트 가능한 순수 설정/함수로 분리할 경우 이에 대한 회귀 테스트를 먼저 작성한다. 전체 CRM 및 원본 테스트, 3D 렌더링·선택·층 분리·메뉴 재진입, 1280px/390px 표시, WebGL 실패 대체 화면을 검증한다. 전후 데이터가 바뀌지 않았음을 확인한다. 시각 테스트에는 가상 자료만 사용한다.

## 반영 순서

이 설계 검토 → 구현 계획 → A안 구현 및 가상 화면 확인 → 검증용 EXE 재생성 → 운영 원격 변경 재확인 → 별도 배포 절차로 운영 CRM 및 새 지도 저장 규칙 반영. 기존 고객 자료를 임의 생성/수정하거나 운영 태그를 재사용하지 않는다.
