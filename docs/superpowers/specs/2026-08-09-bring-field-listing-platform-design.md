## 1. 목적

BRING 직원이 현장에서 건물과 공실 정보를 한 번 입력하고 사진·영상을 정해진 순서로 촬영하면 다음 결과가 자동으로 만들어지는 내부 업무 플랫폼을 구축한다.

1. 건물·호실·공실 정보가 중앙 데이터베이스에 저장된다.
2. 기존 BRING 원주 네이버 지도에 건물과 공실 상태가 표시된다.
3. 사진과 영상이 회사 Google Drive의 건물·호실·촬영일 폴더에 자동 정리된다.
4. 담당자가 당근과 네이버 부동산에 등록할 때 바로 사용할 수 있는 광고 자료 묶음이 생성된다.

1차 성공 기준은 직원이 현장 한 곳을 처음 등록해 촬영을 마친 뒤, 사무실 담당자가 별도의 파일명 변경이나 폴더 정리 없이 Drive 광고 묶음을 열어 매물 광고 입력에 바로 사용할 수 있는 것이다.

## 2. 제품 원칙

- 입력은 한 번만 하고 지도, Drive, 광고 자료에서 재사용한다.
- 건물 공통정보와 호실별 매물정보를 분리한다.
- 원본 사진·영상은 보존하고 광고용 선별본은 별도로 만든다.
- 출입 비밀번호, 열쇠 위치, 건물주 연락처와 내부 메모는 광고정보와 분리한다.
- 현장 통신이 끊겨도 입력과 촬영을 계속할 수 있어야 한다.
- 업로드 실패는 사용자에게 숨기지 않고 상태와 재시도 결과를 보여준다.
- 자동 광고 게시는 하지 않는다. 광고 담당자와 책임 공인중개사가 자료를 검토한 후 각 플랫폼에 등록한다.
- 체크리스트가 바뀌어도 기존 제출 기록이 깨지지 않아야 한다.

## 7. 촬영 경험

촬영 화면은 혼합형으로 구성한다.

- 기본 흐름에서는 앱이 다음 필수 촬영 구역을 안내한다.
- 숙련자는 전체 구역 목록을 열어 원하는 순서로 이동할 수 있다.
- 각 구역에는 권장 구도와 촬영 방향을 짧게 표시한다.
- 필수 촬영 슬롯과 추가 자유사진을 구분한다.
- 상태점검 항목에서 바로 증거사진을 연결할 수 있다.
- 촬영 완료율과 누락된 필수 컷을 실시간으로 보여준다.
- 광고 준비 완료 전 필수 정보와 필수 촬영 누락을 검사한다.

초기 필수 구역은 건물 외관, 도로·진입부, 주차장, 공동현관, 복도·계단, 분리수거장, 호실 전체구조, 창문·채광, 주방, 욕실, 옵션·수납, 보일러·설비, 수리 필요부위, 세로형 영상이다. 건물 공통사진은 같은 촬영 세션의 여러 호실 광고에서 재사용할 수 있다.

## 9. 시스템 구조

### 클라이언트

- 휴대전화와 PC에서 동작하는 설치형 PWA
- Google 계정 기반 Firebase Authentication
- 앱 셸과 최근 작업 캐시
- IndexedDB 기반 임시 초안과 미디어 업로드 대기열
- 재개 가능한 사진·영상 업로드

### Firebase

- 기존 BRING Firebase 프로젝트를 사용한다.
- Realtime Database에 건물, 호실, 매물, 방문, 체크리스트, 작업상태를 저장한다.
- Firebase Storage에 사진·영상 원본과 파생본을 안전하게 먼저 저장한다.
- 플랫폼 데이터는 기존 FM 데이터와 충돌하지 않도록 전용 루트 경로 아래에 둔다.

예상 경로:

```text
fieldPlatform/
  users/
  buildings/
  units/
  listings/
  visits/
  checklistTemplates/
  checklistSubmissions/
  media/
  adPackages/
  driveSyncJobs/
  auditLogs/
  secureAccess/
```

### Drive 동기화 서비스

- Firebase 업로드 완료 후 Drive 동기화 작업을 생성한다.
- 회사 계정 OAuth 권한은 서버의 비밀 저장소에서만 관리한다.
- 서버는 지정된 최상위 폴더 아래에 필요한 하위 폴더를 생성한다.
- 대용량 영상은 재개 가능한 업로드를 사용한다.
- 동일 작업의 재실행으로 파일이 중복되지 않도록 멱등 키를 사용한다.
- 완료 후 Drive 파일 ID와 링크를 미디어 레코드에 기록한다.

### 기존 네이버 지도

- 기존 유지보수 업체 데이터는 유지한다.
- 내부 로그인 후에만 보이는 건물, 공실, 관리건물 레이어를 추가한다.
- Firebase 데이터를 실시간 또는 명시적 새로고침으로 읽는다.
- 핀 상세에는 광고 가능 정보만 기본 표시한다.
- 건물주 연락처와 출입정보는 별도 권한 확인 후 전용 화면에서만 읽는다.

## 10. Google Drive 구조

지정된 `건물 사진` 폴더 아래에 다음 구조를 자동 생성한다.

```text
건물 사진/
  {건물관리번호}_{동명}_{건물명}/
    00_건물공통/
      외관/
      진입로_주차/
      공동현관_공용부/
    {호실}/
      {YYYY-MM-DD}_{촬영유형}/
        01_광고용_대표사진/
        02_전체원본사진/
        03_세로영상/
        04_당근_매물설명.txt
        05_네이버부동산_입력정보.txt
        06_현장체크리스트.pdf
    건물관리/
      {YYYY-MM-DD}_{점검유형}/
        점검사진/
        조치사진/
        점검표.pdf
```

폴더명과 파일명에는 Windows, Google Drive 및 광고 담당자의 사용성을 고려한 안전한 문자만 사용한다. 같은 날짜에 여러 번 방문하면 촬영 세션 번호를 붙여 덮어쓰지 않는다.

### 당근용

- 짧은 제목 후보
- 보증금, 월세, 관리비
- 구조, 옵션, 주차, 입주 가능일
- 입지와 장점 중심의 설명
- 주의사항과 확인 필요 항목
- 대표사진과 전체사진
- 세로영상

### 네이버 부동산용

- 입력 순서에 맞춘 구조화된 매물정보
- 보증금, 월세, 관리비와 포함 항목
- 층, 구조, 방향, 주차, 입주 가능일
- 옵션과 시설 상태
- 광고 설명 초안
- 대표사진과 전체사진

광고 패키지에는 건물주 연락처, 출입 비밀번호, 열쇠 위치, 내부 영업 메모, 촬영자의 개인 메모를 절대 포함하지 않는다.

## 12. 오프라인과 오류 처리

- 입력값은 작성 즉시 로컬 초안으로 저장한다.
- 네트워크가 없으면 사진·영상은 IndexedDB 대기열에 남긴다.
- 네트워크 복구 후 사용자가 앱을 열면 업로드를 자동 재개한다.
- 브라우저 제약으로 백그라운드 업로드가 중단될 수 있으므로 완료 전 앱을 다시 열어야 한다는 상태 안내를 제공한다.
- 업로드 상태는 대기, 업로드 중, Firebase 완료, Drive 동기화 중, 완료, 오류로 구분한다.
- 파일별 진행률과 남은 개수를 표시한다.
- 파일 해시와 촬영 슬롯 기반 중복 방지 키를 사용한다.
- Drive 권한 만료, 용량 부족, 파일명 충돌, 영상 제한 초과를 구분해 안내한다.
- 자동 재시도 후에도 실패하면 운영 대시보드에서 담당자가 재시도한다.
- 삭제는 보관함으로 이동하고 일정 기간 복구할 수 있게 한다.

## 13. 보안

- 로그인 가능 계정은 관리자 허용목록으로 제한한다.
- Firebase 규칙은 역할과 담당 배정에 따라 읽기·쓰기 범위를 제한한다.
- Storage 원본은 공개 URL로 두지 않는다.
- 미디어 조회에는 만료되는 접근 URL을 사용한다.
- Drive 최상위 폴더는 공개 공유하지 않는다.
- 회사 Google OAuth 토큰은 브라우저와 Firebase Database에 저장하지 않는다.
- 출입정보는 별도 데이터 경로와 별도 화면에서 다룬다.
- 광고 패키지 생성 시 허용 필드 목록 방식으로 데이터를 복사한다.
- 모든 중요 수정과 패키지 생성은 감사 로그에 기록한다.
- 직원 권한을 제거하면 즉시 신규 로그인과 데이터 조회가 차단되어야 한다.

## 14. 테스트와 승인 기준

### 기능 테스트

- 기존 건물 검색 및 중복 주소 경고
- 건물과 여러 호실 등록
- 체크리스트 자동저장과 템플릿 버전 보존
- 필수 촬영 누락 시 완료 차단
- 대표사진 선택과 순서 변경
- 광고 문구와 정보 파일 생성
- 지도 핀 생성·수정·상태 필터
- Drive 폴더명, 파일명 및 링크 저장

### 현장 테스트

- 아이폰 Safari, 안드로이드 Chrome, PC Chrome에서 로그인
- 홈 화면 설치 후 카메라 촬영
- 지하 또는 엘리베이터에서 오프라인 작성과 촬영
- 연결 복구 후 대기열 업로드
- 대용량 영상 전송 중 중단 후 재개
- 같은 촬영 세션의 중복 업로드 방지

### 보안 테스트

- 허용되지 않은 계정 로그인 차단
- 직원, 검토자, 관리자 권한 분리
- 광고 자료에서 민감정보 누락 확인
- 만료된 미디어 URL 접근 차단
- 직원 권한 회수 후 접근 차단

### 회귀 테스트

- 기존 FM 메인 화면 정상 동작
- 기존 유지보수 업체 지도 정상 동작
- 기존 Firebase 경로와 규칙 영향 없음
- 기존 Apps Script 민원·견적 자동화 영향 없음

## 15. 출시 방식

개발은 다음 순서로 진행한다.

1. 인증, 권한, 데이터 모델과 보안 규칙
2. 건물·호실·매물 등록
3. 체크리스트와 촬영 흐름
4. 오프라인 대기열과 Firebase Storage 업로드
5. Google Drive 폴더 및 파일 동기화
6. 기존 네이버 지도 연동
7. 광고 패키지 생성과 검토 화면
8. 현장 기기 테스트와 기존 FM 회귀 테스트

각 단계는 독립적으로 검증 가능해야 하며, 기존 `index.html`, `wonju-map.html`, Apps Script 자동화는 새 기능이 검증되기 전까지 현재 동작을 유지한다.
