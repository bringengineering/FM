# BRING CRM 고객 문서 발송센터 설계

## 목적

CRM에서 작성한 견적서와 작업 결과보고서를 고객에게 카카오 알림톡 또는 SMS로 바로 전달한다. 문서는 메시지에 직접 첨부하지 않고 회사 서버가 발급한 기간 제한 열람 링크로 전달하며, 발송 결과와 고객 열람 상태를 CRM 기록으로 남긴다.

## 사용자 흐름

1. 견적서 또는 결과보고서 화면에서 `고객에게 보내기`를 누른다.
2. 기존 고객을 선택하거나 현재 문서에 연결된 고객을 자동 선택한다.
3. 문서 종류, 수신자 이름, 전화번호, 발송 채널을 확인한다.
4. CRM이 PDF를 생성하고 서버에 보호 저장한 뒤 만료되는 열람 링크를 발급한다.
5. 기본값인 카카오 알림톡 또는 SMS를 선택하고 발송 문구를 미리 확인한다.
6. 사용자가 최종 `발송`을 눌러야 외부 전송이 실행된다.
7. 요청, 성공, 실패, 열람, 만료 상태를 고객 상세와 고객 메시지 이력에 표시한다.
8. 알림톡 발송이 실패하면 동일 문서 링크를 이용한 `SMS로 다시 보내기`를 제공한다.

## 화면 구성

기존 `고객 메시지` 메뉴에 `안내 메시지`와 `문서 발송` 탭을 둔다. 문서 화면에는 다음 항목을 제공한다.

- 문서 종류: 견적서 또는 결과보고서
- 연결 문서 및 고객
- 고객명과 전화번호
- 채널: 카카오 알림톡 기본, SMS 선택 가능
- 문서 링크 만료일
- 실제 발송될 메시지 미리보기
- 문서 PDF 미리보기
- 최종 발송 버튼
- 발송·열람 이력 표

견적서와 결과보고서 화면에도 `고객에게 보내기` 진입 버튼을 두되, 실제 외부 전송은 문서 발송 확인 화면에서만 실행한다.

## 문서와 링크 보안

- PDF 원본과 메시지 공급자 비밀키는 데스크톱 EXE, GitHub 저장소, Firebase 클라이언트 데이터에 넣지 않는다.
- 회사 중계 서버가 문서를 보호 저장하고 추측할 수 없는 단회성 토큰 링크를 발급한다.
- 링크는 기본 14일 후 만료하며 발송 전에 만료일을 줄일 수 있다.
- 문서 접근 로그에는 문서 ID, 시간, 성공 여부만 저장하고 불필요한 기기정보는 수집하지 않는다.
- 문서를 교체하거나 발송을 취소하면 기존 링크를 즉시 폐기할 수 있다.
- 권한 있는 CRM 사용자만 링크 발급, 발송, 폐기할 수 있다.

## 메시지 정책

- 견적서와 요청된 결과보고서 전달은 정보성 메시지로 분류한다.
- 별도 영업 문구를 추가하는 경우 기존 CRM의 광고성 수신 동의와 수신거부 정책을 그대로 적용한다.
- 알림톡은 승인된 문서 전달 템플릿만 사용하며 자유 문구가 필요한 경우 SMS 미리보기로 전환한다.
- 모든 메시지는 회사명, 문서명, 고객명, 열람 링크, 링크 만료일을 포함한다.
- 수신번호와 문서가 일치하는지 최종 확인하기 전에는 발송할 수 없다.

## 서버 경계와 데이터 흐름

CRM은 문서 생성 요청에 문서 종류, 연결 고객 ID, 연결 업무 ID와 PDF 바이트만 전달한다. 회사 중계 서버는 인증과 권한을 다시 확인하고 문서를 저장한 뒤 문서 ID와 만료 링크를 반환한다. CRM이 채널과 승인 템플릿 변수를 서버에 보내면 서버가 카카오 또는 SMS 공급자 API를 호출한다.

CRM 서버에는 다음 발송 레코드를 저장한다.

- 발송 ID, 문서 ID, 문서 종류와 버전
- 고객 ID, 수신번호의 마스킹 표시값
- 채널, 템플릿 ID와 버전
- 요청자, 요청 시각, 공급자 메시지 ID
- 요청·성공·실패·열람·만료·폐기 상태와 상태 시각
- 실패 코드와 재시도 원인

비밀키, 전체 공급자 응답, 공개 문서 URL은 일반 CRM 데이터에 저장하지 않는다.

## 오류와 재시도

- PDF 생성 실패: 발송하지 않고 문서 수정 화면으로 돌아간다.
- 링크 발급 실패: 외부 메시지를 전송하지 않는다.
- 알림톡 실패: 실패 원인을 표시하고 사용자가 확인한 후 SMS 재전송을 허용한다.
- SMS 실패: 번호와 공급자 상태를 표시하되 자동 반복 발송하지 않는다.
- 중복 클릭: 발송 요청 키로 중복 전송을 차단한다.
- 서버 상태 불명: 성공으로 표시하지 않고 조회를 통해 최종 상태를 재확인한다.

## 단계별 적용

1. 문서 발송 UI, 발송 레코드 모델, 미리보기, 모의 공급자 테스트를 구축한다.
2. 보호 문서 저장과 기간 제한 링크 발급을 연결한다.
3. 카카오 알림톡 승인 템플릿과 공급자 API를 연결한다.
4. SMS 공급자 API와 알림톡 실패 후 수동 대체 발송을 연결한다.
5. 공개 환경에서 링크 만료, 발송 상태, 중복 차단, 업데이트 배포를 검증한다.

공급자 계정이나 승인 템플릿이 준비되지 않은 환경에서도 UI와 기록 기능은 동작하되 실제 발송 버튼은 `연동 준비 필요` 상태로 안전하게 비활성화한다.

## 검증 기준

- 사용자가 확인 버튼을 누르기 전 외부 메시지가 전송되지 않는다.
- 견적서와 결과보고서가 각각 올바른 고객에게 연결된다.
- 카카오와 SMS 발송 결과가 CRM 이력에 동일한 상태 모델로 기록된다.
- 알림톡 실패 후 SMS 재전송이 새 이력으로 남고 중복 발송되지 않는다.
- 만료 또는 폐기된 링크로 문서를 열 수 없다.
- 문서·고객·전화번호 입력값과 공급자 오류가 화면 출력 시 안전하게 처리된다.
- 비밀키가 저장소, EXE, 렌더러, 로그에 포함되지 않는다.
- 기존 고객 메시지, 견적서, 작업관리 및 결과보고서 기능의 회귀 테스트가 통과한다.

## 이번 범위에서 제외

- 메시지에 PDF 바이너리를 직접 첨부하는 MMS 발송
- 고객이 문서를 수정하거나 전자서명하는 기능
- 광고 캠페인 일괄 발송
- 실패한 메시지의 무제한 자동 재전송
