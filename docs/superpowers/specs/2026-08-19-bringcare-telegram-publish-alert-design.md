# 브링케어 블로그 텔레그램 발행 알림 설계

작성일: 2026-08-19  
상태: 사용자 설계 승인 완료

## 1. 목적

브링케어 네이버 블로그 자동화가 원고 조사·작성·검증·편집기 입력을 마치면 텔레그램으로 즉시 알린다. 사용자는 알림의 버튼으로 기존 ChatGPT 대화를 열고 `발행`이라고 입력한다. 발행 성공 또는 중단 결과도 같은 텔레그램 대화로 전달한다.

완전 무인 공개 발행은 범위에서 제외한다. 네이버 공개 발행은 사용자가 ChatGPT 대화에서 실행 시점에 승인한 뒤 진행한다.

## 2. 사용자 흐름

1. 기존 3시간 자동화가 시장조사, 주제 선정, 공식 근거 확인, 사진 준비, 원고 작성과 검증을 수행한다.
2. 검증을 통과한 원고를 네이버 편집기에 입력하고 발행 직전 상태로 보존한다.
3. 알림 모듈이 텔레그램으로 제목, 유형, 검증 결과, 카테고리와 현재 단계를 전송한다.
4. 메시지에는 `ChatGPT에서 발행 승인` 버튼을 표시한다.
5. 사용자가 버튼을 누르면 설정된 ChatGPT 대화 URL이 열린다.
6. 사용자가 해당 대화에 `발행`이라고 입력한다.
7. 발행 작업은 공개 글을 검수하고 원장 상태를 갱신한다.
8. 알림 모듈이 최종 제목과 공개 URL을 텔레그램으로 전송한다.

## 3. 범위

### 포함

- Telegram Bot API 연결 설정
- Windows에서 토큰을 비공개로 입력하는 설정 도구
- 현재 Windows 사용자에게 묶인 암호화 저장
- `getMe`를 이용한 봇 연결 검증
- `/start` 이후 `getUpdates`를 이용한 개인 Chat ID 확인
- 발행 준비, 검증 실패, 로그인 만료, CAPTCHA, 편집기 오류, 발행 성공 알림
- ChatGPT 승인 대화로 이동하는 인라인 버튼
- 동일 장애 24시간 중복 알림 방지
- 텔레그램 장애 시 블로그 원고와 자산 보존
- 테스트와 운영 안내

### 제외

- 텔레그램 버튼만으로 네이버에 즉시 공개 발행
- 새 Telegram Bot 생성 자동화
- 네이버 로그인 정보, 비밀번호 또는 인증번호 저장
- CAPTCHA 우회 또는 자동 해결
- 네이버 비공식 글쓰기 API 구축
- 텔레그램 그룹이나 불특정 사용자에게 알림 전송

## 4. 구성요소

### 4.1 `telegram-setup.ps1`

대화형 설정 도구다.

- 사용자가 새 Bot Token을 로컬 프롬프트에 직접 입력한다.
- 입력값은 터미널에 다시 표시하지 않는다.
- 토큰은 Windows DPAPI로 현재 사용자 범위에서 암호화한다.
- 암호문은 Git 추적 대상이 아닌 사용자 전용 설정 경로에 저장한다.
- Telegram `getMe` 호출로 토큰의 유효성을 확인한다.
- 사용자가 봇에 `/start`를 보낸 뒤 `getUpdates`에서 개인 채팅 후보를 찾는다.
- 사용자가 확인한 Chat ID만 저장한다.
- ChatGPT 승인 대화 URL을 입력받아 형식과 HTTPS 여부를 확인한다.
- 마지막으로 시험 알림을 한 번 전송한다.

앞서 대화에 노출된 토큰은 사용하지 않는다. 사용자는 BotFather의 `/token` 명령으로 새 토큰을 발급해야 한다.

### 4.2 `telegram_notifier.py`

알림 전송의 단일 진입점이다.

- 설정을 읽고 DPAPI 암호문을 현재 사용자 권한으로 복호화한다.
- 허용된 Chat ID 한 곳으로만 메시지를 보낸다.
- Markdown 또는 HTML 특수문자를 안전하게 이스케이프한다.
- 제목, 상태, 다음 행동과 선택적 공개 URL만 메시지에 포함한다.
- Bot Token과 내부 파일 경로는 로그, 예외, 상태 파일에 출력하지 않는다.
- 네트워크 오류와 Telegram API 오류를 구분해 반환한다.

### 4.3 `telegram-state.json`

비밀값이 없는 운영 상태 파일이다.

- 마지막 알림 식별자
- 알림 종류
- 글 식별자와 제목
- 전송 시각
- 상태 해시
- 마지막 성공 또는 실패 결과
- 24시간 중복 알림 만료 시각

Bot Token, 원문 메시지 전체, 사용자 개인정보는 저장하지 않는다.

### 4.4 자동화 연결 어댑터

기존 `blog/automation/backlog.md`와 `alerts.md`를 읽어 아래 이벤트를 알림 모듈에 전달한다.

- `ready_to_publish`
- `validation_failed`
- `source_or_image_missing`
- `naver_login_required`
- `captcha_detected`
- `editor_changed`
- `publish_succeeded`
- `publish_verification_failed`

알림 실패는 원고 상태를 되돌리거나 폐기하지 않는다. 알림 실패 기록만 남기고 다음 회차에서 제한된 횟수로 재시도한다.

## 5. 메시지 계약

### 발행 준비

```text
📝 브링케어 블로그 발행 준비 완료

제목
{title}

유형
{post_type}

검증
✅ 브리프
✅ 원고
✅ 개인정보
✅ 이미지

카테고리
{category}

현재 단계
네이버 발행 직전
```

인라인 버튼:

- `ChatGPT에서 발행 승인` → 설정된 승인 대화 URL

### 발행 성공

```text
✅ 브링케어 블로그 발행 완료

{title}
{public_url}
```

### 행동이 필요한 장애

```text
⚠️ 브링케어 블로그 자동화 확인 필요

글
{title}

중단 단계
{stage}

필요한 조치
{action}

재개 지점
{resume_point}
```

오류 전문, Bot Token, 상세 로컬 경로, 네이버 인증정보는 전송하지 않는다.

## 6. 보안 설계

- 노출된 기존 Bot Token은 폐기하고 새 토큰만 사용한다.
- 새 토큰은 ChatGPT, Git, 블로그 원고, Markdown 원장에 입력하지 않는다.
- 설정 도구는 토큰을 비공개 프롬프트로 받는다.
- 토큰은 Windows DPAPI 현재 사용자 범위로 암호화한다.
- 암호문과 설정 파일은 사용자 전용 디렉터리에 보관한다.
- 저장 경로는 `.gitignore`와 별도 비밀정보 검사 대상에 포함한다.
- Chat ID는 설치 시 확인한 한 개의 개인 대화만 허용한다.
- ChatGPT 승인 URL은 HTTPS URL만 허용한다.
- 로그와 예외 문자열은 토큰 패턴과 민감한 쿼리 문자열을 삭제한 뒤 기록한다.
- 테스트는 실제 토큰이나 실제 Telegram API에 의존하지 않는다.

## 7. 오류 처리

- 유효하지 않은 토큰: 설정을 저장하지 않고 새 토큰 입력을 요청한다.
- `/start` 미전송: Chat ID를 추측하지 않고 안내 후 중단한다.
- 여러 개인 채팅 후보: 사용자가 대상 ID를 명시적으로 선택한다.
- Telegram 시간 초과: 지수형 재시도 후 실패 상태를 기록한다.
- Telegram 401: 토큰 재발급 필요 상태로 표시하고 반복 호출을 멈춘다.
- Telegram 403: 사용자가 봇을 차단했거나 대화를 시작하지 않은 것으로 안내한다.
- 알림 실패: 네이버 원고와 발행 대기 상태를 유지한다.
- 승인 URL 미설정: 버튼 대신 `ChatGPT에서 발행이라고 입력하세요`라는 안내를 전송한다.
- 네이버 발행 실패: 공개 성공 알림을 보내지 않고 행동 가능한 장애 알림만 보낸다.

## 8. 중복 방지

알림 키는 `event_type + post_id + normalized_status`의 해시로 만든다.

- 같은 장애와 같은 상태는 24시간 동안 한 번만 전송한다.
- 원고가 수정되거나 단계가 바뀌면 새 알림으로 취급한다.
- 발행 성공은 글마다 한 번만 전송한다.
- 실패 후 성공으로 바뀌면 즉시 성공 알림을 보낸다.

## 9. 테스트 전략

- 설정 스크립트가 토큰을 화면이나 로그에 출력하지 않는지 확인
- 잘못된 토큰에서 설정 파일이 생성되지 않는지 확인
- Chat ID가 없거나 여러 개인 경우 추측하지 않는지 확인
- 승인 URL이 HTTP 또는 잘못된 형식이면 거부하는지 확인
- 메시지 특수문자 이스케이프 확인
- 동일 장애 24시간 중복 차단 확인
- 상태 변경 시 새 알림 허용 확인
- 401, 403, 429, 시간 초과 처리 확인
- 전송 실패 시 원고 및 backlog가 보존되는지 확인
- 발행 성공 메시지에 제목과 공개 URL만 포함되는지 확인
- 로그, 상태 파일, 테스트 출력에 토큰 패턴이 없는지 확인

실제 Telegram 연결 시험은 사용자가 로컬에서 새 토큰을 입력한 뒤 한 번만 실행한다.

## 10. 완료 기준

- 사용자가 새 토큰을 채팅에 노출하지 않고 설정을 마칠 수 있다.
- 시험 알림이 등록된 개인 Telegram 대화에 도착한다.
- 검증 통과 원고가 생기면 발행 준비 알림이 한 번 전송된다.
- 버튼을 누르면 설정된 ChatGPT 승인 대화가 열린다.
- 사용자가 `발행`한 뒤 성공 URL이 Telegram에 도착한다.
- 로그인·CAPTCHA·검증 실패 시 원인과 필요한 조치가 전달된다.
- 같은 장애의 반복 알림이 24시간 동안 차단된다.
- 토큰이 Git, 로그, 상태 파일, 원고 어디에도 나타나지 않는다.

## 11. 사용자 설정 절차

1. BotFather에서 `/token`을 실행해 노출된 기존 토큰을 교체한다.
2. `@bringcare_blog_alert_bot`에 `/start`와 확인 메시지를 보낸다.
3. 제공될 `telegram-setup.ps1`을 실행한다.
4. 표시되지 않는 입력란에 새 토큰을 직접 입력한다.
5. 발견된 개인 Chat ID와 승인 대화 URL을 확인한다.
6. 시험 알림 수신을 확인한다.
7. 이후 새 토큰을 채팅이나 문서에 복사하지 않는다.

## 12. 운영상 한계

- ChatGPT 예약 작업은 외부 웹훅을 직접 받지 않으므로 Telegram 버튼 자체가 이 자동화를 즉시 실행하지 않는다.
- 버튼은 승인 대화를 여는 역할만 한다.
- 네이버 로그인 만료, CAPTCHA, 편집기 변경 또는 정책 경고가 있으면 발행을 중단한다.
- PC와 필요한 브라우저 세션이 실행 가능해야 한다.
- 검색·홈피드 노출, 상담, 수익은 보장하지 않는다.
