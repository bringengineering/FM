# CRM 즉시 서버 저장 설계

## 목적

CRM에서 사용자가 고객·건물·상담·할 일 등 업무 정보를 저장하면, 회사 서버의 저장 성공을 확인한 뒤에만 완료로 처리한다. 로컬 캐시나 예약된 동기화만으로 성공 메시지를 표시하지 않는다.

이 설계는 `2026-09-02-crm-customer-auto-building-design.md`의 신규 고객 등록 흐름을 대체한다. 고객명만 입력한 경우 고객은 서버에 즉시 저장하되 건물은 자동 생성하지 않는다. 기존 건물을 명시적으로 선택했을 때만 연결한다.

## 확정 동작

1. 저장 버튼을 누르면 해당 변경을 즉시 서버 저장 큐에 넣는다.
2. 동시에 여러 저장이 발생하면 입력 순서대로 직렬 처리한다.
3. 서버가 성공 응답을 반환하고 최신 서버 데이터에 변경 내용이 존재하는 것을 확인한 뒤 모달·드로어를 닫고 성공 메시지를 표시한다.
4. 서버 저장 실패 또는 오프라인 대기 상태이면 성공으로 처리하지 않는다.
5. 실패 시 입력 화면과 사용자가 작성한 값을 유지하고, 원인과 재시도 동작을 제공한다.
6. 서버 저장 성공 후 기존 실시간 동기화 경로를 통해 다른 직원 PC에도 반영한다.

## 고객 등록

- 고객명은 필수다.
- 기존 건물 선택은 선택사항이다.
- 건물을 선택하지 않으면 고객만 서버에 등록한다.
- 기존 건물을 선택하면 고객 생성과 건물 연결 변경을 하나의 저장 요청에 포함한다.
- 고객 등록 과정에서 새 건물을 만들거나 별도 건물 서버 API를 호출하지 않는다.
- 서버 성공 확인 전에는 고객 상세 화면으로 이동하지 않는다.

## 저장 조정기

렌더러에 하나의 즉시 저장 조정기를 둔다.

- 예약 저장과 즉시 저장이 같은 큐와 동일한 서버 API를 사용한다.
- 현재 저장이 진행 중이면 다음 스냅샷을 덮어쓰지 않고 후속 저장으로 병합한다.
- 즉시 저장 호출자는 자신의 변경이 포함된 서버 응답까지 기다린다.
- `pending` 응답은 성공이 아니라 재시도 가능한 실패로 반환한다.
- 세션이 변경되면 이전 사용자의 저장 결과를 현재 화면에 반영하지 않는다.

기존 자동 저장은 입력 보조용으로 유지할 수 있지만, 명시적 저장 버튼의 성공 판단에는 사용하지 않는다.

## 오류 처리

- 저장 실패 시 모달을 닫지 않는다.
- 버튼의 중복 클릭을 막고 저장 중 상태를 표시한다.
- 실패 메시지는 서버 연결, 권한, 세션 변경, 충돌을 구분해 안전한 한국어로 표시한다.
- 입력값은 현재 렌더러 상태에 남겨 사용자가 수정하거나 재시도할 수 있어야 한다.
- 서버에 반영되지 않은 데이터를 목록에 확정 데이터처럼 노출하지 않는다.

## 적용 범위

우선 공통 저장 경로를 사용하는 고객·상담·할 일·계약·설정 등 명시적 저장 폼에 적용한다. 이미 별도 CAS 또는 canonical API를 사용하는 건물·호실·작업 일정은 각 전용 API의 성공 응답을 그대로 기준으로 삼고 일반 저장 경로로 되돌리지 않는다.

## 검증

- 저장 진행 중 신규 저장을 제출해도 두 번째 변경이 서버에 반영되는 회귀 테스트
- `pending` 또는 오류 응답에서 화면이 닫히거나 성공 메시지가 표시되지 않는 테스트
- 신규 고객을 건물 없이 서버에 저장하는 테스트
- 기존 건물을 선택한 신규 고객의 연결 정보가 한 번에 저장되는 테스트
- 전체 데스크톱 테스트, 로컬 smoke, Windows 빌드
- GitHub CI, 릴리스 자산 3종, 자동 업데이트 채널 probe

## 제외 범위

- Firebase 프로젝트·Rules·Functions 변경
- 새 건물 자동 생성
- 로컬 전용 성공 처리
- 기존 현진님 작업 데이터나 다른 기능 구조 변경
