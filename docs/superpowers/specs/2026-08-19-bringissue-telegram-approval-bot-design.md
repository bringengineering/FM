# 브링이슈 텔레그램 비공개 승인 봇 설계

## 목적

Marketing OS의 영상 제작 결과를 대표자 한 명에게 텔레그램으로 전달하고, 모바일에서 검토·승인·예약·수정·보류할 수 있게 한다. 영상 제작은 기존 Windows 자동화가 담당하고 텔레그램은 승인 리모컨과 오류·성과 보고 채널로만 사용한다.

## 범위

첫 버전은 다음 기능만 제공한다.

1. 제작 완료 영상과 QC 요약 전송
2. 영상 미리보기 또는 로컬/YouTube 비공개 링크 제공
3. `공개 승인`, `내일 12시 예약`, `수정 요청`, `보류` 버튼
4. 승인된 영상의 YouTube 업로드 또는 예약 실행
5. 제작·업로드 오류 알림
6. 업로드 후 1·24·48·72시간 성과 보고
7. 대표자의 한국어 자연어 메시지로 조회·수정 요청·업로드·예약 처리

소재 TOP 20 선택, 신규 영상 제작 지시, 팀원 권한, 결제, 클라우드 파일 저장은 후속 버전으로 미룬다. 초기 자연어 범위는 기존 작업의 조회·수정 요청·업로드·예약에 한정한다.

## 사용자와 권한

- 봇 관리자는 대표자 Telegram 사용자 ID 한 명이다.
- 허용 ID가 아닌 사용자의 메시지와 버튼 요청은 실행하지 않고 보안 로그만 남긴다.
- `/start`는 사용자 ID를 표시하되 승인되지 않은 사용자에게 제작 정보나 파일을 공개하지 않는다.
- 공개, 예약, 삭제, 재업로드는 관리자 버튼 요청만 허용한다.
- 동일 버튼 요청은 작업 ID와 상태를 확인해 한 번만 실행한다.

## 구성 요소

### Telegram Bot Adapter

Telegram Bot API의 메시지 수신, 영상 전송, 인라인 버튼, 콜백 응답을 담당한다. 제작·YouTube 로직을 직접 포함하지 않는다.

### Approval Service

관리자 ID, 작업 상태, 버튼 유효기간, 중복 실행 여부를 검증한다. 승인 작업은 `pending → approved → executing → completed/failed` 상태로 기록한다.

### Natural Language Command Router

대표자의 한국어 메시지를 `조회`, `수정 요청`, `비공개 업로드`, `예약 공개`, `확인`, `취소`, `지원하지 않음` 중 하나로 분류한다. 영상은 작업 ID·제목·브랜드 별칭으로 찾는다. 명령이 둘 이상의 작업이나 시각으로 해석되면 실행하지 않고 한 가지 확인 질문만 한다. 소재 추천과 신규 제작은 초기 버전에서 `지원하지 않음`으로 안내한다.

조회와 수정 요청 저장은 즉시 처리한다. 비공개 업로드·공개·예약·재업로드처럼 외부 상태를 바꾸는 명령은 실행 요약과 확인 코드를 만든 뒤 `진행해`, `승인`, `ㅇㅇ` 같은 확인 답변을 받아야 실행한다. 확인은 같은 관리자·같은 채팅·같은 작업에 대해 10분 동안만 유효하다.

### Production Bridge

현재 `automation/` 제작 스크립트를 호출하고 결과 영상, 메타데이터, QC 결과를 표준 작업 객체로 변환한다. 실패 시 중단 지점과 로그 경로를 반환한다.

### YouTube Bridge

기존 YouTube 업로더를 사용한다. 기본 업로드는 비공개이며, 예약 공개는 별도 확장 OAuth 권한으로 수행한다. 공개 시간은 KST로 입력하고 API에는 시간대가 포함된 ISO 8601 형식으로 전달한다.

### Local State Store

첫 버전은 SQLite를 사용한다. 작업 ID, 영상 경로, SHA-256, 상태, 승인자 ID, 버튼 실행 시각, YouTube 영상 ID, 예약 시각, 오류를 저장한다.

## 데이터 흐름

1. 영상 제작과 자동 QC가 완료된다.
2. Production Bridge가 작업 레코드를 생성한다.
3. 봇이 제목, 길이, 음량, 사실·미디어 QC, 비용, 영상을 관리자에게 보낸다.
4. 관리자가 버튼을 누른다.
5. 또는 관리자가 자연어 명령을 보내고, 위험 작업이면 봇의 실행 요약에 자연어로 확인한다.
6. Approval Service가 사용자 ID, 작업 상태, 영상 해시와 확인 유효기간을 재검증한다.
7. 승인된 작업만 YouTube Bridge로 전달된다.
8. 성공 시 영상 ID와 공개/예약 상태를 텔레그램으로 보고한다.
9. 성과 수집기가 지정 시점에 분석 결과를 보고한다.

## 메시지 규격

제작 완료 메시지는 다음 정보를 포함한다.

- 작업 ID와 제목
- 영상 길이와 화면 수
- 통합 음량과 최대 피크
- 자막·화면·무음·저작권·사실 검증 상태
- Typecast 등 실제 사용 비용
- YouTube 공개 예정 슬롯
- 미리보기 영상

버튼은 `공개 승인`, `내일 12시 예약`, `수정 요청`, `보류`만 제공한다. `영상 보기`는 영상 첨부 또는 링크로 대체한다.

버튼은 빠른 입력 수단으로 남겨두되 필수는 아니다. 같은 작업은 다음과 같은 자연어로도 처리한다.

- `후버 영상 상태 알려줘`
- `후버 결말을 더 짧고 웃기게 수정해줘`
- `후버 영상 비공개로 올려줘`
- `후버 내일 낮 12시에 예약해줘`
- `ㅇㅇ 진행해`
- `취소`

## 수정 요청

`수정 요청`을 누르면 봇이 한 번의 텍스트 답변을 기다린다. 답변은 작업 ID와 연결해 저장하며 자동으로 영상을 덮어쓰지 않는다. 수정본은 새 버전 번호와 새 해시를 만들고 다시 승인을 요청한다.

## 오류 처리

- Telegram 전송 실패: 지수 백오프로 재시도하고 로컬 로그 유지
- 잘못된 관리자 ID: 실행 거부와 보안 로그
- 만료 또는 중복 버튼: 현재 상태 안내 후 실행하지 않음
- 불명확한 자연어: 추측해 실행하지 않고 작업 또는 시각을 한 번만 질문
- 확인 만료: 실행하지 않고 새 실행 요약을 요청하도록 안내
- 영상 파일 변경: 해시 불일치로 승인 취소
- YouTube 인증 실패: 비공개 영상과 작업 상태 유지, 재인증 요청
- 업로드 중단: 재개 가능한 업로드 세션 사용
- QC 실패: 승인 버튼을 표시하지 않고 실패 항목만 보고

## 보안

- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_USER_ID`는 Windows 사용자 환경 변수에 저장한다.
- 토큰, OAuth 토큰, 연락처는 Git·로그·텔레그램 메시지에 출력하지 않는다.
- 봇 토큰이 노출되면 BotFather에서 즉시 폐기하고 새 토큰으로 교체한다.
- GitHub에는 `.env.example`의 변수 이름만 저장하고 실제 값은 저장하지 않는다.
- 관리자 ID 검증은 모든 명령과 콜백에서 공통 미들웨어로 수행한다.
- 자연어 원문에는 토큰이나 OAuth 값을 입력하지 않도록 안내하고, 감지 시 저장·실행하지 않는다.

## 테스트

- 허용·비허용 사용자 ID 테스트
- 중복 버튼과 만료 버튼 테스트
- 영상 해시 변경 차단 테스트
- QC 실패 작업의 승인 버튼 미표시 테스트
- 비공개 업로드 성공·실패 테스트
- 예약 시간대 변환 테스트
- Telegram API와 YouTube API는 테스트에서 가짜 클라이언트로 대체
- 자연어 의도·영상 별칭·한국어 상대시간·확인·취소·불명확성 테스트
- 자연어 조회는 즉시 실행되고 업로드·예약은 확인 전 실행되지 않는지 테스트
- 실제 공개 테스트는 별도 테스트 영상과 비공개 상태로 먼저 수행

## 완료 기준

1. 대표자 계정만 봇을 사용할 수 있다.
2. 완성 영상과 QC 결과가 자동으로 도착한다.
3. 승인 버튼 한 번으로 비공개 업로드 또는 예약 공개가 실행된다.
4. 중복 실행과 파일 변경이 차단된다.
5. 토큰이 코드·로그·Git에 남지 않는다.
6. 업로드 결과와 오류가 텔레그램으로 돌아온다.
7. 후버편을 테스트 작업으로 전송하고 비공개 업로드 상태를 조회할 수 있다.
8. 대표자가 버튼 없이 자연어로 후버 상태 조회, 수정 요청 저장, 예약 실행을 완료할 수 있다.
