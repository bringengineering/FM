# BRING CARE 건물관리 제안서 신청 영역 설계

## 목적

건물관리 광고페이지 방문자가 서비스 내용을 충분히 확인한 뒤 연락처를 남기고, BRING CARE 제안서를 즉시 내려받을 수 있게 한다. 신청 정보는 기존 마케팅 리드 전송 경로를 통해 CRM에 `건물관리 제안서 요청`으로 구분해 저장한다.

## 선택한 방향

추천안인 `신청 완료 후 즉시 다운로드` 방식을 적용한다.

- 공개 다운로드 버튼만 두는 방식보다 건물주 리드를 확보할 수 있다.
- 이메일 발송을 추가하지 않아 별도 메일 서버·발송 실패·스팸함 문제를 만들지 않는다.
- 신청 완료 직후 같은 화면에서 다운로드를 제공해 고객이 기다리지 않도록 한다.
- CRM 장애 시에는 기존 전화 상담과 신청 내용 복사 대안을 제공한다.

## 배치

- 건물관리 페이지의 기업 인증·수상·교육 이력 다음, 최종 상담 영역 바로 앞에 배치한다.
- 섹션 ID는 `building-care-proposal`로 한다.
- 상단이나 모바일 고정 버튼에서 `무료 제안서 받기`를 눌렀을 때 이 영역으로 이동할 수 있게 한다.

## 화면 구성

### 왼쪽: 제안서 안내

- PDF 첫 페이지를 실제 원본에서 렌더링한 표지 미리보기
- 제목: `건물관리 제안서를 받아보세요`
- 설명: `서비스 범위·입퇴실 통합관리·가격과 운영방식을 한 번에 확인하세요.`
- 보조 정보: `BRING CARE 건물관리 제안서 · 총 18페이지 · PDF`
- 포함 내용 요약:
  - 6대 건물관리 서비스
  - 입·퇴실 통합관리 프로세스
  - 관리 범위와 가격
  - 기업 인증과 운영 체계

### 오른쪽: 신청 폼

- 이름: 필수
- 연락처: 필수, `010-0000-0000` 형식
- 건물 주소: 필수
- 개인정보 저장 및 연락 동의: 필수
- 제출 버튼: `무료 제안서 받기`
- 서비스 값: `건물관리 제안서 요청`
- 유입 경로: `/building-care#building-care-proposal`
- 고객 유형: `building_owner`
- 필요한 상담 내용: `BRING CARE 건물관리 제안서 요청`
- 건물 정보: 비워서 전송
- UTM 정보: 현재 페이지 URL에서 기존 방식으로 저장

## 신청 완료 상태

- 성공하면 페이지 이동 없이 같은 카드 안에서 완료 상태로 바뀐다.
- 제목: `제안서 신청이 완료되었습니다.`
- 안내: `아래 버튼을 눌러 BRING CARE 건물관리 제안서를 확인하세요.`
- 버튼: `제안서 PDF 다운로드`
- 다운로드 파일명: `BRING_CARE_건물관리_제안서.pdf`
- 실제 파일 경로: `/downloads/bring-care-building-management-proposal.pdf`
- 새 창이 아닌 브라우저 다운로드로 제공한다.

## 실패 처리

- CRM 전송이 실패하면 다운로드 버튼을 열지 않는다.
- 오류 메시지와 `전화 상담 010-6566-3603`, `신청 내용 복사` 버튼을 표시한다.
- 재전송 중 중복 제출을 막는다.

## 시각 디자인

- 현재 건물관리 페이지의 연한 회청색 배경, 흰색 입체 카드, BRING 블루 포인트를 유지한다.
- 표지 미리보기는 카드 안에서 잘리지 않게 `object-fit: contain`으로 표시한다.
- PC는 제안서 미리보기와 폼의 2열, 모바일은 안내·폼 순서의 1열로 전환한다.
- 입력 영역은 토스형 큰 라벨·충분한 높이·명확한 포커스 테두리를 사용한다.
- 모바일 하단 고정 CTA는 기존 `30초 견적`을 방해하지 않도록 별도 버튼을 추가하지 않고, 페이지 내부 CTA만 사용한다.

## 원본 자산

- 원본 PDF: `H:/내 드라이브/브링 케어/BRING CARE/서비스 소개서(제안서)/브링케어 제안서.pdf`
- 원본은 수정하지 않는다.
- 배포용 PDF는 영문 파일명으로 복사한다.
- 표지 이미지는 원본 PDF 첫 페이지를 PNG 또는 WebP로 렌더링해 사용한다.

## 검증 기준

- 제안서 신청 영역이 기업 인증 다음, 최종 상담 앞에 노출된다.
- 필수 정보와 동의가 없으면 CRM 전송이 발생하지 않는다.
- 성공 시 CRM에 지정된 서비스·경로·고객 유형으로 한 번만 저장된다.
- 성공 후 다운로드 링크가 나타나고 실제 PDF가 200 응답으로 내려받아진다.
- 원본과 배포 PDF의 페이지 수가 모두 18페이지다.
- PC와 390px 모바일에서 가로 넘침, 표지 잘림, 폼 겹침이 없다.
- 전체 랜딩 테스트, 프로덕션 빌드, 정적 내보내기와 Firebase 배포를 통과한다.
