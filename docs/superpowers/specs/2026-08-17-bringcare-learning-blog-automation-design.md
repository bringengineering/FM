# 브링케어 학습형 네이버 블로그 자동화 설계

작성일: 2026-08-17  
상태: 사용자 승인 설계안(C안)  
적용 범위: 주제 조사, 콘텐츠 제작, 이미지 확보, 검증, 네이버 발행, 장애 알림, 성과 수집, 다음 주제 학습, 매뉴얼 개정 후보 관리

## 1. 목적

브링케어 블로그 자동화를 단순 반복 발행이 아니라 다음의 폐쇄형 운영 루프로 만든다.

`후보 조사 → 주제 승인 → 근거·이미지 확보 → 작성 → 검증 → 발행 → 공개 검수 → 성과 수집 → 원인 진단 → 다음 후보 점수 반영 → 매뉴얼 개정 후보 생성`

자동화의 성공은 “정해진 시각에 글을 올렸다”가 아니다. 다음 네 조건을 동시에 충족해야 한다.

1. 독자가 제목에서 기대한 답을 본문에서 충분히 얻는다.
2. 브링케어 사업과의 연결이 자연스럽고 역할 경계가 정확하다.
3. 사실·안전·저작권·개인정보·네이버 공개 형식이 검증된다.
4. 발행 성과가 다음 콘텐츠의 선택과 개선에 실제로 반영된다.

## 2. 타협하지 않는 원칙

- 실제 현장 작업, 고객 반응, 수리 결과를 지어내지 않는다.
- 브링케어 직접 역할, 외부 전문업체 작업, 건물주 결정을 구분한다.
- 조회수만 높은 약한 연관 주제는 제외한다.
- 제목과 대표 이미지로 만든 약속을 본문에서 해결한다.
- 법률·정책·가격·제품·안전·날씨·부동산 통계는 실행 당일 공식 자료를 확인한다.
- 검색·홈피드 노출, 상담, 수익을 보장하지 않는다.
- 검증 실패를 발행 수량으로 덮지 않는다.
- 장애가 확인되면 같은 동작을 무한 반복하지 않는다.
- AI 이미지는 실제 현장 증거를 대신하지 않는다.

## 3. 시스템 구성

### 3.1 기준 문서 계층

운영 기준의 우선순위는 다음과 같다.

1. 최신 자동화 차단·안전 규칙
2. `writing-bringcare-naver-blog` 스킬과 검증기
3. `manuals/브링케어_네이버블로그_마스터매뉴얼_최신본.docx`
4. 성과 원장의 검증된 학습 규칙
5. 개별 게시물 브리프와 작업 기록
6. 과거 대화·초안

Word 매뉴얼은 사람이 읽는 운영 기준서다. 자동화는 매 실행마다 DOCX 전체를 직접 파싱하지 않고, 동일 규칙을 담은 스킬 참조 파일과 구조화 원장을 읽는다. 매뉴얼과 스킬이 충돌하면 작업을 중단하고 `기준충돌` 알림을 보낸다.

### 3.2 저장 자산

- `blog/automation/backlog.md`: 후보와 제작 단계 상태
- `blog/automation/performance-ledger.csv`: 글 단위 성과 원장
- `blog/automation/experiments.csv`: 제목·이미지·도입·CTA 실험 원장
- `blog/automation/topic-cooldown.csv`: 반복 방지와 재도전 가능일
- `blog/automation/alerts.md`: 로그인·CAPTCHA·정책·검증 장애 기록
- `blog/automation/manual-change-candidates.md`: 반복적으로 확인된 새 운영 규칙 후보
- `blog/YYYY-MM-DD-slug.md`: 발행 원고
- `blog/assets/YYYY-MM-DD-slug/`: 이미지, 배너, 사진 권리 원장

구조화 원장은 CSV로 저장하고, 사람이 읽는 상태·장애·개정 후보는 Markdown으로 저장한다.

## 4. 실행 상태 기계

게시물은 다음 상태 중 하나만 가진다.

1. `후보`
2. `조사완료`
3. `브리프검증`
4. `이미지확보`
5. `본문완료`
6. `원고검증`
7. `발행시도`
8. `공개검수`
9. `발행완료`
10. `성과수집중`
11. `회고완료`
12. `차단`
13. `제외`

허용 전이는 다음과 같다.

- 정상: 후보 → 조사완료 → 브리프검증 → 이미지확보 → 본문완료 → 원고검증 → 발행시도 → 공개검수 → 발행완료 → 성과수집중 → 회고완료
- 자료 부족: 브리프검증 또는 이미지확보 → 차단
- 검증 실패: 브리프검증 또는 원고검증 → 차단 또는 제외
- 브라우저 장애: 발행시도 또는 공개검수 → 차단
- 문제 해결: 차단 → 이전 정상 단계

차단된 작업은 원인과 해결 조건이 바뀌기 전까지 자동 재시도하지 않는다.

## 5. 장애 감지와 사용자 알림

### 5.1 즉시 알림 대상

- 네이버 로그인 만료
- CAPTCHA 또는 추가 본인 확인
- 네이버 편집기 핵심 요소를 찾지 못함
- 발행 버튼·공개 설정·태그 입력란 구조 변경
- 계정 정책 경고, 이용 제한, 비정상 활동 경고
- 발행 후 공개 URL을 열 수 없음
- 공개 페이지의 본문·사진·배너가 저장본과 다름

### 5.2 알림 메시지 계약

알림은 짧되 행동 가능해야 한다.

- 장애 종류
- 감지 시각
- 중단 단계
- 게시물 제목 또는 작업 ID
- 자동화가 이미 한 조치
- 사용자가 해야 할 정확한 조치
- 해결 후 재개 지점

예시:

> 네이버 로그인이 만료되어 발행 직전 중단했습니다. `가을 이사 전 냉장고 냄새 확인 순서` 원고와 이미지는 보존되어 있습니다. 브링케어 계정으로 다시 로그인한 뒤 “재개”라고 알려주시면 `발행시도` 단계부터 이어갑니다.

### 5.3 알림 억제

- 동일 장애가 해결되지 않은 동안 매 회차 같은 알림을 반복하지 않는다.
- 최초 1회 즉시 알림 후, 상태가 바뀌거나 24시간이 지났을 때만 다시 알린다.
- 정책 경고·계정 제한은 반복 발행을 즉시 정지하고 반드시 알린다.

## 6. 이미지 확보와 AI 대체 정책

### 6.1 기본 우선순위

1. 브링케어가 직접 촬영한 국내 실제 사진
2. 사용자가 제공하고 공개를 승인한 국내 사진
3. 공공누리·공공저작물 중 대한민국 촬영과 상업적 사용 조건이 확인된 사진
4. 대한민국 촬영 위치와 재사용 권리가 모두 확인된 실사진
5. 국내 제조사·공공기관이 재사용을 명시적으로 허용한 자료
6. AI 이미지

### 6.2 AI 전환 조건

다음 조건을 모두 충족할 때만 AI 이미지로 전환한다.

- 실제 현장 증명이 필수인 `현장사례`가 아니다.
- 국내 실사진을 합리적으로 탐색했지만 권리와 촬영 위치를 함께 확인하지 못했다.
- 사진 부재로 인해 글의 핵심 설명이 불가능하거나 대표 이미지가 반드시 필요하다.
- AI 사용이 독자를 오인시키지 않는다.
- 생성 이미지의 역할이 `개념 설명`, `체크리스트`, `일반 생활 장면`, `인포그래픽` 중 하나다.

### 6.3 AI 이미지 금지 영역

- 실제 브링케어 작업 전후 사진처럼 표현
- 실제 고객·건물·호실을 재현
- 특정 연예인의 집 또는 특정 아파트 내부를 실제처럼 재현
- 제조사 제품을 동일 모델처럼 오인시키는 이미지
- 화재·누수·곰팡이·전기 고장 결과를 실제 증거처럼 표현
- 인물 초상권 또는 상표권 침해 가능성이 높은 생성

### 6.4 AI 이미지 공개 표시

- 네이버의 AI 활용 표시 기능을 사용한다.
- 본문 흐름을 방해하는 장문의 면책 문구는 쓰지 않는다.
- 필요한 경우 캡션에 `이해를 돕기 위한 AI 이미지`라고 짧게 표시한다.
- AI 이미지를 근거 항목으로 계산하지 않는다.

### 6.5 이미지 원장 필드

- `image_id`
- `post_id`
- `kind`: 실제 | 공식자료 | AI | 설명도
- `role`: 대표 | 도입 | 원인 | 확인 | 해결 | 비교 | CTA
- `source_url`
- `photographer_or_owner`
- `license`
- `korea_location_evidence`
- `downloaded_on`
- `mask_required`
- `ai_disclosure_required`
- `approved_for_publish`

## 7. 시장조사 강화

### 7.1 후보 수집

매 실행에서 최소 5개 후보를 수집한다. 후보군은 동일 축으로 편중되지 않도록 다음 풀에서 가져온다.

- 계절·기상·환기·결로·보일러·동파
- 이사·입주·공실·수납·폐기물
- 청소·냄새·세탁기·냉장고·에어컨
- 서울·원주 부동산 공식 통계와 입주 생활
- 공식 공개된 연예인 공간의 일반 적용 가능한 관리 관점
- 승인된 쿠팡 상품과 직접 관련된 구매 문제
- 원룸·다가구·소형 상가의 반복 관리 문제

### 7.2 조사 증거

후보마다 다음 중 최소 세 종류를 확인한다.

- 네이버 크리에이터 어드바이저의 실제 유입·독자 반응
- 네이버 데이터랩 검색 흐름
- 네이버 검색 결과 상위 글의 제목·답·사진·최신성·댓글 질문
- 외부 키워드 도구의 수요·경쟁 참고치
- 공식기관·제조사·공공데이터의 당일 근거
- 기존 브링케어 글의 성과

외부 키워드 도구의 숫자는 네이버 공식 순위 신호로 표현하지 않는다.

### 7.3 상위 글 빈틈 분석

상위 글 10개에서 다음을 기록한다.

- 제목 구조
- 도입 장면
- 핵심 답
- 사진 종류와 배치
- 독자가 직접 할 수 있는 행동
- 안전·전문가 경계
- 최신 공식자료 반영 여부
- 댓글에서 반복된 추가 질문
- 제품 추천 편중 여부
- 브링케어가 제공할 수 있는 새로운 판단 기준

### 7.4 후보 점수

총점은 100점이다.

- 현재 관심도: 20점
- 검색·구매·상담 행동 의도: 20점
- 브링케어 사업 연관성: 20점
- 공식 근거와 이미지 확보 가능성: 15점
- 기존·경쟁 글과의 차별성: 15점
- 과거 유사 콘텐츠 성과: 10점

다음은 점수와 관계없이 탈락한다.

- 사실성 실패
- 사업 연결 실패
- 제목과 본문 약속 불일치
- 개인정보 또는 저작권 위험 미해결
- 위험한 자가 조치
- 현장 사례를 뒷받침할 실제 자료 부재

작성 기준 점수는 70점이다. 60~69점은 수정후승인, 59점 이하는 제외한다. 강제 탈락 항목은 총점 계산 전에 적용한다.

## 8. 성과 원장

### 8.1 게시물 식별자

모든 게시물은 `YYYYMMDD-slug` 형식의 `post_id`를 가진다. URL이 발급되면 같은 행에 기록한다.

### 8.2 고정 필드

- `post_id`
- `title`
- `public_url`
- `published_at`
- `category`
- `post_type`
- `content_role_primary`
- `content_role_secondary`
- `topic_axis`
- `primary_keyword`
- `secondary_keywords`
- `target_reader`
- `reader_scene`
- `promised_answer`
- `cta_type`
- `image_type`
- `headline_pattern`
- `intro_pattern`
- `bringcare_connection_type`
- `affiliate_used`
- `source_count`

### 8.3 시점별 성과 필드

각 시점은 `72h`, `7d`, `14d`, `30d` 접미사를 사용한다.

- 조회수
- 검색 유입 수 또는 비중
- 홈피드 유입 수 또는 비중
- 외부 유입 수 또는 비중
- 주요 유입 검색어
- 공감 수
- 댓글 수
- 저장 또는 공유 가능 지표
- 평균 사용 시간 또는 확인 가능한 체류 지표
- 카카오채널·전화·제휴 링크 행동
- 데이터 확인 가능 여부

네이버가 제공하지 않는 지표는 추정하지 않고 `NA`로 기록한다.

### 8.4 결과 라벨

- `DISCOVERY_WIN`: 신규 유입이 강함
- `SEARCH_WIN`: 14일 이상 검색 유입이 지속
- `ENGAGEMENT_WIN`: 읽기·공감·댓글 반응이 강함
- `CONVERSION_WIN`: 상담·제휴 행동이 발생
- `EVERGREEN`: 30일 이후에도 지속 가치가 있음
- `TITLE_WEAK`: 노출 대비 클릭이 약함
- `BODY_WEAK`: 클릭 대비 읽기·반응이 약함
- `CTA_WEAK`: 충분히 읽혔지만 행동이 없음
- `TOPIC_WEAK`: 노출·클릭 모두 약함
- `INSUFFICIENT_DATA`: 판단 자료 부족

절대 조회수 하나만으로 성공을 정하지 않는다. 각 글의 주역할에 맞는 성공 라벨을 사용한다.

## 9. 성과 기준선과 진단

### 9.1 기준선

초기 20개 글은 절대 목표 대신 같은 계정의 중앙값을 기준선으로 삼는다.

- 동일 글 유형
- 동일 콘텐츠 역할
- 비슷한 발행 후 경과 시간
- 비슷한 계절·이슈 수명

표본이 20개 미만이면 자동화가 확정 결론을 내리지 않고 `잠정`으로 표시한다.

### 9.2 진단 규칙

- 노출·유입 자체가 약함: 주제 수요, 키워드, 카테고리, 발행 시점 검토
- 홈피드 유입은 있는데 체류·반응이 약함: 제목·대표 이미지와 본문 약속 불일치 검토
- 검색 유입은 있는데 빠르게 감소: 최신성, 답의 깊이, 경쟁 글 업데이트 검토
- 읽기 반응은 강하지만 상담이 없음: 서비스 연결과 CTA의 자연스러움 검토
- 조회수는 낮지만 상담이 있음: 전환형 자산으로 유지하고 조회수만으로 폐기하지 않음
- 제휴 클릭은 있으나 상담이 없음: 수익형으로 분류하고 서비스 성과와 분리
- 같은 검색어로 여러 글이 경쟁: 키워드 잠식 가능성을 표시하고 통합·내부링크 검토

## 10. 다음 주제 학습

### 10.1 성과 점수 반영

후보의 `과거 유사 콘텐츠 성과` 10점은 다음처럼 계산한다.

- 동일 주제축 최근 5개 글
- 동일 검색 의도 최근 5개 글
- 동일 제목 패턴 최근 10개 글
- 동일 이미지 유형 최근 10개 글

표본이 부족하면 5점의 중립값을 사용하고 확신도를 낮춘다.

### 10.2 재사용할 것과 금지할 것

재사용 가능:

- 질문형·비교형·상식 교정형 등 제목의 기능
- 실제 장면으로 시작하는 도입 원리
- 체크리스트·비교표·판단 기준 같은 정보 구조
- 성과가 좋은 대표 이미지의 구도와 역할
- 검색어 확장 방식

재사용 금지:

- 성공한 제목의 단어만 바꾼 복제
- 같은 도입 문장
- 같은 브링케어 연결 문단
- 동일 결론의 반복 게시
- 사진 재탕으로 다른 현장처럼 표현

### 10.3 쿨다운

- 동일 주키워드: 기본 30일
- 동일 문제와 결론: 기본 60일
- 동일 유명인·정책 이슈: 새로운 공식 사실이 없으면 재사용 금지
- 성과 부진 주제축: 3회 연속 `TOPIC_WEAK`이면 60일 보류
- 성과 우수 주제축: 후속 질문이 다를 때만 14일 이후 확장 가능

## 11. 실험 관리

한 글에서는 핵심 변수 하나만 실험한다.

- 제목 패턴
- 대표 이미지 유형
- 도입 방식
- 정보 구조
- 브링케어 연결 위치
- CTA 문구

실험 원장 필드:

- `experiment_id`
- `hypothesis`
- `primary_variable`
- `control_reference`
- `success_metric`
- `guardrail_metric`
- `sample_requirement`
- `result`
- `decision`
- `confidence`

조회수를 늘리면서 개인정보·사실성·상담 품질이 악화되는 실험은 성공으로 판정하지 않는다.

## 12. 매뉴얼 학습과 개정

자동화가 Word 매뉴얼을 임의로 바꾸지는 않는다. 다음 조건을 만족하면 `manual-change-candidates.md`에 개정 후보를 기록한다.

- 같은 실패가 3회 이상 반복
- 같은 교정이 3회 이상 성공
- 네이버 편집기 구조가 실제로 변경
- 공식 정책·법률·플랫폼 규칙 변경
- 새로운 사진·AI·제휴 공개 기준 필요
- 사용자가 새로운 고정 규칙을 명시적으로 확정

개정 후보는 다음 필드를 가진다.

- 발생 날짜
- 관련 게시물 또는 장애 ID
- 기존 규칙
- 제안 규칙
- 근거
- 예상 영향
- 자동화·스킬·검증기 수정 필요 여부
- 사용자 승인 상태

사용자가 승인한 후보만 Word 매뉴얼, 스킬, 자동화 프롬프트에 동시에 반영한다. 세 자산 중 하나라도 누락되면 `기준불일치`로 기록한다.

## 13. 자동화 실행 순서

1. 자동화 상태와 차단 여부 확인
2. backlog와 기존 공개 글 확인
3. 성과 원장 최신 수집 시점 확인
4. 72시간·7일·14일·30일 도래 글의 성과 수집
5. 성과 진단 및 쿨다운 갱신
6. 후보 5개 조사
7. 강제 탈락 적용
8. 후보 점수 계산
9. 최고 후보 브리프 작성
10. `validate_brief.py` 실행
11. 실제 이미지 우선 탐색
12. 실사진 실패 시 AI 전환 조건 판정
13. 본문·대표 이미지·태그·CTA 작성
14. `validate_draft.py` 실행
15. 로그인·편집기 상태 확인
16. 네이버 발행
17. 공개 페이지 검수
18. 성과 원장에 발행 기준선 저장
19. backlog를 `발행완료/성과수집중`으로 갱신
20. 성공 시 제목과 URL 보고, 실패 시 행동 가능한 알림

성과 수집과 새 글 발행이 같은 회차에 있으면 성과 수집을 먼저 수행한다.

## 14. 공개 페이지 검수

발행 성공은 공개 URL이 생성된 것만으로 인정하지 않는다. 다음을 모두 확인한다.

- 제목 오탈자와 약속 일치
- 제목 제외 본문 가운데 정렬
- 의미 묶음 사이 실제 빈 문단
- 배경색 강조의 위치와 과다 사용 여부
- 실제 인용구·구분선 컴포넌트
- 이미지 순서·중복·캡션·AI 표시
- 개인정보 노출 없음
- 카테고리·전체공개·검색 허용
- 네이버 태그 입력란 등록
- 하단 출처·태그·연락처 덤프 없음
- 상담 배너 마지막 1회
- 제휴 글의 경제적 이해관계 표시

공개 검수 실패 시 URL을 성공으로 보고하지 않고 `차단`으로 전환한다.

## 16. 검증 및 테스트

### 16.1 정적 검증

- 자동화 프롬프트, 스킬, Word 매뉴얼의 핵심 규칙 일치
- 성과 원장 필수 열 존재
- 허용 상태 외 값 없음
- 게시물 ID와 URL 중복 없음
- 시점별 지표가 미래 날짜에 입력되지 않음
- 실제 제공되지 않는 지표가 숫자로 추정되지 않음

### 16.2 시나리오 테스트

1. 로그인 만료: 원고 보존, 즉시 알림, 반복 시도 금지
2. CAPTCHA: 발행 중단, 사용자 해결 요청
3. 편집기 요소 변경: 클릭 추측 금지, 구조 변경 알림
4. 국내 실사진 성공: 권리 원장 저장 후 사용
5. 국내 실사진 실패·AI 허용: AI 생성·표시 후 발행
6. 현장사례 사진 실패: AI 대체 금지, 차단
7. 72시간 성과 수집: 원장 갱신 후 다음 후보 점수 반영
8. 조회수 낮고 상담 발생: 전환형으로 유지
9. 동일 주제 3회 부진: 쿨다운 적용
10. 공개 페이지 정렬 실패: 성공 보고 금지

### 16.3 완료 기준

- 위 10개 시나리오가 모두 예상 상태로 종료
- 성과 수집 값이 다음 후보 점수에 재현 가능하게 반영
- AI 대체가 현장사례에 적용되지 않음
- 로그인·CAPTCHA·편집기 장애가 즉시 사용자에게 전달
- Word 매뉴얼·스킬·자동화 프롬프트 간 핵심 모순 없음
- 기존 게시물·사용자 파일을 손상시키지 않음

## 17. 도입 순서

1. 구조화 성과 원장과 쿨다운 원장 생성
2. 기존 게시물 목록을 초기 원장으로 이관
3. 스킬에 이미지 대체·성과 학습·알림 규칙 추가
4. 검증기에 새 필드와 실패 조건 추가
5. 자동화 프롬프트 갱신
6. Word 매뉴얼을 v1.1로 개정
7. 로그인 장애·AI 대체·성과 수집 시나리오 테스트
8. 첫 20개 글은 학습 준비 기간으로 운영
9. 20개 이후 계정 중앙값 기반 자동 진단 활성화

## 18. 범위 밖

- CAPTCHA 우회
- 계정 보안 장치 우회
- 권리 불명 사진 무단 사용
- 네이버 비공개 알고리즘 추정값을 사실로 사용
- 쿠팡 파트너스 승인되지 않은 링크 자동 생성
- 상담·조회·수익 보장
- 실제 현장 자료 없는 현장사례 자동 생성

## 19. 최종 결정 요약

- 로그인·CAPTCHA·편집기 장애는 우회하지 않고 즉시 알림한다.
- 국내 실사진을 우선하되, 일반 정보·트렌드 글은 조건부 AI 이미지로 대체한다.
- 현장사례는 AI 이미지로 대체하지 않는다.
- 성과는 72시간·7일·14일·30일에 누적한다.
- 절대 조회수보다 글의 역할과 계정 내 비교 기준을 사용한다.
- 성과는 다음 후보의 10점 항목, 쿨다운, 후속 주제, 제목·이미지·도입·CTA 실험에 반영한다.
- 반복된 학습은 자동으로 매뉴얼을 바꾸지 않고 개정 후보로 올린다.
- 사용자 승인 후 Word 매뉴얼·스킬·자동화 프롬프트를 동시에 개정한다.
