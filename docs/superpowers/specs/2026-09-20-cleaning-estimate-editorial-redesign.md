# 브링케어 청소 견적페이지 UX/UI 전면개편 명세

작성일: 2026-09-20  
상태: 사용자 방향 승인 — 구현 전 최종 검토

## 1. 목표

현재 `/cleaning-estimate`의 기능 중심 화면을, 사용자가 제공한 `BRING CARE 상세페이지3 (단일파일).html`의 장점을 반영한 프리미엄 전환형 상세페이지로 개편한다.

페이지의 첫째 목적은 고객이 브링케어를 신뢰하게 만드는 것이고, 둘째 목적은 자신의 가격을 빠르게 확인하게 하는 것이며, 셋째 목적은 기존 CRM으로 견적 신청을 완료하게 하는 것이다.

## 2. 디자인 방향

### 채택안: 에디토리얼 상세페이지와 견적 위저드의 결합

- 참고 페이지의 큰 타이포그래피, 넓은 여백, 블루·화이트의 명확한 대비, 화면당 한 메시지 원칙을 채택한다.
- 참고 페이지처럼 모든 내용을 길게 나열하지 않는다. 청소 고객이 가격에 도달하는 길이를 줄이고, 첫 화면에서 1~2회 스크롤 안에 서비스와 가격 선택을 시작하게 한다.
- 정장 사진은 `책임지는 운영회사`라는 브랜드 인상을 만드는 데 사용한다.
- 실제 청소사진은 서비스 범위와 작업 역량을 증명하는 자료로 사용한다.
- 페이지 외형과 신청 폼을 분리하지 않는다. 스토리와 신청이 한 흐름처럼 이어져야 한다.

## 3. 시각체계

### 색상

- Primary Blue: 기존 브링케어 블루 `#145DA8`
- Action Blue: `#1672CF`
- Deep Navy: `#071C33`
- Soft Navy: `#0B294C`
- Paper: `#F4F6F8`
- White: `#FFFFFF`
- Lime Accent: `#C7F23F`
- 본문색: `#0F2032`
- 보조본문: `#5E6C79` 이상 명도로 유지해 WCAG 4.5:1 대비를 확보한다.

참고 파일의 밝은 로열블루는 CTA와 숫자 강조에만 제한적으로 사용한다. 여러 그라데이션을 반복하지 않는다.

### 타이포그래피

- Pretendard Variable을 유지한다.
- 히어로 제목: 데스크톱 72~88px, 모바일 42~48px, 800~900 weight.
- 섹션 제목: 데스크톱 48~64px, 모바일 32~40px.
- 본문: 모바일을 포함해 최소 16px, 줄간격 1.6 이상.
- 큰 글자를 장식이 아니라 메시지 위계에만 사용한다.

### 공간과 형태

- 8px 기반 간격체계를 사용한다.
- 주요 섹션 상하 여백은 데스크톱 112~144px, 모바일 72~96px.
- 카드 반경은 20~28px, 버튼 반경은 12~16px 또는 핵심 CTA에 한해 pill 형태.
- 그림자는 최소화하고 배경색·여백·타이포그래피로 계층을 만든다.

## 4. 페이지 구조

### 4.1 몰입형 히어로

- 정장 단체사진을 화면 전체 폭의 배경으로 사용한다.
- 좌측 또는 하단에 네이비 그라데이션 스크림을 적용해 문장 대비를 확보한다.
- 핵심 문구: `청소 가격, 먼저 확인하고 신청하세요.`
- 보조 문구: 고객이 제공한 정보 검토 후 작업 전 견적을 확정하며, 확정견적 이후 기본 작업에는 현장 추가금이 없다는 원칙.
- 하나의 주 CTA: `내 청소가격 확인하기`
- 보조 신뢰요소는 짧은 문장 세 개로 제한한다: 사전 확정견적, 책임검수, 단일창구.
- 모바일 첫 화면에서 제목과 CTA가 최대한 한 화면 안에 들어오도록 사진 높이를 제한한다.

### 4.2 약속 섹션

세 개의 작은 배지 대신 화면을 나눈 세 개의 에디토리얼 블록으로 보여준다.

1. 가격 — 현장 추가금 없는 사전 확정견적
2. 품질 — 작업 완료 후 브링케어 책임검수
3. 문제처리 — 업체가 아니라 브링케어가 끝까지 응대

각 블록은 큰 숫자, 짧은 제목, 한 문단으로 구성한다.

### 4.3 서비스 선택

- 7개 서비스를 텍스트 버튼이 아닌 이미지 카드로 표현한다.
- 첫 화면에는 주력상품 3종(원룸·다가구, 아파트, 공용부·계단)을 크게 보여준다.
- 나머지 4종은 동일 영역 아래의 작은 카드로 제공한다.
- 각 카드에는 실제 청소사진, 서비스명, 시작가격 또는 `현장견적`을 표시한다.
- 선택하면 같은 화면 아래에 해당 가격표가 부드럽게 펼쳐지고 자동으로 초점이 이동한다.

### 4.4 가격 선택

- 표 모양 대신 넓은 가격 행 카드로 구성한다.
- 선택된 면적은 파란 테두리, 체크 아이콘, 라임 가격 강조를 함께 사용해 색상만으로 상태를 표현하지 않는다.
- `부가세 포함`, `기본 작업 현장 추가금 없음`을 가격 가까이에 배치한다.
- `전체 가격표 보기`는 별도 아코디언으로 유지한다.

### 4.5 신뢰 증명

- 정장 콘셉트 이후 실제 현장사진을 사용해 과장된 인상을 상쇄한다.
- 창틀·주방·욕실·수납장 등 4개 구역을 이미지 중심으로 보여준다.
- 작업 흐름은 `범위 확인 → 확정견적 → 작업 → 사진검수 → 문제처리`의 5단계다.
- 후기나 실적 수치가 확인되기 전에는 임의 후기·가짜 평점·가짜 숫자를 넣지 않는다.

### 4.6 견적 위저드

- 기존 7단계 데이터 흐름과 CRM 연결은 유지한다.
- 서비스와 면적 선택은 앞선 상세페이지 영역에서 완료되므로 위저드 안에서는 반복 질문하지 않는다.
- 나머지 단계는 현장상태 → 주소·희망일 → 사진 전달방법 → 검토 → 연락처 순으로 단축한다.
- 데스크톱은 중앙 720~800px 카드, 모바일은 화면 폭 전체에 가깝게 배치한다.
- 모바일 하단에 한 개의 주 CTA를 고정하고, 이전 버튼은 낮은 강조도로 둔다.
- 입력값 자동저장과 진행률을 유지한다.

### 4.7 마지막 CTA와 안내

- 신청 직전 예약·결제 흐름을 짧게 안내한다.
- `견적 요청 → 범위·가격 확정 → 예약금 20% → 작업·검수 → 잔금 80%`
- 취소·변경 상세규정은 접힌 안내로 제공한다.
- 고객센터 영업시간과 연락수단을 마지막에 반복한다.

## 5. UX 규칙

- 고객은 첫 진입 후 두 번 이내의 탭으로 자신의 가격을 확인할 수 있어야 한다.
- 한 화면에 주 CTA는 하나만 둔다.
- 터치 영역은 최소 44×44px, 입력 글자는 최소 16px이다.
- 모든 입력은 보이는 라벨을 갖고, 오류는 해당 입력 바로 아래에 표시한다.
- 진행 중 입력값은 기기에 자동저장한다.
- 뒤로가기를 제공하고 입력값을 유지한다.
- 모션은 150~250ms 범위이며 `prefers-reduced-motion`을 존중한다.
- 이미지에는 실제 내용을 설명하는 대체텍스트를 제공한다.
- 가로 스크롤과 모바일에서 잘리는 고정 요소를 허용하지 않는다.

## 6. 데이터와 CRM

- 공식 가격 원장은 기존 `pricing.ts`와 Obsidian의 `BRING CARE 판매가격표 v0.1.md`다.
- 견적 신청은 기존 `submitMarketingLead`를 통해 `crmCompany/marketingLeadInbox`로 보낸다.
- 서비스, 선택 면적, 안내가격, 현장상태, 주소, 희망일, 사진전달 방식, 메모, 고객정보를 보존한다.
- 사진은 초기 공개판에서 직접 업로드하지 않는다. 접수 후 인증된 문자 또는 카카오 링크로 별도 수집한다.
- 페이지 제출 성공 시 기존 완료화면으로 이동한다.
- 전송 실패 시 전화상담과 신청내용 복사 대안을 제공한다.

## 7. 컴포넌트 구조

- `CleaningEstimatePage`: 페이지 조립과 메타데이터
- `EditorialHero`: 사진 전체형 히어로
- `TrustPromises`: 3대 약속
- `ServiceGallery`: 이미지 기반 7개 서비스 선택
- `PriceSelector`: 서비스별 가격 및 전체 가격표
- `ProofGallery`: 실제 청소 범위와 작업 증명
- `CleaningProcess`: 5단계 작업 흐름
- `EstimateWizard`: 신청 상태와 단계 전환
- `PaymentFlow`: 예약금·잔금 안내
- `CleaningEstimateData`: 서비스·가격·옵션 데이터 원장

페이지 하나가 모든 렌더링과 상태를 담당하지 않도록 기능별 파일로 분리한다.

## 8. 반응형 기준

- 375px: 작은 휴대전화 검증 기준
- 390px: 대표 모바일 기준
- 768px: 태블릿 세로
- 1024px: 태블릿 가로·작은 노트북
- 1440px: 데스크톱 기준

모바일에서는 사진과 텍스트를 세로로 쌓고, 히어로 CTA와 가격선택 CTA가 첫 행동을 방해하지 않게 한다.

## 9. 검증 기준

- 공식 7개 서비스와 모든 가격이 누락되지 않는다.
- 부가세 포함 및 현장 추가금 원칙이 가격 가까이에 표시된다.
- 선택한 서비스와 가격이 CRM payload에 정확히 들어간다.
- 키보드만으로 전체 신청을 완료할 수 있다.
- 375px, 390px, 768px, 1440px에서 가로 스크롤이 없다.
- 375px 모바일 첫 화면에서 핵심문구와 CTA 접근이 가능하다.
- 전체 사이트 빌드, 랜딩 테스트, 렌더링 테스트가 모두 통과한다.
- PC와 모바일 실제 브라우저 화면을 최종 검수한다.

## 10. 제외 범위

- 결제대행사 실제 계약과 결제창 API 연동
- 공개 사진 업로드 저장소
- 실제 고객후기 생성
- 대표번호 확정 및 교체
- 기존 다른 랜딩페이지 전체 리디자인
