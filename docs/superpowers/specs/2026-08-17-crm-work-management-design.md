# BRING CRM 작업관리 설계

## 목적

대표가 건물별 현장 작업의 예정·진행·완료 상태, 담당자, 비용, 증빙을 한 화면에서 파악한다. 팀원은 자신이 맡은 작업과 다음 일정을 확인하고 상태와 완료 증빙을 기록한다.

## 확정 화면

CRM 왼쪽 메뉴에 `작업관리`를 추가한다. 첫 화면은 사용자가 승인한 A안 대표용 작업 대시보드다.

- 상단 지표: 오늘 작업, 예정, 진행 중, 완료, 이번 달 완료 비용, 월 정기 예정액
- 필터: 전체/예정/진행 중/완료/정기 작업, 건물, 담당자, 작업 종류, 기간
- 작업 목록: 작업명, 건물, 일정, 상태, 담당자·업체, 비용, 증빙 여부, 다음 행동
- 작업 상세: 기본정보, 작업 전후 기록, 비용, Drive 증빙 링크, 변경 이력
- 주요 행동: 새 작업 등록, 상태 변경, 완료 처리, 수정, 보관

## 데이터 구조

기존 공용 CRM 서버의 세 컬렉션을 그대로 사용하며 별도 직원 자동화 시스템은 만들지 않는다.

### `serviceRecords`

개별 작업의 실행 이력이다. 예정·진행·완료 상태를 모두 담을 수 있도록 다음 필드를 표준화한다.

- `id`, `buildingId`, `serviceType`, `title`
- `status`: `planned`, `in_progress`, `completed`, `cancelled`
- `scheduledDate`, `startedAt`, `completedAt`
- `owner`, `vendorName`, `vendorPhone`
- `amount`, `summary`, `nextAction`
- `driveFileId`, `evidenceUrl`
- `createdAt`, `updatedAt`, `archivedAt`

Drive 파일 ID가 있는 기록은 해당 ID 기준으로 중복 등록하지 않는다.

### `serviceContracts`

계단청소처럼 반복되는 서비스 계약의 원장이다.

- 주기, 월 비용, 시작일, 상태, 연결 건물
- 시작일이 없으면 `시작일 확인 필요`로 표시하고 일정을 생성하지 않는다.
- 시작일이 확정되면 일정 생성 대상으로 전환한다.

### `serviceSchedules`

반복 계약에서 생성되는 개별 실행 일정이다. 계약과 건물을 참조하며, 실제 완료 시 `serviceRecords`와 연결한다.

## 첫 등록 데이터

### 예초 작업

- 건물: 북원로2475번길93
- 완료일: 2026-08-15
- 업체: 사계절제초작업
- 비용: 150,000원
- 내용: 건물 외부 수목·벽면·통행로 주변 예초 및 정리
- 상태: 완료
- 증빙: Google Drive 완료보고서

### 계단청소

- 건물: 북원로2475번길93
- 주기: 주 1회
- 월 비용: 60,000원
- 상태: 계약 예정·시작일 확인 필요
- 시작일 확정 전에는 개별 일정을 만들지 않는다.

## 기존 표시 실패 원인과 수정 원칙

서버 데이터는 저장됐지만 최초 1.7.8 설치본이 서비스 화면 코드보다 먼저 빌드되어 화면에 표시되지 않았다. 1.7.9 설치본에는 건물 상세 표시 코드가 포함됐지만, 사용자가 원하는 전체 작업 관점이 아니라 건물 상세 안의 보조 섹션에 불과했다.

작업관리 메뉴는 공용 서버 데이터를 직접 읽는 독립 CRM 화면으로 만든다. 로컬 데모나 하드코딩 수치를 사용하지 않으며, 서버에 데이터가 있는데 화면에서 누락되면 빈 상태로 오표시하지 않고 동기화 오류를 표시한다.

## 권한과 감사

- admin/member: 작업 생성·수정·상태 변경·보관 가능
- viewer: 조회만 가능
- 모든 변경은 기존 CRM 계정과 시각을 감사로그에 남긴다.
- 실제 출입 비밀번호나 민감정보는 작업 메모에 저장하지 않는다.
- Drive 링크는 HTTPS Google Drive 링크만 외부 브라우저로 연다.

## 동기화와 오류 처리

- 공용 Firebase 저장 경로를 사용해 팀원에게 동일하게 표시한다.
- 저장은 레코드 단위 PATCH로 수행하고 전체 CRM 데이터를 덮어쓰지 않는다.
- 같은 Drive 파일 또는 같은 작업 ID의 재등록은 기존 기록을 갱신한다.
- 서버 읽기 실패 시 `작업 없음` 대신 `동기화 확인 필요`를 표시한다.
- 계단청소 시작일 미정 상태는 일정 미생성으로 유지한다.

## 검증 기준

1. 작업관리 메뉴에서 예초 완료 1건과 계단청소 예정 계약 1건이 보인다.
2. 완료 1건, 예정 1건, 이번 달 완료 비용 150,000원과 월 정기 예정액 60,000원이 서로 섞이지 않고 집계된다.
3. 건물 필터에서 북원로2475번길93을 선택하면 두 항목만 표시된다.
4. 예초 작업의 Drive 원본 버튼이 안전한 외부 열기로 동작한다.
5. viewer에게 변경 버튼이 노출되지 않는다.
6. 계단청소 시작일이 없으면 개별 일정이 생성되지 않는다.
7. 새 작업 저장 후 다른 CRM 사용자에게 동일 기록이 보인다.
8. 서버 오류를 빈 작업 목록으로 오인하지 않는다.
9. 전체 데스크톱 테스트와 smoke 검증을 통과한다.

## 제외 범위

- 직원 급여·근태 자동화
- 업체 자동 배정·자동 결제
- Drive 파일 전체 자동 수집
- 시작일이 확정되지 않은 반복 일정의 추정 생성
