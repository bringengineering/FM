# Windows TV 운영보드 원격 연결 설계

## 확인한 환경
- 사용자가 TV 연결 컴퓨터를 Windows로 확인했다.
- 현재 로컬 운영보드는 기존 FM 화면/인증을 이용한다. 원격 TV 연결은 아직 없다.
- 기존 `crm-ai-worker`는 Firebase 직원 토큰 검증을 수행하지만 TV 전용 인증은 없다. 카카오 intake Worker는 용도가 다르므로 변경하지 않는다.

## 구현 경계
기존 직원 토큰은 관리자 제어 요청에만 쓴다. TV는 업무 수정 API를 호출할 수 없는 별도 인증을 갖는다. 기존 관리자 세션, Firebase refresh token, 서비스 계정 키를 TV로 복사하지 않는다. 공개 URL이나 소스에 등록 코드를 넣지 않는다.

## 연결 흐름
1. Windows TV 클라이언트가 기기 등록을 시작한다. 서버가 고엔트로피의 대기 토큰과 짧은 표시 코드를 발급한다. 대기 토큰은 화면/로그/URL에 표시하지 않는다.
2. 직원 관리자 화면에서 코드를 입력하고 기기 이름을 확인하여 승인한다. 코드는 10분 후 만료하고 승인 시 1회 소비한다. 승인/소비는 원자적으로 처리해야 한다.
3. TV는 대기 토큰으로 승인 결과를 수령한다. 조회 전용 기기 토큰은 Windows 보호 저장소에 보관한다. 서버는 토큰 원문 대신 해시를 저장한다.
4. TV는 승인된 표시 데이터와 편성만 조회한다. 업무 원문이나 전체 CRM 저장소를 다운로드하지 않는다.
5. 관리자가 기기 해제 시 이후 모든 데이터 조회를 거부한다. 성공 조회 여부, 마지막 접속, 클라이언트 버전을 관리 화면에 표시한다.

## 데이터와 편성
- 관리자 게시 서비스에서 화이트리스트 스키마로 검증한 집계/표시 데이터를 서버에 저장한다. 자유 입력 제목, 공지, 사진은 게시 전 미리보기와 명시적 게시가 필요하다.
- 게시에는 버전과 생성시각을 포함한다. TV는 마지막 정상 버전을 유지하고 오류/오래된 자료를 분명히 표시한다. 오래된 자료를 최신 실적으로 표시하지 않는다.
- 직원의 회사별/업무별 조회 권한을 임의 확대하지 않는다. 서버가 관리자임을 검증한다.
- 기기 인증 저장에는 승인 원자성과 즉시 해제를 보장하는 저장소가 필요하다. 기존 AI_USAGE KV를 재사용하지 않는다. 저장소 선택/배포는 별도 검토 후 진행한다.
- 사진·영상·시간대 예약은 후속 범위이며 현재 5개 장면과 편성 동기화를 먼저 연결한다.

## Windows 실행
기존 FM과 같은 화면 컴포넌트를 쓰되, TV 실행 모드에는 편집/고객 상세/직원 로그인 메뉴를 노출하지 않는다. 최초 설치와 시작프로그램 등록은 실제 TV 컴퓨터에서 실행 승인 후 한다. 자동 로그인 설정이나 원격 지원 프로그램을 임의 설치하지 않는다.

## 배포 및 검증 게이트
- 로컬 인증 테스트: 미승인·만료·재사용·무차별 코드 시도·비관리자 승인·해제 토큰·타 기기 토큰 거부.
- 통신 테스트: 서버 개인정보 필드 차단, 일정/실적 60초 갱신, 게시 충돌, 오류 시 마지막 성공시각 유지.
- 실제 Windows TV: 등록→승인→전체화면→원격 편성 변경→재시작→해제까지 확인.
- 기존 CRM 로그인/저장/AI/카카오 경로 회귀검사.
- Firebase Functions/Hosting 배포 금지 유지. 새로운 서버 저장소와 운영 배포는 대상/비용/계정 확인 없이 실행하지 않는다.

## 현재 상태
이 문서는 구현할 인증/배포 경계를 정리한 설계다. 원격 API, 기기 토큰 저장, 관리자 승인 화면, TV 설치는 완료되지 않았다.
