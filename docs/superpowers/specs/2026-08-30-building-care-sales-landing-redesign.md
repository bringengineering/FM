# BRING CARE 건물관리 광고페이지 전면 리뉴얼 설계

## 1. 목표

`/building-care`를 서비스 목록 페이지가 아니라 건물주를 상담으로 전환하고 기업 담당자에게 운영 신뢰를 증명하는 온라인 영업 페이지로 재구성한다.

첫 방문자는 3초 안에 다음을 이해해야 한다.

- 원주 소형 임대건물 건물주를 위한 서비스다.
- 공실·임차인·시설·민원·수리를 하나의 창구에서 관리한다.
- 월 89,000원부터 시작한다.

페이지를 끝까지 본 사용자는 다음을 확인할 수 있어야 한다.

- BRING CARE가 어떤 순서와 기준으로 일하는가.
- 입퇴실이 발생했을 때 다음 입실까지 무엇을 연결하는가.
- 실제로 어떤 현장을 수행했는가.
- 무엇을 사진과 보고서로 전달하는가.
- 관리비에 포함되는 것과 별도 비용은 무엇인가.
- 회사와 파트너 운영체계를 신뢰할 근거가 무엇인가.

## 2. 선택한 접근

### 검토한 접근

1. **17개 섹션을 모두 독립적으로 유지**
   - 장점: 제공 정보를 빠짐없이 노출한다.
   - 단점: 모바일에서 설명이 길고 중복되며 기획 문서처럼 보인다.
2. **영업 흐름 중심 14개 구간으로 압축 — 채택**
   - 장점: 내용은 유지하면서 중복을 합치고 시각적 증거를 앞세울 수 있다.
   - 단점: 각 섹션의 카피와 사진을 더 정교하게 편집해야 한다.
3. **건물주 광고페이지와 기업 제휴페이지를 완전히 분리**
   - 장점: 각 대상에게 가장 정확한 메시지를 전달한다.
   - 단점: 현재 검증 가능한 기업 자료가 충분하지 않고 관리 비용이 커진다.

### 결정

이번 단계에서는 2안을 적용한다. 앞부분은 건물주 전환, 뒷부분은 운영 신뢰와 기업 협업 검토에 필요한 증거를 담당한다. 향후 제휴 자료가 축적되면 별도의 기업 제휴 페이지로 분리할 수 있다.

## 3. 서비스 위계

시각적으로 다음 위계를 반드시 유지한다.

1. **Main Business — Building Care**
   - PM: 공실·임차인·입퇴실 일정·커뮤니케이션·기록
   - FM: 월 2회 현장방문·공용부·이상징후·사진기록
   - Maintenance Coordination: 필요성 확인·업체 연결·일정·완료 확인
2. **Key Entry Product — 입퇴실 패키지**
   - 퇴실부터 다음 입실까지의 시간을 관리하는 핵심 이벤트 상품
3. **Acquisition Product — Cleaning**
   - 건물 정기청소와 입퇴실청소
4. **Supporting Capability**
   - 실제 현장기록·관리보고·지역 파트너·CRM
5. **Future**
   - 축적 데이터 기반 운영 고도화. 현재 제공 기능처럼 표현하지 않는다.

청소를 Building Care와 같은 높이의 서비스 카드로 나열하지 않는다.

## 4. 최종 Sales Story — 14개 구간

### 01. Hero — 누구를 위한 무엇인지

- Eyebrow: `원주 소형 임대건물 통합 운영관리`
- Headline: `건물은 임대하고, 관리는 맡기세요.`
- Body: `공실부터 임차인·시설점검·민원·수리까지 건물주 대신 확인하고 처리합니다.`
- Price: `BUILDING CARE · 월 89,000원부터`
- Contract: `최소 계약기간 6개월`
- Primary CTA: `내 건물 관리 상담받기`
- Secondary CTA: `입퇴실 패키지 알아보기`
- Visual: 실제 소형 임대건물 사진과 실제 관리보고 UI를 결합한다. 팀 단체사진은 사용하지 않는다.

### 02. Problem — 건물주의 반복 노동

- Headline: `건물 하나 관리하는데, 왜 이렇게 연락할 곳이 많을까요?`
- 세 개의 문제 장면: 공실·퇴실 / 시설·민원 / 일정·결과 확인
- 결론: `업체는 따로 있지만 모든 연락·확인·결정은 결국 건물주의 몫입니다.`
- 긴 텍스트 카드 대신 실제 상황을 상징하는 장면, 아이콘, 연결 화살표를 사용한다.

### 03. One Contact — 하나의 관리창구

- Headline: `이제 관리창구를 하나로 줄이세요.`
- Before: 건물주가 중개사·청소업체·임차인·수리업체·현장을 각각 연결
- After: 건물주 → BRING CARE → 공실·임차인·시설·민원·수리·보고
- 네트워크 다이어그램으로 표현한다.

### 04. Building Care System — 본사업

- PM, FM, Maintenance의 세 개 대형 패널
- 각 패널은 실제 현장사진, 핵심 역할, 포함 항목, 건물주가 얻는 이익 순서로 구성한다.
- 전문용어보다 고객 언어를 우선하고 영문 약어는 보조 표기로만 사용한다.
- FM은 법정검사나 전문진단을 직접 수행하는 것으로 표현하지 않는다.

### 05. General Management Process — 시작부터 보고까지

- Headline: `건물주는 연락 한 번이면 됩니다.`
- 7단계: 문의 접수 → 상황 확인 → 현장 필요성 판단 → 조치 결정 → 담당·전문업체 배정 → 완료 확인 → 건물주 보고
- 실제 신청 후 무엇이 일어나는지 보여주는 진행 UI로 표현한다.
- 운영 목표시간을 게시할 경우 `목표`임을 명시하고 실제 운영 가능 범위를 최종 확인한다.

### 06. Turnover Package Hero — 두 번째 Hero

- Eyebrow: `BRING TURNOVER PACKAGE`
- Headline: `퇴실하는 순간부터, 다음 입실까지.`
- Core: `비어 있는 시간을 줄이는 것이 가장 중요한 관리입니다.`
- 일반 서비스 카드보다 확실히 큰 크기와 시각적 장면을 사용한다.
- CTA: `입퇴실 패키지 문의하기`

### 07. Turnover Flow + Vacancy Time — 과정과 차별화 통합

- 9단계 입퇴실 흐름과 Vacancy Turnaround Time 비교를 한 구간 안에서 연결한다.
- 상단: 퇴실 예정 → 현장점검 → 작업결정 → 일정준비 → 청소·수리 → 촬영 → 협력 중개사 공유 → 입실 준비 → 다음 입실
- 하단: 일반적인 순차 대기와 BRING의 병렬 준비를 두 개의 시각 트랙으로 비교한다.
- 검증되지 않은 단축률이나 기간을 사용하지 않는다.
- 공인중개 행위를 직접 수행하는 것처럼 표현하지 않고 `협력 공인중개사 네트워크 공유`, `임차인 모집 지원`으로 표기한다.

### 08. Pricing — 포함과 별도 비용

- Headline: `복잡한 건물관리, 월 89,000원부터.`
- 기본 관리비 카드와 별도 비용 카드를 나란히 배치한다.
- 포함: PM, FM, Maintenance Coordination, 월간 관리보고
- 별도: 정기청소, 입퇴실청소, 수리·자재, 전문진단, 도배·장판, 폐기물, 특수청소, 법정 전문점검
- 핵심 설명: `89,000원은 실제 공사비가 아니라 건물운영을 확인·조정·관리하는 기본 관리비입니다.`

### 09. Entry Services — 작은 서비스로 시작

- Headline: `관리계약이 아니어도 괜찮습니다. 필요한 일부터 맡겨보세요.`
- Cleaning과 Turnover Package를 두 개의 큰 상품으로 구분한다.
- Cleaning CTA: `청소 견적받기`
- Turnover CTA: `입퇴실 패키지 문의하기`
- 가격은 현재 확정 가격만 노출한다.

### 10. Real Cases — 갤러리가 아닌 사례

- Headline: `말보다 현장으로 보여드립니다.`
- 실제 수행 경험만 사용한다.
- 사례 구조: 문제 → BRING의 확인·조율·작업 → 결과
- 실제 날짜, 지역, 업무범위, 거래금액, Before/After를 가능한 범위에서 표시한다.
- 허위 후기, 임의 성과, AI 현장사진은 사용하지 않는다.

### 11. Management Report — 운영 증거

- Headline: `건물에 가지 않아도, 무슨 일이 있었는지 알 수 있습니다.`
- 실제 CRM 또는 보고서 구조를 앱형 UI로 크게 보여준다.
- 접수시간, 현장사진, 이상징후, 담당자, 건물주 승인, 비용, 완료여부, 다음 확인사항을 포함한다.
- 예시 숫자는 `화면 예시`로 명확히 표시한다.

### 12. Trust & Operations — 기업도 검토 가능한 증거

- `왜 BRING CARE인가요?`와 파트너 네트워크를 통합한다.
- 하나의 창구, 월 2회 확인, 접수부터 완료, 사진과 기록, 원주 지역 네트워크를 제시한다.
- 추가 신뢰정보: 사업자 정보, 적용 가능 지역, 개인정보 처리, 보험·인허가 보유 여부, 파트너 선정 기준, 고객·민원 처리 기준
- 보유하지 않은 보험·인증·수치를 임의로 만들지 않는다.
- 기업 협업 CTA는 일반 상담과 분리해 `기업·제휴 문의`로 둔다.

## 5. 토스에서 참고할 디자인 문법

토스의 자산·소스·전용 폰트를 복제하지 않는다. 다음 원칙만 BRING CARE 디자인 시스템으로 번역한다.

### Typography

- 한국어 기본 글꼴: 프로젝트에서 합법적으로 배포 가능한 `Pretendard Variable` 또는 현재 사용 중인 동급 산세리프
- Hero: 데스크톱 64–76px / 모바일 42–50px, 800–900 weight, line-height 1.06–1.12
- Section headline: 데스크톱 44–56px / 모바일 32–40px, 800–900 weight
- Card headline: 22–28px, 750–850 weight
- Body: 16–19px, line-height 1.65–1.8
- 숫자·가격은 본문보다 한 단계 크게 하고 자간을 좁힌다.
- 한 문단은 모바일에서 3–4줄을 넘기지 않는다.

### Color

- Page canvas: `#F4F7FB`
- Card: `#FFFFFF`
- Primary ink: `#0B2748`
- Secondary ink: `#5D7187`
- Accent: `#1769FF`
- 강한 남색 전체 배경 전환은 사용하지 않는다.
- 강조는 파란색 버튼, 외곽선, 숫자, 작은 라벨로 제한한다.

### Spacing and shape

- 데스크톱 섹션 간격 120–160px, 모바일 72–96px
- 카드 반경 24–32px
- 버튼 반경 14–18px
- 카드 테두리 `rgba(11,39,72,0.08)`
- 그림자는 넓고 옅게 사용한다. 카드마다 강한 그림자를 반복하지 않는다.
- 한 화면에는 하나의 가장 큰 결론만 둔다.

### Motion

- 스크롤 진입 시 12–20px의 짧은 상승과 투명도 전환
- 시간관리 트랙과 관리 프로세스는 선이 진행되는 가벼운 애니메이션
- `prefers-reduced-motion`을 지원한다.
- 장식 목적의 과도한 패럴랙스는 사용하지 않는다.

### 사진이 필요하지 않은 구간

- 관리 프로세스
- Turnaround Time
- 가격 포함·제외 범위
- 관리보고 KPI

이 구간은 다이어그램과 실제 앱형 UI가 사진보다 이해가 빠르다.

## 9. 구현 경계

- `/building-care` 전용 구성요소로 분리한다.
- 다른 세 개 광고페이지의 구조와 스타일을 변경하지 않는다.
- 기존 공통 폼과 연락처 모듈을 재사용한다.
- 사례와 가격은 데이터 구조로 분리해 추후 수정 가능하게 한다.
- 이미지에는 의미 있는 대체텍스트를 제공한다.
- 모바일, 태블릿, 데스크톱을 모두 검증한다.
- 기존 Analytics 이벤트가 있다면 CTA 이름을 바꾸더라도 추적이 유지되게 한다.

## 10. QA 기준

- 3초 안에 대상·서비스·가격을 이해한다.
- 두세 번 스크롤 안에 왜 필요한지 이해한다.
- Building Care가 본사업이고 청소는 진입상품임이 보인다.
- 89,000원의 포함·제외 범위가 오해 없이 구분된다.
- 입퇴실 패키지와 공실 시간관리 개념이 시각적으로 이해된다.
- 실제 사례와 실제 보고서가 충분히 보인다.
- 공인중개·법정점검·미개발 기술을 과장하지 않는다.
- 일반 고객 CTA와 기업 제휴 CTA가 혼동되지 않는다.
- 토스와 유사한 명료함은 느껴지지만 토스의 자산을 복제하지 않는다.
