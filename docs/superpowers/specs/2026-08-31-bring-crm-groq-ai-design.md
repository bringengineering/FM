# BRING CRM Groq AI 연동 설계

## 목표

BRING CRM의 기존 고객·상담·작업 흐름 안에서 전 직원이 같은 AI 기능을 사용한다. 첫 범위는 `AI 비서`와 `상담 기록 자동정리`다. Groq API 키와 고객 개인정보는 데스크톱 프로그램 및 GitHub에 노출하지 않는다.

## 확정 범위

### AI 비서

CRM 탐색 메뉴에 `AI 비서`를 추가한다. 직원은 직접 입력한 업무 내용 또는 CRM에서 선택한 고객·상담·작업의 허용된 필드를 바탕으로 다음 결과를 요청할 수 있다.

- 상담 요약
- 다음 행동 추천
- 영업 문자 초안
- 작업·수익 보고서 초안

생성 결과는 초안으로만 표시한다. AI가 고객·상담·할 일·작업 데이터를 자동 저장하거나 외부로 발송하지 않는다. 직원이 결과를 검토한 후 기존 CRM 저장 기능으로 반영한다.

### 상담 기록 자동정리

상담 기록 작성 영역에 `AI로 정리` 동작을 추가한다. 입력된 상담 원문을 기준으로 다음 필드를 제안한다.

- 상담 요약
- 고객의 현재 요청
- 상담 결과
- 다음 행동

상담 원문은 유지하며 제안값은 저장 전에 직원이 수정하거나 폐기할 수 있다. 빈 입력, 지나치게 긴 입력, 지원하지 않는 형식은 클라이언트에서 먼저 안내한다.

## 아키텍처

```text
BRING CRM 데스크톱 앱
  -> Firebase 로그인 토큰과 AI 요청
BRING CRM AI Gateway (별도 Cloudflare Worker)
  -> 사용자 인증·권한 확인
  -> 입력 허용 목록 검사·개인정보 마스킹·길이 제한
  -> Cloudflare Secret의 Groq API 키로 요청
Groq Cloud / Qwen
  -> 구조화된 초안 응답
AI Gateway
  -> 출력 형식·크기 검사
BRING CRM
  -> 직원 검토 후 선택적으로 저장
```

기존 `bring-care-kakao-intake` Worker에는 AI 기능을 섞지 않는다. 같은 Cloudflare 계정에 별도 Worker를 두어 카카오 민원 접수 장애와 CRM AI 장애를 분리한다.

## 구성 요소와 책임

### CRM AI 클라이언트

- AI 기능별 요청 형식을 생성한다.
- 현재 Firebase 사용자의 ID 토큰을 요청에 포함한다.
- AI 응답을 초안 UI에 표시한다.
- 재시도, 취소, 원문 유지와 직원 확인을 담당한다.
- Groq API 키와 모델 공급자 자격증명을 알지 못한다.

### AI Gateway

- 허용된 Origin, HTTP 방식, 본문 크기와 기능 종류만 수락한다.
- Firebase ID 토큰을 서버에서 검증하고 CRM 허용 직원인지 확인한다.
- 허용된 필드만 추출하고 전화번호·이메일·계좌번호·주민등록번호 형태를 마스킹한다.
- 기능별 고정 시스템 지시문과 출력 스키마를 적용한다.
- 직원별·전체 요청 제한을 적용한다.
- Groq 오류를 내부 정보가 없는 CRM용 오류 코드로 변환한다.
- 원문, 마스킹 전 개인정보, 인증 토큰, Groq API 키를 로그에 남기지 않는다.

### Groq 공급자 어댑터

- 모델 ID와 Groq 호출 형식을 Gateway 내부에 격리한다.
- 응답을 CRM 공통 형식으로 변환한다.
- 향후 Gemini, OpenAI, Ollama로 교체해도 CRM UI 계약은 유지한다.

## API 계약

첫 버전은 단일 `POST /v1/assist` 엔드포인트를 사용한다.

요청의 의미 필드는 다음으로 제한한다.

- `task`: `assistant_summary`, `next_action`, `sales_message`, `work_report`, `consultation_structure`
- `content`: 직원이 직접 입력했거나 CRM이 허용 목록으로 구성한 텍스트
- `context`: 고객 유형, 업무 유형, 담당자처럼 비민감 업무 문맥

응답은 `ok`, `requestId`, `result`, `warnings`로 정규화한다. `consultation_structure`의 `result`는 `summary`, `currentRequest`, `outcome`, `nextAction` 필드를 가진다. 공급자의 원본 응답은 CRM에 전달하지 않는다.

## 개인정보와 보안

- Groq 키는 Cloudflare Secret `GROQ_API_KEY`로만 저장한다.
- 소스코드, `.env` 커밋, GitHub Actions 변수, CRM 빌드 산출물에는 키를 넣지 않는다.
- 마스킹 전 원문은 Gateway 메모리에서 요청 처리 동안만 사용하고 저장하지 않는다.
- 자유형 개인 메모는 기본적으로 AI 전송 대상에서 제외한다.
- 전화번호, 이메일, 계좌번호, 주민등록번호 유사 패턴은 Groq 전송 전에 치환한다.
- 건물 주소는 업무상 필요한 경우에만 시·군·구 수준 또는 비식별 별칭으로 축약한다.
- AI 결과는 사실 확정값이 아닌 초안임을 UI에 표시한다.

무료 Gemini와 달리 Groq의 데이터 처리 조건도 운영 적용 직전에 재확인한다. 조건이 고객정보 처리 기준을 충족하지 않으면 마스킹된 비민감 요청만 허용하거나 공급자를 교체한다.

## 오류 처리

- `401/403`: 다시 로그인하거나 권한을 확인하도록 안내한다.
- `413`: 입력을 줄이도록 안내하며 원문은 보존한다.
- `429`: 무료 한도 또는 직원별 제한 도달을 안내하고 CRM 업무는 계속 사용할 수 있게 한다.
- 공급자 장애·시간 초과: 한 번의 제한된 서버 재시도 후 일시 장애로 응답한다.
- 잘못된 AI 출력: 저장 후보로 표시하지 않고 다시 시도할 수 있게 한다.

AI 실패는 CRM의 고객·상담·작업 저장 기능을 차단하지 않는다.

## 사용량과 운영

- 로그에는 요청 ID, 익명 사용자 식별자, 기능 종류, 성공 여부, 처리 시간, 토큰 사용량만 남긴다.
- 무료 한도 보호를 위해 직원별 분당·일일 호출 제한과 회사 전체 일일 제한을 둔다.
- 모델명과 제한값은 Worker 설정으로 관리한다.
- 무료 한도가 끝나면 자동 유료 결제로 전환하지 않고 명시적으로 중단한다.

## 테스트와 완료 기준

### 자동 테스트

- 로그인 토큰 없음, 변조 토큰, 미허용 사용자를 거부한다.
- 허용된 사용자는 지원하는 각 기능을 호출할 수 있다.
- 전화번호·이메일·계좌번호·주민등록번호 형태가 공급자 요청 전에 마스킹된다.
- 개인 메모와 허용되지 않은 필드가 공급자 요청에 포함되지 않는다.
- 본문 크기, 기능 종류, 출력 스키마와 호출 제한이 검증된다.
- Groq의 429, 시간 초과, 비정상 JSON이 안전한 오류로 변환된다.
- 저장소와 패키징 산출물에서 Groq 키 형태가 발견되지 않는다.
- AI 장애 중에도 기존 CRM 저장 테스트가 통과한다.

### 운영 검증

- Cloudflare Worker Secret 등록 후 상태 확인이 성공한다.
- 대표 계정과 현진님 계정에서 동일한 AI 기능을 사용할 수 있다.
- 비로그인 상태와 미허용 계정은 호출할 수 없다.
- 실제 CRM에서 상담 원문을 정리하되 직원 승인 전에는 데이터가 변경되지 않는다.
- 다른 PC의 최신 CRM에서도 별도 AI 설치 없이 기능이 작동한다.

## 배포와 롤백

- AI Gateway와 CRM 변경은 독립적으로 배포한다.
- Gateway가 준비되지 않은 CRM에서는 AI 메뉴를 비활성화하고 기존 기능을 유지한다.
- CRM 자동 업데이트 채널의 다음 미사용 버전으로만 배포하며 기존 태그를 이동하거나 재사용하지 않는다.
- 문제 발생 시 Worker의 AI 기능 플래그를 끄면 CRM 재배포 없이 AI 호출을 중단할 수 있다.

## 제외 범위

- AI의 CRM 데이터 자동 저장
- AI가 고객에게 문자·이메일·카카오 메시지를 자동 발송하는 기능
- 고객 전체 데이터베이스를 Groq에 일괄 전송하는 기능
- 모델 학습 및 파인튜닝
- 음성 전사와 이미지 분석
- Firebase Functions 및 Hosting 신규 배포
