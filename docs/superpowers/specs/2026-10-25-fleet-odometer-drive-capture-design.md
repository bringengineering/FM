# 차량대장 계기판 촬영·Google Drive 저장 설계

## 목표

공용차량 운행 시작 시 출발 km와 계기판 사진을 모두 필수로 받고, 휴대폰 후면 카메라로 촬영한 사진을 회사 Google Drive의 `내 드라이브/브링 케어/BRING CAR` 아래에 안전하게 저장한다. Drive 업로드가 확인된 경우에만 운행기록을 생성한다.

## 확정 요구사항

- 운행 목적과 목적지는 필수 자유 입력이다.
- 출발 km는 다시 필수로 지정하며, 숫자·정수·현재 계기판 이상인지 검증한다.
- 출발 계기판 사진은 필수다.
- 휴대폰에서는 `사진 촬영` 버튼이 후면 카메라를 우선 실행한다.
- 촬영 후 미리보기를 보여주고 `다시 촬영`할 수 있다.
- 사진은 Google Drive의 `브링 케어/BRING CAR/계기판 사진/YYYY-MM`에 저장한다.
- 파일명은 `YYYYMMDD-HHmm_직원명_출발km_운행번호.jpg` 형식으로 만든다. 파일명에 사용할 수 없는 문자는 제거한다.
- Drive 연결·권한 확인 또는 업로드가 실패하면 운행 시작을 생성하지 않는다.
- Realtime Database에는 대용량 data URL을 저장하지 않고 Drive 파일 ID, Drive 열기 URL, 파일명과 업로드 완료 상태만 기록한다.

## 선택한 접근 방식

기존 현장 앱에서 운영 중인 Google Identity Services, `GoogleDriveClient`, 회사 Drive 인증 흐름을 재사용한다. PC의 `H:` 드라이브는 Google Drive 데스크톱 동기화 경로이므로 브라우저 앱이 직접 쓸 수 없다. 앱은 동일 폴더의 안정적인 Google Drive 폴더 ID를 확인해 Drive API로 업로드한다.

다른 선택지는 Firebase Storage에 먼저 올린 뒤 서버에서 Drive로 복사하는 방식과 PC 로컬 경로에 직접 저장하는 방식이다. 전자는 저장소 이중화와 서버 운영 범위가 불필요하게 커지고, 후자는 휴대폰에서 작동하지 않아 제외한다.

## 사용자 흐름

1. 직원이 차량대장에 로그인하고 `운행 시작`을 연다.
2. 앱은 회사 Google Drive 연결 상태와 `BRING CAR` 폴더 쓰기 권한을 확인한다.
3. 직원이 운행 목적, 목적지, 출발 km를 입력하고 `계기판 사진 촬영`을 누른다.
4. 후면 카메라로 촬영한 사진의 미리보기, 파일 정보와 `다시 촬영` 버튼을 보여준다.
5. `운행 시작`을 누르면 입력 검증 후 사진을 JPEG로 회전 보정·축소·압축한다.
6. 앱이 월별 폴더를 찾거나 만들고 사진을 Drive에 업로드한다.
7. 업로드 응답의 파일 ID를 확인한 뒤 운행기록과 차량 상태를 저장한다.
8. 업로드 실패 시 입력과 촬영본을 화면에 유지하고 재시도 안내를 표시한다.

## 폴더 및 파일 규칙

- 고정 루트: 사용자가 만든 Google Drive 폴더 `내 드라이브/브링 케어/BRING CAR`
- 자동 하위 폴더: `계기판 사진/YYYY-MM`
- 파일명 예: `20261025-0930_김민욱_1280km_-Oabc123.jpg`
- Drive `appProperties`에는 운행 ID, 사용자 UID, 차량 ID, 촬영 시각과 출발 km를 기록해 중복 업로드를 찾을 수 있게 한다.
- 동일 운행 ID의 파일이 이미 있으면 새 파일을 만들지 않고 기존 파일을 재사용한다.

## 데이터 모델과 보안

운행기록의 기존 `evidenceUrl` data URL은 새 기록에서 사용하지 않는다. 대신 `evidenceDriveFileId`, `evidenceDriveUrl`, `evidenceFileName`, `evidenceUploadState: "complete"`를 필수로 저장한다. Firebase 규칙은 새 필드의 형식과 업로드 완료 상태를 검증하며, 사진 원본 data URL 저장은 차단한다.

Drive OAuth 토큰은 메모리에만 보관하고 DB·로컬 스토리지·로그에 기록하지 않는다. 기존 회사 Google 계정 로그인 힌트와 지정 루트 쓰기 권한 검증을 그대로 사용한다. 다른 폴더 ID로의 업로드는 허용하지 않는다.

## 오류 처리

- Drive 미연결: `Google Drive 연결` 버튼을 표시하고 운행 시작을 비활성화한다.
- 폴더 권한 없음: `BRING CAR 폴더 편집 권한을 확인해 주세요.`를 표시한다.
- 업로드 일시 실패: 입력과 사진 미리보기를 유지하고 같은 운행 ID로 재시도한다.
- DB 저장 실패: Drive 파일 ID를 유지해 재시도 시 중복 파일을 만들지 않는다.
- 촬영 취소·지원되지 않는 파일·10MB 초과: 운행 시작 전에 명확한 오류를 표시한다.

## 검증 계획

- 출발 km 공란·소수·현재 km 미만을 거부하는 단위 테스트
- 사진 미선택, Drive 미연결, 업로드 실패 시 운행기록이 생성되지 않는 테스트
- 폴더 경로·파일명 정규화·동일 운행 ID 중복 방지 테스트
- Firebase 규칙에서 Drive 증빙 필드 누락과 data URL을 거부하는 에뮬레이터 테스트
- Android/iPhone 폭에서 카메라 촬영, 미리보기, 다시 촬영, 업로드 상태를 육안 검수
- 실제 지정 Google Drive 폴더에 테스트 사진 1장을 올리고 파일 ID·경로·열기 링크를 확인한 뒤 테스트 파일은 제거한다.

## 범위 밖

이번 변경에는 도착 계기판 사진의 Drive 이전, 기존 DB data URL 일괄 마이그레이션, 차량별 별도 Drive 루트, 오프라인 업로드 큐는 포함하지 않는다. 출발 촬영 흐름을 안정화한 뒤 같은 구조로 확장할 수 있다.
