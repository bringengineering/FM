# BRING CARE 건물관리 랜딩 시각 전환 개편안

## 1. 목표

현재 `/building-care`의 판매 흐름은 유지하면서, 글을 읽기 전에 서비스와 차이를 이해할 수 있는 시각 블록을 추가한다. 정체성은 **실제 현장사진으로 증명하고, 표와 도식으로 이해시키는 건물관리 회사**로 정의한다.

## 2. 참고 원칙

- 아정당 랜딩에서 참고할 요소: 아이콘형 서비스 탐색, 구조화된 비교표, 단계 도식, 후기 카드, 반복 CTA.
- 복제하지 않을 요소: 아정당 고유 문구·이미지·아이콘·레이아웃 수치·코드.
- BRING CARE 고유 자산: 실제 관리 현장사진, 월간 관리보고, 원주 직영 운영, 사전 승인 원칙, 공실·입퇴실 관리 흐름.
- 실제 고객후기·평점·보상 수치는 확인된 근거가 없으면 노출하지 않는다.

## 3. 확정 방향: 증거 중심 하이브리드

실사, 서비스 아이콘, 비교표, 관리 도식, 후기 또는 현장 기록을 결합한다. 단순한 서비스 소개가 아니라 `왜 필요한지 → 무엇을 하는지 → 무엇이 포함되는지 → 실제로 했는지 → 어떻게 확인하는지`를 한눈에 이해시키는 구조다.

## 4. 추가·개편 블록

### 4.1 서비스 아이콘 메뉴

첫 문제 제기 직후 6개 아이콘 카드를 배치한다.

1. 공실 관리
2. 입·퇴실 관리
3. 공용부 청소
4. 시설 점검
5. 민원 연결
6. 수리·보수 조율

각 카드는 3D 일러스트 대신 단순한 청색 계열 그래픽 아이콘, 제목, 한 줄 효익으로 구성한다. 모바일에서는 2열, 데스크톱에서는 6열이다.

### 4.2 직접 관리 vs BRING CARE 비교표

행은 `연락 창구`, `현장 확인`, `업체 조율`, `완료 확인`, `관리 기록`, `월간 보고`로 구성한다. 열은 `건물주 직접 관리`와 `BRING CARE 관리`다. BRING CARE 열을 청색 외곽선과 옅은 배경으로 강조한다. 직접 관리 열을 과도하게 비하하지 않고, 절차 차이를 사실적으로 표시한다.

### 4.3 월 관리비 포함·별도 표

월 89,000원 기본관리 범위와 별도 실비 항목을 구분한다.

- 기본 포함: 정기 현장확인, 공실·공용부 상태 기록, 문의 연결, 업체 조율, 월간 관리보고.
- 별도 작업: 청소 작업비, 수리·자재비, 폐기물 처리, 전문 시공.
- 하단 고정 문구: `별도 비용이 필요한 작업은 범위와 금액을 먼저 안내하고 승인 후 진행합니다.`

### 4.4 관리 도식

`확인 → 조율 → 처리 → 보고`를 네 개의 시각 카드와 연결선으로 표현한다. 각 단계에는 실제 사진 한 장 또는 사진 일부를 배치해 텍스트-only 흐름도를 피한다.

### 4.5 실제 관리기록 카드

공개 가능한 고객후기가 확보되기 전에는 임의 후기를 만들지 않는다. 대신 실제 현장사진과 함께 `상황 / 확인 / 조치 / 결과 기록`을 보여주는 관리기록 카드를 사용한다. 현재 실제 사진 5건을 활용한다.

후기 문구가 확보되면 다음 조건으로 교체 또는 추가한다.

- 고객 동의 확인
- 이름·주소 비식별화
- 실제 문구의 의미를 바꾸지 않음
- 임의 별점과 평균점수를 만들지 않음

### 4.6 운영 기준 비교

`일반 개별관리`와 `BRING CARE 운영`을 겹친 카드 형태로 비교한다.

- 여러 업체 개별 연락 → BRING CARE 한 곳에 요청
- 완료 여부 직접 확인 → 사진과 기록으로 확인
- 비용 발생 후 확인 → 사전 안내·승인 후 진행
- 기록 분산 → 월간 관리보고로 정리

보험·보상처럼 오해될 수 있는 `보장` 표현은 사용하지 않는다.

## 5. 페이지 순서 변경

기존 14개 구간의 큰 판매 흐름은 유지한다. 새 섹션 ID를 늘리지 않고 기존 구간 내부를 시각화한다.

1. Hero: 기존 유지
2. Owner problem: 서비스 아이콘 메뉴 추가
3. One contact: 직접 관리 vs BRING 비교표로 강화
4. Care system: 실사 포함 관리 도식으로 변경
5. Management process: 아이콘형 단계 도식
6. Turnover package: 기존 유지
7. Turnover time: 시각 대비 강화
8. Price: 포함·별도 비교표 추가
9. Entry services: 기존 유지
10. Real cases: 관리기록 카드 구조로 강화
11. Report: 기존 유지
12. Trust: 운영 기준 비교 카드 추가
13. FAQ: 기존 유지
14. Consultation: 기존 CRM 폼·카카오·전화 유지

## 6. 시각 시스템

- 배경: `#F4F7FB` 단일 계열 유지
- 카드: 흰색, 24~28px 라운드, 약한 경계선, 2단 그림자
- 강조: `#1769FF`
- 제목: 굵은 산세리프, 큰 크기, 짧은 문장
- 아이콘: 청색·하늘색 기반의 동일한 선 굵기
- 표: 모바일에서 가로 스크롤 대신 행별 카드로 재배치
- 사진: 실제 기록에는 `BRING CARE 실제 관리기록` 표기
- 캠페인/AI 이미지는 실제 실적 구간에 사용하지 않는다.

## 7. 데이터·전환 유지

- CRM 제출 로직과 `sourcePath=/building-care` 유지
- 전화 `010-6566-3603` 유지
- 카카오톡 `https://pf.kakao.com/_xnaRfX/chat` 유지
- 기존 가격 `월 89,000원부터`, 부가세 별도, 기본 6개월 유지
- 다른 세 랜딩 페이지는 변경하지 않는다.

## 8. 검증 기준

- 기존 14개 섹션 ID와 순서 유지
- 6개 서비스 아이콘 카드 렌더링
- 직접 관리 vs BRING 비교표 렌더링
- 관리비 포함·별도 표 렌더링
- `확인 → 조율 → 처리 → 보고` 도식 렌더링
- 실제 관리기록 이미지 최소 5장 유지
- 허위 고객후기·별점·보장 문구 없음
- 데스크톱과 모바일 레이아웃 확인
- CRM 폼, 전화, 카카오 링크 테스트
- 전체 랜딩 테스트, 빌드, Firebase 정적 내보내기, Hosting 배포 후 공개 URL 확인

## 9. 범위 제외

- 고객후기 수집 시스템
- 보험 또는 보상 상품
- 실제 월간 보고서 자동 생성 기능
- 다른 랜딩 페이지 전면 개편
