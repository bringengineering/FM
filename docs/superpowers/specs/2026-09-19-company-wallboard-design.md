# 회사 운영보드 · 시각화 및 TV 재생 설계

## 목적과 승인된 방향
사내 프로그램 작업 폴더 선택 화면에 `회사 운영보드`를 CRM과 동등한 독립 폴더로 추가한다. 직원 업무를 공개 순위로 평가하기보다 담당·마감·진행·성과·지원 요청을 시각적으로 리마인드한다. 기존 업무와 일정을 복제하거나 수정하지 않는다.

## 기존 구조
`desktop-crm/src/workspace-shell.js`의 LANDING_FOLDERS는 운영 내부 폴더를 독립 카드로 노출한다. 이 구조에 navFolder=company-wallboard, view=companyWallboard를 추가한다. 새 운영 서버나 중복 CRM을 만들지 않는다. `app.js`에는 라우팅과 수명주기 연결만 추가하고 집계·화면·CSS는 별도 모듈로 분리한다.

## 대안과 선택
1. 기존 사내 프로그램에 독립 폴더와 전용 재생 컴포넌트 추가: 선택. 기존 권한과 데이터 접근을 재사용한다.
2. CRM 대시보드 그대로 확대: 사용자 요구와 다르고 작은 글씨·민감정보 노출 위험이 있다.
3. 처음부터 별도 서비스로 분리: TV 배포는 편하지만 인증·데이터·관리 화면이 중복된다. 1단계의 안전한 표시 모델을 재사용하는 전용 TV 클라이언트는 2단계로 구현한다.

## 1단계: 사내 프로그램의 시각화와 재생 검증
- 독립 폴더 안에서 관리 도구와 TV 미리보기를 제공한다. 운영 데이터 쓰기 없이 권한 내 조회만 사용한다.
- 업무 화면: 담당자별 큰 카드, 마감 배지, 시작 전/진행/검수/보완/완료 상태 분포. 이름을 코드에 고정하지 않고 서버 회원과 업무에서 가져온다.
- 시간표 화면: 날짜와 시간축, 현재 시간선, 다음 일정. 시간 미정/종일 일정은 별도 구역에 표시한다. 기존 일정만 사용하고 Google 캘린더는 연결하지 않는다.
- 이슈 화면: 지연·보완 요청·확인이 필요한 항목의 건수와 상태 카드. 업무 기한 초과를 민원 긴급도로 임의 해석하지 않는다.
- 성과 화면: 검수 완료/전체와 상태별 막대그래프. 입력 진행률과 완료율은 구분한다. 실제 목표 수치가 없는 지표는 달성률을 만들지 않는다.
- 공지 화면: 미리보기용 문구 입력. 1단계는 해당 컴퓨터의 로컬 편성임을 명시하고 원격 게시 완료로 표시하지 않는다.
- 모든 화면은 큰 제목, 숫자, 도형, 상태 아이콘, 짧은 라벨을 중심으로 구성한다. 긴 표나 본문을 TV에 그대로 붙이지 않는다.
- 기본 화면당 30초. 화면별 10~120초, 활성화, 순서 변경, 이전/다음, 자동 재생/일시정지, 화면 고정을 지원한다.
- 활성 화면이 없으면 안내 화면을 보여준다. 데이터가 많으면 자동 페이지 분할하며 잘린 자료를 전체처럼 표시하지 않는다.
- 전체화면은 사용자가 재생 버튼을 누를 때 요청한다. 실패 시 일반 화면 재생을 유지하며 Esc로 복귀할 수 있다.
- 초기 기준 해상도 1920×1080, 1280×720 대응. 제목 40px 안팎, 주요 숫자 56px 이상, 본문 24px 안팎을 기준으로 실제 잘림과 대비를 검수한다. 흰색·파란색 기존 브랜드와 명확한 상태 색상을 사용한다.

## 데이터·보안 계약
표시 전용 모델은 업무 식별자, 안전한 표시명, 담당자 표시명, 상태, 날짜, 프로젝트 표시명, 집계 숫자만 허용한다. 고객 전화번호·이메일·출입정보·개인 메모·급여·원문 결과보고서는 포함하지 않는다. 자유 입력 업무명에도 민감정보가 있을 수 있어 TV에 자동 공개하지 않고 승인된 표시 제목 또는 일반화된 제목을 사용한다. 미리보기에도 같은 보호 정책을 적용한다.

조회 로딩/정상/실패/오래된 자료를 구분한다. 마지막 성공 갱신 시각을 유지하고 실패 시 갱신 시각을 현재로 바꾸지 않는다. 자료가 없는 상태와 조회에 실패한 상태는 다른 화면으로 표시한다. 60초 갱신은 중복 요청 없이 수행하고 화면 이탈·로그아웃 시 요청 결과 반영과 타이머를 해제한다. 권한이 없는 데이터는 클라이언트 표시뿐 아니라 원래 데이터 접근 정책을 따른다.

## 2단계: TV 컴퓨터와 원격 운영
1단계 미리보기를 실제 TV 원격 운영 완료로 표현하지 않는다. 전용 기기 등록/해제와 조회 전용 인증, 서버의 표시 필드 제한, 관리자 편성 저장을 구현한 뒤 TV 클라이언트를 연결한다. 링크만 알아도 회사 정보를 볼 수 있는 공개 URL은 만들지 않는다. 기존 직원 관리자 세션을 TV에 복사하지 않는다.

서버 편성 변경→TV 갱신, 버전 표시·안전한 화면 업데이트, 기기 마지막 접속, 예약 편성·긴급 공지 만료를 검증한다. Windows 자동 실행과 원격 지원은 TV 컴퓨터의 OS·접근 승인 확인 후 설정한다. 원격 프로그램 설치나 OS 변경은 1단계 범위가 아니다. Firebase Hosting·Functions 배포는 기존 제한을 유지한다.

## 이후 확장
현장 사진·영상은 게시 승인·접근 권한·유효기간을 갖춘 자료만 지원한다. 다중 TV 그룹·시간대별 편성과 외부 뉴스는 별도 후속 범위다. 브라우저 임의 사이트 iframe이나 공개 영상 자동재생을 1단계에 넣지 않는다.
