# 브링 차량대장 다중 차량 설계

## 목표

기존 EV4 차량대장에 `기아 모닝(23모 0648)`을 추가하고, 사용자가 차량을 선택한 뒤 일정 확인·예약·출차·운행 종료·이상 신고·운행기록을 차량별로 처리하게 한다. 기존 EV4 자료는 변경하거나 이전하지 않는다.

## 차량 기본값

- EV4: 기존 `ev4-001` 데이터와 계약·정비 정보를 그대로 사용한다.
- 모닝: ID는 `morning-001`, 이름은 `기아 모닝`, 차량번호는 `23모 0648`로 생성한다.
- 모닝 초기 주행거리는 미등록 상태로 취급한다. 첫 운행 시작 시 사용자가 입력한 출발 km와 계기판 사진을 기준으로 현재 주행거리를 표시한다.

## 사용자 흐름

1. 홈 화면 상단에서 EV4와 모닝을 선택한다.
2. 선택한 차량의 현재 상태, 계기판 km, 현재 운행자와 주요 메뉴만 표시한다.
3. 일정표는 선택 차량의 예약만 보여준다.
4. 새 예약, 출차, 운행 종료, 이상 신고는 선택 차량 ID로 저장한다.
5. 운행기록은 기본적으로 선택 차량 기록만 보여주며 차량 전환으로 다른 차량 기록을 확인한다.
6. 관리자의 승인·반려도 현재 선택 차량의 예약에만 적용한다.

## 데이터 구조

기존 Firebase `crmCompany/fleetManagement` 구조를 유지한다. `vehicles/morning-001`만 추가하며, trips·reservations·issues·maintenance·contracts의 기존 `vehicleId` 필드를 실제 선택 차량 ID로 기록한다. 기존 문서와 보안 규칙의 스키마는 변경하지 않는다.

초기화 함수는 멱등적으로 동작해야 한다. EV4가 이미 있더라도 모닝이 없으면 모닝만 추가하고, 기존 차량·운행·예약 자료를 덮어쓰지 않는다.

## 화면 설계

- 홈과 일정표 상단에 두 차량을 전환하는 큰 탭을 둔다.
- 각 탭에는 차량명과 차량번호를 표시하고 선택 상태는 브랜드 라임색으로 강조한다.
- 모닝 km가 아직 없을 때는 `첫 운행 시 등록`으로 표시한다.
- 모바일에서 한 손으로 누를 수 있도록 탭과 주요 버튼의 높이는 44px 이상으로 유지한다.
- 현재 운행 중인 차량을 다른 사용자가 선택하면 `운행 중` 상태를 명확히 표시하고 새 출차는 막는다.

## 동작 및 오류 처리

- 차량을 바꾸면 일정표·기록·현재 km·운행 상태가 즉시 해당 차량 기준으로 다시 계산된다.
- 예약 충돌 검사는 같은 차량 안에서만 수행한다. 서로 다른 차량의 같은 시간 예약은 허용한다.
- 사용자가 운행 중인 차량이 있으면 해당 차량에서만 종료 화면으로 진입한다.
- 저장 요청에 차량 ID가 없거나 등록되지 않은 차량이면 사용자에게 오류를 표시하고 저장하지 않는다.
- 사진 업로드 파일명과 Drive 메타데이터에 차량 ID를 포함해 두 차량 사진을 구분한다.

## 검증

- 모닝 초기 생성이 기존 EV4 자료를 덮어쓰지 않는지 테스트한다.
- 차량 전환 시 홈·일정표·운행기록이 해당 차량 자료만 표시하는지 테스트한다.
- 예약·출차·이상 신고에 선택 차량 ID가 저장되는지 테스트한다.
- 예약 충돌이 동일 차량에서만 차단되는지 테스트한다.
- 타입 검사, 린트, 프로덕션 빌드, Firebase 규칙 테스트와 실제 운영 화면 검수를 수행한다.

## 제외 범위

- 모닝의 계약·렌트 정보와 정비 기준은 이번 작업에서 임의 생성하지 않는다.
- 모닝의 실제 주행거리는 관리자가 추정하여 입력하지 않는다.
- 기존 EV4 운행 및 예약 자료를 모닝으로 이동하지 않는다.
