# 회사 방향 승인본의 TV 운영보드 연결 설계

## 목적과 범위

CRM 프로젝트 관리에서 대표가 게시한 회사 방향 승인본만 TV 자동 순환에 표시한다. 기존 로드맵·업무·일정 장면과 TV 기기 인증, 게시·자동 갱신 경로는 유지한다. 이번 범위는 회사 비전, 조직의 표시 이름·역할, 연간·반기 목표와 확인 가능한 달성률이다. 매출·분기 목표·Gemini 요약은 별도 데이터 근거와 승인 흐름이 마련되기 전까지 추가하지 않는다.

## 확정한 접근

기존 Cloudflare TV 게시 스냅샷에 안전하게 축약한 `strategy` 모델을 추가한다. TV 기기가 Firebase를 직접 읽거나 초안을 복사하지 않는다. 자동 서버 재게시가 CRM의 `companyStrategyPublications/<year>`에서 해당 연도 승인본을 읽고, 검증 후 TV 전용 모델로 투영한다. 대표가 승인본을 게시한 뒤 기존 갱신 주기에 반영된다. 운영 배포 전에는 기존 TV 게시 규칙과 새 필드의 하위 호환성을 검증한다.

## 승인과 데이터 경계

- 기준 연도는 서버의 한국 시간 현재 연도다. 해당 연도 승인본이 없으면 `strategy`는 `null`이고 장면을 편성에서 제외한다. 이전 연도의 비전을 현재 목표로 보이지 않는다.
- 승인본의 `content`를 JSON으로 파싱하고 `company-strategy-core.validatePublication`으로 재검증한다. 형식이나 승인 참조가 틀리면 새 게시를 거부한다. 초안만 있는 경우에는 장면을 만들지 않는다.
- TV 모델은 `year`, `vision`, 조직원의 `displayName`·`role`·상하관계용 화면 내부 인덱스, 목표의 `period`·`title`·`unit`·`target`·`current`·`percent`·`source`만 허용한다. 원본 UID, 이메일, 전화번호, 주소, 인증정보, 작성자 메타데이터, 고객정보, 개별 평가 및 초안은 보내지 않는다.
- 조직 이름은 승인본의 UID를 현재 활성화된 `access`·`teamProfiles`와 서버에서 대조해 얻는다. 일치하지 않거나 표시명이 안전한 형식이 아니면 해당 사람의 이름은 `담당자`로 표시한다. TV에는 UID를 보내지 않는다.
- 숫자 목표의 달성률은 기존 `projectStrategy` 계산을 사용한다. 기준값·현재값·목표값이 누락되거나 마일스톤이면 퍼센트를 `null`로 표시하고 `집계 대기`라고 쓴다. 0%로 대체하지 않는다. 확인되지 않은 실적·출처를 생성하지 않는다.
- 목표 `source`는 화면에는 요약된 근거명으로만 표시한다. 연락처·주소 및 민감 문자열이 포함되면 게시를 거부한다. 문자열은 허용 길이와 출력 이스케이프 검증을 거친다.

## 편성과 표시

- 기존 10개 장면은 그대로 둔다. 새 `strategy` 장면은 승인본이 있을 때만 자동 순환에 추가되므로 최대 편성 항목을 11개로 확장한다. 기존 10개 편성과 순서는 변경하지 않고 새 장면을 마지막에 30초로 배치한다.
- 승인본이 없거나 `strategy: null`이면 새 항목이 편성에 있어도 TV는 이를 건너뛴다. 편집 화면은 `승인본 게시 후 표시`라고 안내한다. 기존 게시본을 읽는 구버전 TV는 알 수 없는 새 항목을 무시할 수 있어야 한다.
- 기존 밝은 회색 배경·흰 카드·파란 강조색과 큰 글자 위계를 따른다. 화면은 상단에 비전, 중앙에 조직(이름·역할), 하단에 목표 카드(연간·상반기·하반기)를 둔다. 목표가 많으면 기존 자동 순환의 하위 페이지로 나누고, 작은 화면에서 겹치지 않도록 한다.
- 목표 카드에는 목표값과 현재값을 단위와 함께 표시하고 퍼센트가 확인될 때만 진행 막대를 그린다. 회사 비전과 인원 이름·역할은 원본 승인 문구만 사용한다.
- TV의 자료 기준일과 마지막 게시 시각을 볼 수 있게 한다. 네트워크 조회에 실패하면 로컬 마지막 정상 게시본을 유지하고 `연결 확인 중 · 최근 게시자료 유지` 및 그 게시 시각을 표시한다. 실패한 조회 결과나 빈 초안으로 마지막 승인본을 덮어쓰지 않는다.

## 구현 경계

1. 서버 읽기 권한: TV 전용 서비스 리더에게 `companyStrategyPublications/<year>` 읽기만 허용한다. 초안·쓰기 권한은 주지 않는다. Firebase 규칙 테스트로 다른 경로 접근을 거부하는지 확인한다.
2. 서버 투영: 서버 자동 갱신 모듈이 승인본을 읽고 순수 투영 함수로 허용 필드만 만든다. 서버 게시 전에 폐쇄형 스키마로 검증한다. CRM 프로그램 수동 게시도 같은 투영 함수를 사용해 상이한 TV 모델이 생기지 않게 한다.
3. 게시 계약: `strategy`는 이전 게시본과 호환되도록 선택적 필드로 도입한다. 새 게시본에는 `strategy: null` 또는 검증된 모델을 명시한다. 기존 게시본에는 필드가 없어도 TV가 정상 표시한다.
4. 화면: 웹 TV와 CRM 로컬 미리보기의 장면 키·내용·페이지 수·노출 조건을 일치시킨다. 기존 기기 페어링 및 다른 장면은 바꾸지 않는다.
5. 자동 반영: 승인본 게시 성공 시 기존 서버 재게시 트리거를 호출하고 주기적 재조정도 유지한다. 서버 실패는 진단 상태로 남기되 TV는 마지막 정상 자료를 유지한다.

## 검증 기준

- 승인본이 없거나 초안만 있으면 회사 방향 장면이 보이지 않으며 기존 장면은 정상 순환한다.
- 정상 승인본을 게시하면 서버 재게시 뒤 TV가 사용자 새로고침 없이 같은 값을 표시한다. 목표 수치가 비어 있으면 퍼센트 대신 `집계 대기`를 표시한다.
- 승인본 변경 전·후의 화면과 게시 JSON을 비교해 허용한 필드만 바뀌는지 확인한다. UID, 이메일, 전화번호, 주소, 고객정보, 초안 및 승인되지 않은 Gemini 문구가 포함되지 않는다.
- 서버 조회 실패·권한 오류·잘못된 승인본에서는 새 스냅샷이 게시되지 않고 이전 정상 게시본과 게시 시각을 유지한다.
- 기존 TV 게시본·편성·페어링과 새 편성의 하위 호환 테스트, Firebase 권한 테스트, 데스크톱·Worker 테스트, 1366×768 및 TV 가로 화면 시각 검수를 통과한다.
- 실제 TV 반영 시간과 자동 순환은 두 기기에서 관찰하기 전까지 `현장 검증 완료`로 보고하지 않는다. 운영 배포·승인본 내용 입력은 이 설계의 구현 완료와 별개다.
