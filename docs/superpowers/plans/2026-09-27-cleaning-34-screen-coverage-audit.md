# BRING Cleaning Center 34-screen coverage audit

Date: 2026-09-28
Reference: `BRING_Cleaning_Center_v1.0_Final_34_Screens` (34 numbered PNGs + index.html)
Purpose: distinguish the approved CRM-integrated MVP from the full aspirational mockup set; this is not a claim of 34-screen parity.

## Status definitions

- **MVP now** — the current CRM branch contains a cleaning-specific flow or integration for the capability; still requires production deployment and real-data verification.
- **Reuse / partial** — an existing CRM module can be opened or linked, but the dedicated cleaning-center experience shown in the mockup is not implemented or not verified end-to-end.
- **Later / absent** — not implemented as a cleaning-specific capability in this delivery. Do not advertise it as available.

## Release conclusion

The approved delivery remains an **integrated CRM MVP**, not the complete 34-screen standalone cleaning SaaS. Screen #04 now renders customer 360 from linked CRM customer, building, order, ledger and case records inside the live workspace. Screens #13, #25 and #33 have CRM-bound, source-backed local UI flows for canonical billing rows, guarded refund lifecycle and staff-reported incidents. Screen #30 now reuses the CRM message composer with a canonical order/customer link and existing confirmation policy. Screen #02 now has a local CRM view bound to existing customer/activity/order records, with provider CTI clearly marked disconnected. Screen #31 saves a scheduled consultation into the canonical CRM activity history. Screen #34 now reads a server-validated, read-only weekly supplier-amount summary through the existing order API; the bank payout action stays disabled because required financial controls and ledgers are not present. Pricing policy management, refund, extra-charge and delay endpoints have not been deployed; production build/release, live provider verification, account verification and payout are not connected. Other listed visual and functional gaps remain.

No production deployment, company customer/order data entry or physical TV validation is proven by this audit. `release/firebase-targets.json` currently sets `functionsDeploymentAllowed: false` and archives `cleaningPartnerApi` and `cleaningRefundsApi` alongside the unapproved Functions; the separate manual allowlist remains limited to `cleaningOrdersApi` and `projectCleaningOrdersToWallboard`. A separate approved release action is required before live use can be claimed.
