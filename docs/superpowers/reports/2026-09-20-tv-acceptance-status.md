## 다음 진행 순서

1. 회사 Cloudflare OAuth 승인 후 TV 업데이트 명령이 포함된 Worker만 배포하고 익명·오입력 probe를 다시 통과시킨다. Firebase Functions/Hosting은 배포하지 않는다.
2. `bring-tv-production` Environment에 회사 코드서명 인증서·비밀번호·게시자·지문 비밀값 4개를 등록한다. 현재 Environment와 운영 브랜치 제한은 생성됐지만 비밀값은 비어 있다.
3. PR #118을 검토·병합한 뒤 첫 미사용 `tv-v` 버전을 수동 발행한다. 기존 태그 이동·재사용은 워크플로가 차단한다.
4. 사용자가 TV Windows 컴퓨터에서 최초 서명 설치본을 실행하거나 이미 승인된 원격 접속 방식을 제공한다.
5. 관리자 로그인으로 기기 승인, 게시, 업데이트 예약, 재시작 후 새 버전 보고, 연결 해제를 실제 TV에서 확인한다.
6. 현장 720p/1080p 가독성 및 5개 장면 순환을 캡처로 검증한다.

버전 보고 기능의 서버 선행 배포 완료: `516a0f51-9bb7-4638-984c-5bcf7c62d858` (이전 `6bdb100b-1e63-4c30-87b9-480cfecefeee`). 같은 회사 계정·Worker·저장소이며 설정/마이그레이션 변경 없음. 배포 후 health 200, 정상 버전+미승인 토큰 401, 잘못된 버전 400, 구형 빈 요청+미승인 토큰 401, 익명 관리자 목록 401 확인. 실제 직원 승인·실제 TV 데이터 수신을 검증한 것은 아니다.

기기별 업데이트 예약·취소·상태 보고 변경은 아직 회사 Worker에 배포하지 않았다. 로컬 명령줄의 기존 Cloudflare 토큰은 다른 계정에 묶여 있었고, 회사 계정 OAuth 승인 화면에서 보안 권한 확대 확인을 대기 중이다. 잘못된 계정으로는 배포하지 않았다.

최신 자동검사: desktop 2,192개 중 2,190 통과·의도된 2개 건너뜀, company-site field 510 통과·118 건너뜀, Worker 59 통과, 실제 로컬 SQLite 재시작 검증 통과, company-site typecheck·build 통과. GitHub PR 검사 2개도 모두 성공했다.

로컬 SQLite 검증은 버전 기록 후 런타임 재시작·목록 조회까지 통과했다. 종료 시 임시 번들을 감시하던 도구 오류는 테스트용 파일 감시 비활성화 후 재실행에서 재현되지 않았다.
