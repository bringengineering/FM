## 추가 범위
- `WALLBOARD_DEVICES`: 전용 SQLite Durable Object와 최초 마이그레이션.
- `WALLBOARD_RATE_LIMITER`: TV 경로 전용 IP당 60회/분 제한.
- `WALLBOARD_ENABLED`: TV 경로 활성화. 기존 AI 요청 제한과 저장소를 재사용하지 않음.
- 서버 등록만으로 직원 업무가 공개되지 않음. 기기 관리자 승인과 별도 자료 게시가 필요함.

- 운영 배포와 실제 인증된 TV 수신 검증 결과는 아래에 별도로 기록한다. 아직 완료로 간주하지 않음.

## 문제 발생 시
TV만 문제가 있으면 `WALLBOARD_ENABLED=false`로 비활성화하고 현재 클래스/바인딩/저장소를 유지한 채 재배포한다. 기존 TV 자료와 등록정보를 삭제하지 않는다. 새 Durable Object 마이그레이션이 있으므로 이전 버전으로 무조건 롤백하지 말고, 클래스 없는 이전 버전의 롤백 제약을 확인한다. 기존 AI 기능에 문제가 있으면 검증된 이전 AI 코드를 유지하면서 TV 경로를 비활성화하는 호환 복구 버전을 준비한다.

## 운영 배포 결과
- 회사 OAuth 로그인과 고정 계정으로 배포 성공. 다른 계정의 환경변수는 해당 자식 프로세스에서만 제외했고 전역 인증 설정은 변경하지 않았다.
- 새 운영 버전: `6bdb100b-1e63-4c30-87b9-480cfecefeee`.
- 기존 주소 유지: `https://bring-crm-ai-gateway.bringengineering1008.workers.dev`.
- 실제 health 200, 등록 start 200, 발급된 대기 토큰의 poll 결과 pending 확인. 미승인 등록 1건은 10분 후 만료하며 사용자 데이터·업무 실적은 게시하지 않았다.
- 인증 없는 display/list는 각각 401 AUTH_REQUIRED. 기존 AI 경로도 올바른 요청 형식에서 인증 없을 때 401 AUTH_REQUIRED 확인. 초기 AI 진단 요청이 잘못된 필드로 400을 반환하여 실제 API의 content 필드로 바로잡아 검증했다. AI 모델을 호출하거나 비용을 발생시키는 인증 요청은 하지 않았다.
- 독립 코드 검토에서 배포 차단 문제 없음. 서버 테스트와 별개로 실제 직원 로그인→TV 승인→게시→TV 수신은 아직 미검증.
- Windows 검증 설치본은 로컬에만 있으며, 관리자 UI 변경은 아직 설치된 CRM에 업데이트하지 않았다. 실제 기기 연결과 프로그램 자동 업데이트는 다음 단계다.
