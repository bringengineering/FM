# BRING CRM 3D 설비지도 통합 검증 결과

## 결과와 배포 상태

기존 CRM 본문에 3D 설비지도를 직접 연결했다. iframe 또는 외부 프로그램 실행 방식이 아니다. 건물별 저장 어댑터, 좁은 IPC, 직원 권한, 조건부 저장 및 로컬 DB 규칙 검증을 구현했다.

**로컬 개발 결과이며 운영 배포 완료가 아니다.** 운영 서버 데이터·인증·기존 규칙은 변경하지 않았다. GitHub push, PR 생성, 기존 브랜치 병합, 태그 이동, Functions/Hosting 배포, 자동 업데이트 공개를 수행하지 않았다. 현진님 작업과 운영 기준 이후 변경사항은 배포 전에 다시 대조해야 한다.

## 사용 동선

1. CRM 메뉴 → 3D 설비지도 → CRM 건물 선택.
2. 빈 건물은 확인 후 임시 모형 생성. 기본 지하 1층+지상 1층, 16×12m는 실측값이 아니다.
3. 건물 설정과 설비 기록을 입력하고 저장. 서버 확인 전에는 저장 완료로 표시하지 않는다.
4. 기존 JSON은 원본과 대상 검토 후 가져오기. 이미 모형이 있으면 백업 다운로드와 별도 확인이 필요하다.
5. 연습 모드의 예시 건물·편집은 메모리에만 반영하며 회사 자료를 변경하지 않는다.

## 구현 범위

| 구분 | 반영 내용 |
|---|---|
| CRM 통합 | 메뉴·건물 화면 진입, 건물 ID 연동, 기존 UI 톤, 루트 범위 스타일 |
| 설비 관리 | 10개 데이터 영역, 카탈로그, 사진·문서 근거, 연결 관계, 층 복제 |
| 3D·도면 | 회전·확대·층·레이어·투명화, 평면 좌표·도면 이미지, 배관 경로 |
| 점검 | 점검 일정·담당, 작업 이력·비용, 점검 현황·보고서 |
| 데이터 | 개별/전체 백업, 가져오기 검토, 회사/연습 분리 |
| 저장 안전 | 세션·건물 확인, ETag/revision 충돌 차단, 크기 검증, 실패 초안 유지 |
| 수명주기 | 계정 변경·이탈 시 지도/이벤트/WebGL 정리, 늦은 응답 무효화 |

회사 저장은 crmCompany/buildingAtlas/{buildingId}만 사용한다. 고객·계약 원장의 통째 저장과 분리했다. 연락처·개인 메모·가격 등은 지도에 자동 복사하지 않는다.

## 실제 CRM 화면 검증: 가상 데이터만 사용

브라우저에서 실제 index.html/app.js와 통합 모듈을 실행했다. preview의 외부 연결은 CSP로 차단하고 저장은 메모리 fixture로 대체했다. 따라서 이 화면 검증은 운영 서버 저장 증거가 아니며, 서버 저장 증거는 위 에뮬레이터 검증이다.

- 빈 모형 확인·설비 등록·저장 확인·새로 조회 후 같은 기록 확인.
- 저장 실패 강제 시 오류 문구와 입력 필드 초안 유지.
- 연습 예시 다가구 추가: 63개 기록, 기존 연습 건물 유지.
- 점검 일정/담당 저장, 점검 이력 저장, 배관 경로 저장.
- 평면 X좌표 변경→3D 모델 상세 좌표 반영, 현장 확인 수준 해제.
- 다른 층 설비 복제, 64개 기록 확인 및 사진/점검 일정 미복제 확인.
- 건물 둘러보기 단계 표시와 보고서/전체 백업 화면 확인.
- WebGL 생성 실패를 fixture로 강제해도 목록·상세 유지 확인.
- CRM 메뉴 왕복 후 정상 재조회 확인.
- 계정을 viewer로 전환하면 이전 화면 정리 후 읽기 전용 재조회, 등록/수정/가져오기 비활성화 확인.
- 1280px와 390px에서 document 가로 넘침 없음 측정. 390px 편집창과 실패 메시지/저장 버튼 시각 확인.

## 확인 한계 및 운영 반영 전 체크

- 설치된 EXE 빌드·실행·다운로드 저장 경로·자동 업데이트는 이번 실행에서 검증하지 않았다.
- 인앱 브라우저의 보고서 다운로드 이벤트를 확인하지 못했다. 보고서 화면과 데이터 생성/다운로드 호출은 테스트했지만 **실제 파일 다운로드 완료로 보고하지 않는다**. EXE에서 보고서와 JSON 저장 파일 열기 확인이 필요하다.
- 사진/도면 파일 선택·JSON 가져오기의 실제 OS 파일 선택창은 이번 UI 세션에서 끝까지 실행하지 않았다. 크기 제한·가져오기 검토·백업 확인·오류·늦은 파일 읽기는 자동 테스트로 검증했다.
- 브라우저 일부 확인창 조작은 자동화 응답이 지연되어 성공으로 집계하지 않았다. 검색/메신저 이탈 방어는 실제 핸들러를 실행하는 회귀 테스트로 확인했다.
- RTDB Rules는 저장 외피·권한·revision·문자열 크기를 검증한다. modelJson 내부 모델 구조는 Electron main에서 검증한다. 직접 REST로 악성 모델을 쓰는 권한 사용자를 Rules만으로 완전히 막는 구조는 아니다. 읽을 때도 모델 검증을 수행한다.
- 실제 센서 연동·AI 진단·도면 자동 실측은 범위 밖이다. 추정 모형은 시공·차단·소방 대응·구조 안전 판단에 사용할 수 없다.

운영 반영 전: 원격 최신 변경 비교 → EXE 파일 저장 확인 → 새 지도 경로 규칙 배포 승인 → CRM 릴리스 승인 → 실제 테스트 건물로 계정 두 개의 저장/조회 확인 순서로 진행한다. 기존 규칙·브랜치·태그를 무조건 덮어쓰지 않는다.

## 후속 검증: 로컬 EXE 패키징

- 운영 브랜치 codex/bring-field-platform을 읽기 전용으로 재확인: 1889ef252c10e2bdf6b5de46329aae2cf240b482로 기준과 동일.
- 잠금 파일 기준 npm ci 후 electron-builder로 Windows unpacked 빌드 성공. publish=never, 버전=1.42.0-atlas.local, 코드서명 없음. 운영 설치 프로그램이 아닌 개발 검증 전용이다.
- 출력: desktop-crm/dist-atlas-verification/win-unpacked/BRING CRM.exe. 실행에는 같은 폴더의 resources 등 전체 파일이 필요하다.
- app.asar 내부의 crm-host.mjs, native/mount.mjs, building-atlas-service.js 포함 확인.
- 패키징한 EXE의 기존 BRING_CRM_SMOKE=1 모드 실행: 종료 코드 0, ready=true, initialized=true. 테스트 전용 userData 및 가상 계정 사용. 고객·건물 수 0이며 운영 자료에 접근하지 않음.
- 이 결과는 **앱 시작 검증**이다. 보고서/백업의 실제 저장 대화창 처리 및 파일 열기, 설치·자동 업데이트 검증을 대체하지 않는다. 해당 항목은 계속 미완료다.
