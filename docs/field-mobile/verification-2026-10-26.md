# 현장 앱 검증 및 수정 결과 — 2026-10-26

범위: 첫 개발 빌드의 소스·자동 시험·브라우저 동작·네이티브 설정. 고객 데이터나 실제 발송 없이 합성 사진과 가상 현장으로 확인했다.

## 발견하여 수정한 문제

| 문제 | 수정·검증 |
|---|---|
| SQLCipher 키가 설정되지 않은 별도 연결에서 트랜잭션 실행 | 설치된 Expo SQLite 58의 `Transaction.createAsync`가 새 연결을 여는 것을 확인했다. 보관함의 모든 동작을 직렬화하고 이미 키가 설정된 전용 연결에서 BEGIN/COMMIT/ROLLBACK을 실행한다. native 연결 계약 모형과 실제 Node SQLite 쿼리 시험을 함께 사용했다. 실기기 암호화 시험은 아니다. |
| 사진 예약 요청 중 분류 수정 가능 | 네트워크 요청 전에 최신 기기 메타데이터를 원자적으로 읽고 전송 상태로 고정한다. 늦게 도착한 이전 목록의 정보로 예약하거나 예약 중 분류를 바꾸지 않는다. |
| 촬영 탭을 다시 누르면 준비 상태만 해제됨 | 같은 화면으로 이동하는 요청은 그대로 유지한다. 앱이 배경으로 이동하거나 카메라 오류가 나면 준비 상태를 해제한다. native 카메라 이벤트의 실기기 확인은 남아 있다. |
| 이미지 변환 실패 시 decoder 자원 해제 누락 | render/encode/read/save 실패 전 구간을 finally로 보호한다. 파일 크기를 읽기 전에 검사하고 저장 실패 시 원본 캐시는 삭제하지 않는다. |
| 누락된 업로드 ID가 문자열처럼 검사됨, 응답 용량이 문자 수로 검사됨 | ID 타입을 명시 검사하고 JSON 응답은 스트림을 읽으며 UTF-8 바이트 128KiB를 제한한다. 초과 시 읽기를 취소한다. Native 연동 시 streaming `expo/fetch`를 주입해야 한다. |
| 저장 중 추가 입력 유실 가능, 사진 선택 시 이전 이미지 잠깐 표시 | 저장 중 입력을 잠그고 미리보기 데이터와 photoId를 묶었다. 읽기 실패를 무한 대기 대신 오류로 표시한다. |

추가 실패 시험은 실제 SQLite 파일 재열기·원자적 롤백·다른 UID·동시 revision 수정·hash 불일치·암호화 기능 누락·기존 DB의 키 유실·예약 응답 유실·여러 chunk 중 응답 유실·예약 중 분류 변경·인증 철회·대용량 응답 취소를 포함한다. native 모듈 mock은 해당 API의 계약을 확인하며, 실제 OS나 암호화 엔진의 대체 검증으로 사용하지 않는다.

브라우저에서는 전/후 합성 사진 2장 추가, 사진 설명 저장 전 전환 차단, 작업 본문/후속 조치 저장 전 이동 차단, 수동 검토 확인, 사진 수정 뒤 검토 무효화, 현장 B의 사진/본문 격리, 현장 A 복귀 시 초안 유지, 발송 비활성화를 확인했다. 문의번호는 1551-3873이다.

## 아직 통과 판정을 내리지 않은 항목

- APK/IPA 생성·설치, 실제 Android/iPhone 카메라·HEIC·권한·잠금·재부팅·SQLCipher 파일 암호화.
- 현재 PC의 PATH와 표준 Android SDK/Android Studio JDK 위치에서 실행 도구를 찾지 못했다. iOS native 빌드용 macOS/Xcode도 이 Windows 환경에서는 사용할 수 없다.
- 실제 직원 로그인/App Check, 운영 현장 할당, Drive 사진 보관, 서버 PDF·CRM 원장 연결, 실제 고객 전달.
- 개발 CLI 의존성 보안 경고 해소, iOS 자동 백업 제외 및 배포·스토어 심사 준비.

따라서 **현재 개발 코드 검증은 통과했지만, 운영 출시 또는 실기기 수용 시험 완료 상태는 아니다.** 소스·문서·로컬 검토용 묶음만 변경했고 운영 배포, Firebase 등록/권한 변경, 보고서 저장, 메시지 발송은 하지 않았다.
