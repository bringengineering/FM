# Structured hash false-positive correction
Packaged CRM context save failed when SHA64 contained a random13-digit sequence matching the existing resident-number detector. A deterministic test reproduces rejection in sha256 and snapshotJSON. The correction recognizes exact64hex hash values only in explicit hash fields. General notes and credential detection retain their original checks.
Snapshot JSON is recursively inspected and additionally scanned as serialized text, masking only known quoted hash values for resident-number detection. This preserves detection in property names, numeric scalars and duplicate members. Review found and rejected broader token removal and parse-only scanning before commit.
Verification: Node426; native Main CRM context freeze/re-read, delayed edits/session cleanup and ZIP checks pass; independent final review found no Critical/Important issue. Regression tests cover legitimate hashes, standalone/labelled resident numbers, passwords, sensitive JSON keys/numbers and duplicates. Fixed packaged build verification pending. No operational deployment performed.
