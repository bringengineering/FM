# CRM 공유 복원 연결 개발 검수

CRM 공유 복원은 파일 사전 검사, 사유 입력, 서버 승인 준비, 신규 적용 범위 확인, 실제 적용 순서입니다. 기존 항목을 덮어쓰지 않으며 Drive 원본 파일 복원은 별도 범위입니다. 공유 복원 적용 후에는 현재 초안을 유지하고 사용자가 공유 프로젝트 조회로 최신 자료를 확인합니다.

Main은 고정된 회사 Functions 주소와 로그인 토큰을 사용합니다. renderer에는 토큰이나 서버 주소 설정을 노출하지 않고 준비 응답의 세션 ID만 실행 시 전달합니다. 현재 CRM/R&D 관리자 승인과 실제 로그인 세대·세션 객체를 비동기 호출 전후 확인합니다. Main에서 준비한 현재 로그인 승인 요청만 실행할 수 있습니다. 로컬 시험 모드에서는 실제 회사 서버 실행을 거부합니다. 기본 비활성화이며 회사 운영 반영 후 별도 활성화가 필요합니다.

클라이언트 승인 정보는 메모리에만 최대 20개 보관하며 만료·세션 변경 시 정리합니다. 서버도 사용자별 대기 요청 20개·전체 보관 항목 200개·32MiB를 원자적으로 제한합니다. 다음 승인 준비 시 만료된 대기 요청과 하루 지난 완료 확인 기록을 정리합니다. 실행 완료 시 회사 데이터 사본을 제거하고 결과 해시·승인자·감사 요약만 남깁니다. 연구 이력과 영구 복원 감사 기록은 삭제하지 않습니다. 하루가 지난 요청의 확인 기록이 정리되면 같은 승인 ID로 서버 재확인할 수 없으며 최신 공유 자료와 영구 감사 기록을 확인해야 합니다. 응답 손실 시 자동으로 재전송하지 않으며, 사용자가 같은 승인 ID로 다시 확인하면 서버가 적용 이력을 확인해 중복 적용을 막습니다.

검증 범위:

- Node 클라이언트: 준비/적용 분리, 세션 ID 전용 요청, 토큰 비노출, 기본 비활성화·일반 구성원·준비하지 않은 승인 거부, 같은 UID 재로그인 거부, 응답 손실 자동 재시도 없음, 만료 거부, 토큰 갱신 대기 중 계정 변경 거부, 최초 입력 고정
- 실제 Main/preload/CRM 화면: 기본 비활성화 및 로컬 시험에서 실제 실행 거부, 상태 안내
- 실제 CRM DOM과 주입된 시험 API: 사유·깨끗한 입력·별도 확인 체크, 적용 요청의 세션 ID, 완료 후 재적용 버튼 차단, 지연된 준비 응답의 세션 초기화 후 재표시 방지
- 로컬 Firebase Auth/Functions/Database HTTP와 동일 Main 클라이언트 코드: 인증된 준비/실행, 원본 이력·다른 회사 데이터 유지, 로그인 세대 변경 거부
- 기존 로컬 복원/되돌리기/101건 페이지/문자 그대로 표시/지연 응답 검사 회귀 통과

시험 API 화면 결과는 실제 Main의 회사 로그인-HTTP-서버 전체 경로를 증명하지 않습니다. 실제 회사 계정·Google Drive·두 PC·운영 배포/활성화는 아직 검증하지 않았습니다. 원래 61개 검수 범위와 미완료 상태를 유지합니다.

실제 로컬 Auth HTTP 검사에서 20개 대기 승인 후 추가 거부, 다음 준비의 만료/하루 지난 기록 정리, 영구 감사 유지, 작은 완료 확인 기록으로 동일 요청 재확인이 통과했습니다. 서버 테스트 1,154개 및 빌드 통과. 전체 회사 루트 트랜잭션의 비용·규모 검토와 회사 실계정 검증은 별도 미완료입니다.
