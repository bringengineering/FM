# BRING CARE PPT 디자인 시스템 웹 적용 설계

## 1. 목적

기존 BRING CARE 광고 랜딩을 제안서와 사용자가 승인한 PPT 디자인 언어로 통일하고, `브링케어 24H 입·퇴실 관리 패키지`를 대표 상품으로 추가한다.

검색 광고의 서비스별 의도는 유지한다. 계단청소, 건물관리, 입주·이사청소를 하나의 페이지로 합치지 않으며, 각 랜딩에서 필요한 경우 24H 입·퇴실 관리로 확장되는 구조를 만든다.

## 2. 확정 정보

- 대표 연락처: `010-6566-3603`
- 모든 공개 가격: 부가세 별도
- 월 정기관리: `8만 9천원부터`
- 정기청소 주 1회: `3층 6만원 / 4층 7만원 / 5층 8만원`
- 관리 건물 기본 입·퇴실청소: `10만원부터`
- 일반 단건 입·퇴실청소: `12만원부터`
- 외부 전문작업 연결·조율: `승인된 작업금액의 5%`
- 현장 작업비, 자재비, 폐기물비, 전문업체 시공비: 별도
- 카카오 상담: `https://pf.kakao.com/_xnaRfX/chat`

## 3. 적용 범위

### 변경 대상

- `/stair-cleaning`
- `/building-care`
- `/move-in-cleaning`
- 신규 `/turnover-care`
- 위 페이지가 공유하는 상담 폼, 상담 완료 화면, 공식 채널, 헤더와 푸터
- 공개 마케팅 화면에 표시되는 전화번호
- CRM 광고 문의 접수함이 허용하는 서비스와 유입 경로

### 변경하지 않는 대상

- 내부 `/field` 업무 화면
- 데스크톱 CRM의 기존 업무·영업 데이터 구조
- 기존 현장기록의 사실관계와 사진
- 네이버 블로그 설정과 게시물
- 회사 메인 홈페이지 전체 구조

이번 작업은 광고와 상담 퍼널의 1차 디자인 통일이다. 회사 메인 홈페이지 전체 개편은 이 결과를 확인한 뒤 별도 범위로 다룬다.

## 4. 디자인 원칙

붙여 넣은 Brandlogy PPT 문서는 시각적 참고자료로만 사용한다. Brandlogy 로고, 이름, 고유 자산은 웹에 사용하지 않는다.

BRING CARE 웹에는 다음 규칙을 적용한다.

- Pretendard 중심의 단일 타이포그래피
- 흰색 우세 배경과 브랜드 블루 `#1456f0`
- 본문색 `#222222`, 보조색 `#45515e`, 약한 정보색 `#8e8e93`
- 16~24px 반경의 카드
- 표준 카드 그림자와 제한적인 브랜드 글로우
- CTA와 필터에는 pill 또는 8~10px 반경 버튼
- 숫자, 가격, 비교, 절차는 문장보다 KPI 카드·가격 카드·흐름도로 시각화
- 파란 Hero Gradient는 한 섹션에 최대 하나의 대표 요소에만 사용
- 핑크는 BRING CARE 브랜드에 필요하지 않으므로 사용하지 않음
- 장식용 도형이나 의미 없는 일러스트로 밀도를 채우지 않음

PPT의 고정 좌표는 웹에 그대로 적용하지 않는다. 대신 모든 섹션에서 다음 읽기 순서를 유지한다.

1. 작은 장 제목
2. 한 문장 핵심 제목
3. 짧은 부제
4. 시각화된 본문
5. 하나의 주 행동

## 5. 공통 컴포넌트

### 공통 헤더

- BRING CARE 원본 로고
- 주요 서비스 링크
- 대표번호 `010-6566-3603`
- `상담 신청` CTA
- 모바일에서는 서비스 링크를 줄이고 전화와 상담 행동을 우선함

### 히어로

- 왼쪽: 검색 의도와 일치하는 제목, 한 줄 설명, 핵심 범위, CTA
- 오른쪽: 실제 현장 이미지 또는 한 개의 대표 그라데이션 카드
- 가격은 큰 숫자 한 줄과 `부가세 별도`를 같은 시야 안에 표시

### 가격 카드

- 서비스명, 시작 가격, 적용 대상, 기본 포함, 별도 항목을 한 카드에 배치
- 현재 페이지와 가장 관련 있는 상품 카드 하나만 그라데이션으로 강조
- 전체 가격표 아래에 변동 조건과 부가세 별도 문구를 표시

### 절차 흐름

- 4~6단계의 가로 흐름
- 모바일에서는 2열 또는 세로 흐름으로 전환
- 각 단계는 번호, 동작 이름, 한 줄 설명으로 제한

### 상담

- CRM 직결 신청 폼을 그대로 사용하되 시각 체계를 통일
- 접수 성공 후 카카오톡 즉시 상담을 유지
- 모바일 하단 고정 행동은 `전화 상담`과 `간편 견적` 두 개로 제한

## 6. 페이지별 설계

### `/stair-cleaning`

- 제목과 첫 CTA는 계단·공용부 정기청소에 집중
- 가격 카드에서 `3층 6만원 / 4층 7만원 / 5층 8만원`, 주 1회 기준, 부가세 별도를 표시
- 청소 범위와 완료 사진 제공을 앞에 배치
- `청소하면서 건물까지 봅니다`는 보조 차별점으로 유지
- 하단에 `입·퇴실까지 함께 관리하기` 링크를 둬 `/turnover-care`로 연결

### `/building-care`

- 월 정기관리 `8만 9천원부터`, 부가세 별도를 대표 가격으로 표시
- 정기 방문, 관리 보고, 사전 입·퇴실 일정 관리, 통합 상담 창구를 시각화
- 기존의 공실·민원·점검 설명을 유지하면서 24H 입·퇴실 패키지를 후속 상품으로 연결

### `/move-in-cleaning`

- `관리 건물 10만원부터`와 `일반 단건 12만원부터`를 명확히 분리
- 두 가격 모두 원룸 기본 청소의 시작 가격이며 부가세 별도임을 표시
- 평형, 오염도, 잔존물, 옵션, 추가 작업에 따른 변동 조건을 가격 바로 아래 노출
- 퇴실 예정이 있는 건물주는 `/turnover-care`로 연결

### 신규 `/turnover-care`

대표 메시지:

> 퇴실 후에 움직이지 않습니다. 14일 전부터 준비합니다.

보조 설명:

> 퇴실 확인부터 직영 청소, 필요한 보수 연결, 완료 사진과 다음 임대 준비까지 하나의 흐름으로 관리합니다.

핵심 구조:

1. 24H 대표 히어로
2. 기존 사후 대응과 BRING CARE 사전 준비형 비교
3. D-14 접수부터 D+1 임대 준비까지의 6단계
4. 적용 조건과 제외·지연 조건
5. 브링케어 직접 수행, 외부 전문업체, 건물주 승인 역할 구분
6. 전체 가격표
7. 실제 현장기록
8. FAQ
9. CRM 간편 견적과 카카오 상담

24H 공개 문구:

> 퇴실 14일 전까지 접수되고 출입·작업 범위·비용 승인이 완료된 호실 중 중대한 추가 수리가 없는 경우, 퇴실 확인 시점부터 24시간 안에 청소·경미한 정리·사진 기록·인계 준비를 마치는 것을 운영 기준으로 합니다.

금지 문구:

- `24시간 안에 새 임차인이 계약됩니다.`
- `무조건 공실 0일입니다.`
- `어떤 집이든 하루 안에 끝납니다.`

## 7. 이미지 원칙

- 실제 현장, BEFORE/AFTER, 완료 증거는 소유권이 확인된 실사진만 사용
- 현재 저장소의 실제 현장기록 이미지를 우선 사용
- Google Flow 이미지는 향후 브랜드 배경이나 과정 설명에만 교체 가능
- 생성 이미지를 실제 고객 현장이나 작업 결과처럼 표현하지 않음
- 얼굴, 전체 주소, 호실, 차량번호와 임차인 정보는 공개하지 않음

## 8. 데이터와 CRM 연결

신규 `/turnover-care` 폼은 기존 무료 Firebase 접수함을 사용한다.

- 서비스값: `24H 입·퇴실 관리`
- 유입 경로: `/turnover-care`
- 이름, 전화, 지역, 문의 유형, 필요한 상담 내용, 건물 정보, UTM을 저장
- 비로그인 사용자는 신규 레코드 생성만 가능
- 공개 사용자는 접수함을 읽거나 수정하거나 삭제할 수 없음
- 승인된 CRM 계정만 문의를 읽음

기존 세 서비스의 허용값은 유지하고 신규 서비스만 추가한다.

## 9. 접근성과 반응형

- 모든 텍스트는 충분한 색 대비를 확보
- 포커스 표시를 유지
- 터치 대상은 최소 44px
- 데스크톱 가격 4열은 태블릿 2열, 모바일 1열로 전환
- 24H 조건과 부가세 문구는 작은 화면에서도 생략하지 않음
- 이미지에는 실제 내용을 설명하는 대체 텍스트를 제공
- 시각적 순서와 문서의 제목 계층을 일치시킴

## 10. 검증 기준

- 모든 공개 마케팅 전화번호가 `010-6566-3603`으로 통일됨
- 모든 가격에 `부가세 별도`가 명확히 표시됨
- 네 가지 가격 체계와 5% 조율비가 확정값과 일치함
- 기존 세 랜딩의 검색 의도가 유지됨
- `/turnover-care`에서 24H의 시작·종료와 적용 조건을 확인할 수 있음
- CRM 보안 규칙이 신규 서비스 생성만 허용하고 공개 읽기·수정·삭제를 계속 차단함
- 랜딩 컴포넌트 테스트, CRM 제출 테스트, Database Rules 에뮬레이터 테스트가 통과함
- 프로덕션 빌드와 Firebase 정적 내보내기가 통과함
- 데스크톱과 모바일 화면에서 가격, CTA, 조건 문구가 잘리지 않음
- 배포 후 네 페이지와 상담 완료 화면이 HTTP 200으로 응답함

## 11. 배포

1. 테스트 우선으로 새 가격·연락처·페이지 요구사항을 고정
2. 공통 디자인 토큰과 컴포넌트 구현
3. 기존 세 랜딩 적용
4. `/turnover-care` 구현
5. CRM 접수 허용값과 보안 규칙 확장
6. 전체 검증
7. Database Rules 먼저 배포
8. Hosting 배포
9. 운영 URL의 데스크톱·모바일·상담 링크 점검

내부 FIELD 화면과 데스크톱 CRM 릴리스는 이번 배포 대상이 아니다. 신규 문의는 기존 광고 신규문의 접수함에 동일하게 표시된다.
