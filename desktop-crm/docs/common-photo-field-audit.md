# 공용부 실사진 평가와 분류 보완

## 평가 조건

2026-10-26 브링케어 Drive 활동사진에서 서로 다른 4개 현장의 JPEG 사진을 현장별 파일명 순서로 12장씩 고르게 선택했다. 개발용 24장과 다른 현장의 검증용 24장을 구분했다. 사진을 먼저 직접 검토해 기준표를 고정했으며, Gemini 예측을 정답으로 복사하지 않았다. 원본·Drive 식별정보·사진별 기준표·결과는 저장소 밖에 보관한다.

기준표 SHA-256: `bfd5d09720f773643eaf52a0fa17f9be77c3adc20b092e116351386138b50919`.

기준은 AI 도우미의 시각 검토로, 독립된 현장 전문가의 검수나 전체 활동사진에 대한 정확도 조사가 아니다. 전체 창호처럼 유리·창틀이 함께 강조되거나 입구·바닥 경계에 걸친 사진은 허용 범주를 사전에 여러 개 기록했다. 확정할 수 없는 구역은 정확도 분모에서 제외한다. 단일 사진의 깨끗함으로 작업 전·후나 완료를 정답 처리하지 않는다.

축소본은 EXIF 등 메타데이터를 제거한 120KB 이하 JPEG다. Pillow 인코딩은 CRM과 같은 입력 상한을 따르지만 Electron 출력과 바이트가 같지는 않다. 실제 호출은 정상 Google 로그인 후 기존 인증된 CRM Worker를 사용했다. Gemini API 키는 조회·복사·출력하지 않았으며 Worker 안의 기존 Secret으로만 호출했다. 로그인 자격증명은 평가 프로세스 메모리에만 유지했다.

검증 현장의 6장은 사진만으로 단일 구역을 확정하기 어려워 구역 계산에서 제외했다. 합계 자동분류 비율은 31/42(73.8%)다. 83.9%는 자동분류된 사진의 허용 범주 일치율로, 모든 사진 중 83.9%를 올바르게 자동 처리했다는 뜻이 아니다. 코드 보완은 개발 표본 결과로 진행해 `9011660`에 고정한 다음 별도 검증 현장의 예측을 열어 확인했다. 검증 결과에 맞춰 분류 코드를 다시 조정하지 않았다.

주요 사례:

- 고정된 배수 홈·그레이팅 위 낙엽·종이를 분리수거 용기로 해석했다. 최초 보류 후 확대 재검토가 오히려 분리수거장으로 확정한 사례도 있었다.
- 외부 바닥의 오염·잔여물이 중심인데 모퉁이 수거함·작은 재떨이 때문에 분리수거장으로 분류한 사례가 있었다.
- 소화기·공용 설비함에는 맞는 항목이 없어서 점수 부족 또는 구역·대상 불일치로 보류됐다.
- 실물 게시판과 글자가 적힌 설비함을 문서·화면 캡처로 잘못 판단했다. 비현장 판정은 재검토 대상에서 제외되므로 최초 인식이 중요하다.

별도 검증에서는 계단·계단참을 출입구로 오인한 사례 1장이 추가됐다. 천장과 쓰레기 봉투는 전체·확대 판단 불일치로, 설비함 3장과 유리 출입문 등은 구역·대상 충돌로 보류됐다. 이 보류 자체와 잘못된 자동분류는 따로 계산한다.

작업 동작 여부는 개발 표본 24/24, 검증 표본 21/24, 합계 45/48이 사전 시각 기준과 일치했다. 도구가 보이지만 직접 작업이 확정되지 않는 사진의 과대 판단 1장, 물줄기·빗자루 청소 동작 미검출 2장이 있었다. 검증 사진에서 확인된 동작 오류는 후속 개선 과제로 남긴다. 전·후 짝이나 완료 판정의 정확도를 검증한 수치는 아니다.

각 묶음의 API 요청은 기본 분류 1회와 최대 6장 재검토 1회였으며 Worker 내부에서는 사진을 다시 나눠 Gemini에 요청한다. 관측 시간은 개발 약 15.5초, 검증 약 20.2초로 다운로드·로그인 시간을 제외한다.

## 반영한 보완

- `fixtures`(공용 설비·게시판)를 선택 항목으로 추가한다. 소화기·공용 설비함·계량기함·실물 게시판의 구체적인 구조를 요구하고 `target=other`로 처리한다. 기존 필수 체크리스트는 바꾸지 않는다.
- 고정 배수 철망과 가전 필터, 바닥 쓰레기와 쓰레기통, 중심 바닥과 배경 수거대의 구분 예시를 지침에 추가한다.
- 실제 공간에 부착된 게시판·설비함의 글자를 화면 캡처로 오인하지 않도록 설명한다. 실제 `screen_capture`·`document_layout` 판정의 보류 규칙은 유지한다.
- 미분류 원인을 점수 부족, 구역 시각 근거 부족, 구역·대상 충돌, 대상 근거 부족, 지원하지 않는 분류로 구분해 닫힌 코드와 설명으로 전달한다. 점수를 정확도 확률로 표시하지 않는다.
- 새 CRM이 `categorySchema: "common-v2"`를 전송한 경우에만 확장 항목을 반환한다. 표시가 없는 기존 CRM에는 기존 열거형만 제공한다. 새 항목 때문에 구버전 클라이언트가 응답 전체를 거절하는 문제를 방지한다.

모델 자체의 가중치를 학습하거나 파인튜닝한 변경은 아니다. 실사진에서 드러난 오류를 바탕으로 지침·분류 목록·근거 검증·회귀 검사를 보완한 것이다. 새로운 Gemini 지침의 실제 정확도는 운영 반영 또는 승인된 별도 실행 환경에서 다시 측정하기 전까지 개선 수치로 주장하지 않는다. 검증용 현장의 예측을 보고 기준표를 바꾸거나 같은 표본의 재실행을 독립 검증으로 표현하지 않는다.
