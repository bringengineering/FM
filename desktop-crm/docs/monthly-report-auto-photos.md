# 월간보고서 활동사진 자동 작성

승인된 흐름: 건물·보고월 선택 → `사진 찾아 AI 보고서 작성` → 처음 한 번 활동사진 상위 폴더 선택 → 사진 검토와 보고서 초안. 기존 2열 화면과 수동 PDF 저장·고객 발송은 유지한다. 자동 발송은 하지 않는다.

- Drive 선택기에 실제로 표시된 폴더만 지정 가능하다. 이 PC의 Windows 보호 저장소에 CRM 사용자/Google 계정별로 암호화하여 기억한다. 재실행 시 정확한 저장 폴더의 현재 Drive 권한·삭제 여부를 재검증한다. 회사 전체 공유 설정이나 Drive 권한은 바꾸지 않는다.
- 폴더 날짜는 `YYMMDD_건물명(활동명)` 또는 `YYYYMMDD_건물명(활동명)` 기준이다. 파일 업로드일을 작업일로 추정하지 않는다. 공백·구분문자 정규화 후 건물명을 정확히 비교하며 비슷한 다른 건물이나 다른 보고월은 제외한다. 같은 이름의 CRM 건물이 여러 개면 자동 작성을 중단한다.
- 지정한 폴더 내부만 탐색한다. 깊이 3, 탐색 노드 60, 일치 활동 폴더 40, 폴더별 24장, 총 후보 120장으로 제한한다. 월별 후보는 날짜/활동별로 고르게 구성하고 Gemini에 24장 단위로 검토시킨 뒤 대표 사진 최대 12장을 넣는다. 제한·권한·변환 등으로 누락된 경우 UI에 일부 검토임을 표시한다.
- 모델이 선택한 사진 설명은 메인 프로세스의 해당 건물·월 후보에 묶어 보관한다. 보고서 생성 시 렌더러가 전달한 설명 대신 검증된 관찰 내용을 사용한다. 사진 관찰은 완료 건수에 더하지 않으며 완료 상태는 CRM 작업 기록만 따른다. CRM 업무와 사진 날짜가 맞지 않으면 확인 대상으로 서술한다.
- 사진이 없으면 경고와 함께 CRM 자료만으로 초안을 만든다. 요청 오류 시 기존 초안을 유지한다. 작성 중 건물·월·계정·자료 변경은 이전 결과를 무시한다. 사진 제외/재선택 후에는 기존 AI 문장을 지우고 선택 자료로 다시 작성할 수 있다.

검증: Node 단위/IPC 회귀 테스트, 전체 desktop 테스트, `scripts/check-monthly-report-automation.cjs`의 로컬 가상 데이터 브라우저 QA. 브라우저 QA는 외부 요청을 모두 차단하며 실제 Google 계정/사진 또는 고객 발송을 사용하지 않는다. 실제 계정으로는 최초 폴더 지정과 사진 권한 확인이 필요하다.
